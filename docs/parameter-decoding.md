# 관측 근거에서 발주 모수를 다시 선택하는 경로

연구 범위는 **문서와 판매 이력에서 `c/p/v/b/F`를 구성하고, 부족한 모수는 매니저에게 질문한 뒤 공통 optimizer로 발주하는 것**이다. L40S 비교에서 모수·근거와 질문·실제 발주 손실의 개선을 확인해 기존 `recovery-v1`에 `scoped` 추론 경로를 채택했다. ModernBERT·모수 head·수요 GRU·가치 head의 가중치는 모두 고정했으며, 추가 학습이나 새 head를 도입하지 않았다. ABCD와 TAT-QA는 이번 최적화 대상에 포함하지 않았다.

## 무엇을 수정했는가

기존 모델은 다른 상품·기간·구버전 문서의 숫자를 먼저 고르면 근거 검사에서 이를 거부했다. 그러나 같은 입력에 현재 발주에 맞는 근거가 있어도 다시 선택하지 않아 미확정으로 남겼다. 이후 불필요한 질문이나 보류가 발생할 수 있었다.

[새 선택 모듈](../src/newsvendor/structured_decode.py)은 기존 선택이 거부된 경우에만 적용 가능한 식을 다시 검토한다. 조건은 다음과 같다.

- 모델이 해당 필드를 `verified`·`compute`로 판단해야 한다. 부족 비용 `b`는 `preference` 유형이어야 한다.
- 기존에 승인된 값과 근거는 그대로 유지한다. 누락·충돌·후보 상태를 임의로 확정하지 않는다.
- 같은 적용 범위의 현재 문서가 서로 다른 값을 제시하면, 숫자를 선택하지 못했어도 충돌 상태와 양쪽 근거를 보존한다. 매니저의 무응답은 이 충돌을 해소하지 않는다.
- 기존 파서가 지원하는 문서 형식에서 역할·SKU·기간·단위·최신 버전 검사를 통과한 식만 허용한다. 모든 피연산자는 실제 인코딩한 토큰에 있어야 한다.
- 기존 연산·피연산자 head의 점수 합으로 식을 선택하고 공통 계산기가 값을 계산한다. 후보가 없으면 미확정 상태를 유지한다.

수정 전 신경망 출력은 `rawFields`에 보존하고, 복구한 근거와 후보 수는 `parameterDecoding`에 기록한다. 따라서 원시 신경망 정확도, 근거 제약을 적용한 구성 정확도, 질문 후 최종 정확도를 구분한다. 평가 정답·미래 수요·매니저의 미관측 응답은 이 모듈의 입력에 넣지 않는다.

## 비교 조건과 지표

[후속 등록](../configs/research-parameter-decoding-v2.json)은 동일 L40S에서 같은 가중치로 세 경로를 비교한다. `parent`는 기존 선택, `scoped`는 수정 경로, `first`는 같은 허용 후보 중 첫 식을 고르는 대조군이다. `first`도 기존 신경망의 상태·유형·추출 방식 판단을 사용하므로 전체가 규칙으로만 동작하는 모델은 아니다. 첫 시도의 등록과 결과도 보존한다.

먼저 Train 변형 6,051건과 변형 학습에서 제외한 Train family의 1,259건을 진단했다. 부모 모델이 원래 Train 출처를 본 적이 있으므로 이를 새로운 출처 일반화로 해석하지 않는다. 이후 생성 Train 360건·완전 관측 판매 154조건에서 각 경로가 직접 구성한 상태로 질문하고 발주했다. 같은 상태를 후보 사이에 전달하지 않고, 완전히 같은 관측 입력의 고정 신경망 출력만 재사용했다. 직접 실행과 캐시 출력의 일치도 확인했다.

문서 조건은 원래 형식, 다른 SKU, 다른 기간, 구버전, 환불액·수수료의 서술 순서 변경이다. 변형은 관측 문서만 사용하며 원래 유효한 금액과 상태를 보존한다. Train의 변형 순차 비교는 입력 hash로 고정한 family별 한 사례, 총 85건씩이다. Dev는 생성 60건과 판매 336조건 전체를 각 문서 조건에서 비교한다.

원래 판매 조건은 모수별 응답 유무 16가지 조합을 모두 실행해 누락률 0·10·20%의 기대 결과를 계산한다. 질문 순서가 응답 표본을 바꾸지 않는다. 문서 변형의 순차 비교는 기본 응답 조건을 사용한다. 기존 Dev는 개발에 사용된 자료이며 이번 비교도 새로운 blind test가 아니다. 보호된 Test와 별도 27개 출처 holdout의 추론은 실행하지 않았다.

모수 정확도는 관측 상태의 `c/p/v/b` 네 필드를 채점하며, 아직 없는 값을 없는 것으로 유지한 경우도 포함한다. 근거 정확도는 관측 가능한 값의 식과 출처가 일치하는 비율이다. 최종 정확도에는 관측한 매니저 응답과 기존 상태 복사·검증의 효과가 포함된다. 따라서 높은 최종 정확도가 모든 값을 채웠거나 원시 신경망이 모두 맞혔다는 뜻은 아니다.

질문은 관측상 빠진 항목에 대한 요청과 이미 근거가 있는 항목에 대한 불필요한 요청으로 나눈다. 전자의 수를 경제적으로 최적인 질문 수와 동일시하지 않는다. `neededRecovered`는 실제로 빠졌던 모수의 회복만 센다. 총손실은 실제 출력한 발주량의 종료 손실과 질문 비용의 합이며, 종료 손실에는 보류 비용·잘못된 진행의 기존 벌점도 포함한다. 품절 구간의 손실 하한은 완전 관측 손실과 합쳐 평균내지 않는다.

## 최종 Dev 결과와 채택 범위

v2는 원래 조건의 보존 기준과 모든 문서 변형 기준을 통과했다. 아래 초기 정확도는 조건마다 생성 60건·판매 336건, 총 396건의 1,584개 필드에 대한 결과다. 근거 분모는 이 중 관측 가능한 값 1,193개다. 질문을 받기 전의 구성 결과이며 원시 신경망 출력은 세 경로에서 동일하다.

| Dev 문서 조건 | 초기 모수 정확도, 기존 → 수정 | 초기 근거 정확도, 기존 → 수정 |
| --- | ---: | ---: |
| 원래 형식 | 100% → 100% | 100% → 100% |

| 환불액·수수료 서술 순서 변경 | 100% → 100% | 100% → 100% |

세 혼입 조건에서 빠진 모수의 요청·회복은 각각 328·331·323건에서 모두 336건이 됐다. 기본 응답 조건의 최종 모수·근거·상태·유형은 모두 100%이고, 전 사례가 발주에 도달했다. 여기에는 관측한 매니저 답변이 포함된다. 잘못된 발주 진행은 기존·수정 모두 0건이다. 원래 조건의 응답 누락률 10%·20% 총손실 **71.8147·117.8583**과 모든 행동·발주량도 그대로 유지했다.

예를 들어 질문 예산이 세 번인 `retail:405:578:60:missing_v_b`의 다른 SKU 조건에서, 기존 경로는 문서에 있는 판매가·원가까지 질문한 뒤 부족 비용을 물어 잔존가치를 해결하지 못하고 보류했다. 수정 경로는 부족 비용과 잔존가치만 질문해 발주량 7.6168을 출력했다. 이 조건의 총손실은 635.4017에서 46.3962가 됐다. 이는 실제 판매 이력에 통제 생성한 문서·비용을 연결한 사례이며 실제 기업의 수익 증가를 뜻하지 않는다.

생성 혼입 조건의 최종 모수 정확도는 수정 후 각각 86.67%·89.17%·90.42%다. 원래 생성 Dev 손실 147.6813을 보존했고, 문서 혼입의 퇴행을 줄였지만 어려운 조건을 모두 해결하지 못했다. 서술 순서만 바꿔도 두 경로의 생성 손실이 함께 148.3549가 되는 행동 민감성도 남는다.

Dev 원시 경로 **21,060개**의 실제 발주량·질문 비용·종료 손실·총손실을 전수 재계산했다. `first`와 `scoped`의 모든 행동·발주량·손실은 같았다. 따라서 이번 개선은 관측 근거의 적용 범위와 충돌을 올바르게 처리한 효과이며, 학습 점수에 의한 후보 재평가나 가치 학습의 추가 이점을 입증하지 않는다. 반복한 문서 조건·응답 조합을 새로운 독립 판매 표본으로 세지 않는다.

L40S에서 v2의 Train family 진단은 114.36초, Train 순차 비교는 415.72초, Dev 비교는 1,194.25초였다. 동일한 관측 입력의 encoder 출력을 재사용한 세 경로 비교 시간이며 서비스의 사례별 지연 측정이나 학습 시간은 아니다. 가중치 전체 hash는 전후 동일한 `e01f07f8ab6325411975733303a277c95d5c914170fd833d18c452ab4bd105dd`다.

## 첫 시도의 Train 결과와 발견한 퇴행

| 진단 자료 | 방식 | 모수 정확도 | 근거 정확도 | 잘못 승인한 값 |
| --- | --- | ---: | ---: | ---: |
| 6,051건, 24,204필드 | 기존 | 62.66% | 51.06% | 0 |
| 동일 자료 | 수정 | 88.45% | 84.86% | 0 |
| 제외한 Train family 1,259건, 5,036필드 | 기존 | 62.23% | 50.05% | 0 |
| 동일 자료 | 수정 | 88.56% | 84.87% | 0 |

별도 Train family의 모수 오류는 1,902개에서 576개로 줄었다. 같은 입력의 원시 신경망 출력은 변하지 않았다. 첫 후보를 고르는 대조군도 같은 점수였고, 첫 6,051건에서 실제 복구한 6,241개 필드는 모두 허용 후보가 하나였다. 이 결과로 학습 점수에 의한 재평가의 추가 이점을 주장하지 않는다.

원래 Train의 생성 총손실 150.5491, 판매 총손실 45.7155와 질문·회복은 모두 같았다. 다른 SKU·기간·구버전 조건의 생성 총손실은 각각 573.5268→308.3253, 573.7810→299.0613, 570.1003→323.9157로 줄었다. 같은 조건의 판매 총손실은 58.5174→52.8822, 60.5841→52.8822, 153.9086→52.6629였다. 구버전 조건은 보류를 포함한 판매 종료 손실도 123.7735→32.3117로 줄었고, 다른 SKU·기간 조건의 종료 손실은 같으며 질문 비용만 감소했다. 서술 순서 조건은 변화가 없었다.

원시 경로 9,492개를 전수 대조해 실제 발주량·질문 비용·종료 손실·총손실을 재계산했다. 기존 조건은 모두 보존됐지만, 문서 변형의 생성 시나리오에서 잘못된 진행이 SKU 1→3건, 기간 0→3건, 구버전 0→1건으로 늘었다. 첫 등록의 변형 조건 기준에 이 항목이 빠져 있었다. **v1은 채택하지 않았다.** 원래 Dev의 일부 실행을 중단했으며 그 출력으로 수정안을 고르지 않았다. 이미 생성된 부분 측정과 중단 로그도 보존한다.

원인은 값이 선택되지 않은 필드에서 관측한 충돌을 단순 미확정으로 처리한 것이었다. 원가·판매가를 복구하자 기본 후보 집합으로 발주할 수 있게 됐지만, 서로 다른 현재 계약이 남은 상태였다. 후속 v2는 인코딩한 현재 근거 사이의 충돌을 별도로 보존하고, 변형 조건의 생성 시나리오에도 잘못된 진행·불필요한 질문의 퇴행 금지 기준을 추가했다. 정상 응답으로 충돌을 해소하면 다시 발주할 수 있고, 무응답은 충돌을 해소하지 않는 검사를 포함했다. v2는 기존 Train family 1,259건을 다시 진단한 뒤 동일한 전체 Train 순차 비교를 거쳤다. v1의 6,051건 결과를 v2의 측정으로 바꿔 적지 않는다.

## 재현 자료

[전체 수치·파일 hash·검증 결과](evidence/research-parameter-decoding-results.json)에 v1 실패와 최종 v2 결과를 함께 보존한다. 원시 측정과 실행 소스, 입력·환경 정답의 분리, 원래 gzip과 압축 해제된 JSONL의 hash도 기록한다.

- [실행 소스·입력·보고서·검증 기록](evidence/artifacts/parameter-decoding-records-v2.tar.xz)
- [v2 Train 진단·순차 경로 원시 기록](evidence/artifacts/parameter-decoding-train-raw-v2.tar.xz)
- [v2 Dev 전체 원시 경로](evidence/artifacts/parameter-decoding-dev-raw-v2.tar.xz)
- [v1 Train 전체 원시 기록](evidence/artifacts/parameter-decoding-train-raw-v1.tar.xz)
- [중단한 v1 Dev의 부분 원시 기록](evidence/artifacts/parameter-decoding-interrupted-raw-v1.tar.xz)

사용한 가중치는 [공개 `recovery-v1` 조립 절차](model-bundle.md)로 복원한다. 새 가중치를 다운로드할 필요는 없다. 추론 옵션은 다음과 같다.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  uv run python scripts/predict_research.py \
  --bundle results/released-model/recovery-v1 \
  --inputs results/released-model/example-inputs.jsonl \
  --output results/released-model/scoped-predictions.jsonl \
  --parameter-decoding scoped
```

CUDA 환경에서는 사용할 GPU를 지정하고 `--device cuda`를 추가한다. 옵션을 생략하면 기존 bundle의 설정을 사용하며, 과거 결과를 재현하는 기본 경로는 바뀌지 않는다. 출력 파일은 덮어쓰지 않는다.

독립 재현은 별도 디렉터리에 소스·공개 가중치·측정 자료를 복사하고 작업용 데이터·checkpoint·네트워크 접근을 차단해 실행했다. 결과와 무관하게 관측 ID에서 일정 간격으로 선택한 원래 조건 및 네 변형, 세 경로의 **540개 경로**가 행동·상태·발주량·질문 비용·손실까지 모두 일치했다. 원래 판매 조건에서는 응답 유무 16개 조합을 모두 포함한다. 실행 시간은 70.26초이며 전체 가중치 hash도 유지됐다. 성능 표 전체를 재평가한 새 평가가 아니라 보존한 경로의 재현 검사다.

아래는 공개 자료로 같은 재현을 실행하는 명령이다. 먼저 위 안내로 bundle을 조립하고, CUDA PyTorch가 설치된 Python 3.12와 L40S 한 대를 지정한다. 저장소 기본 `uv sync` 환경은 CPU용이다. 소스 hash를 맞추기 위해 압축에 포함한 소스에서 실행한다.

```bash
mkdir -p results/parameter-decoding-reproduction
tar -xJf docs/evidence/artifacts/parameter-decoding-records-v2.tar.xz \
  -C results/parameter-decoding-reproduction
tar -xJf docs/evidence/artifacts/parameter-decoding-dev-raw-v2.tar.xz \
  -C results/parameter-decoding-reproduction

cd results/parameter-decoding-reproduction
CUDA_VISIBLE_DEVICES=0 CUBLAS_WORKSPACE_CONFIG=:4096:8 \
  HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  /absolute/path/to/cuda-venv/bin/python \
  docs/evidence/scripts/reproduce-parameters.py \
  --bundle /absolute/path/to/recovery-v1 \
  --records results/parameter-decoding-v2 \
  --output results/reproduced-parameters-dev.json
```

CPU 테스트 374개, 5개 자료 묶음의 출처 분리 검사, 수치 smoke 30개가 통과했다. smoke의 보고 파일을 모으는 래퍼에서 반환값 처리 오류가 났지만 실제 검사는 완료됐으며, 실행 소스 hash가 일치하는 원본 결과와 래퍼 오류·복구 기록을 모두 보존했다. Ruff와 기본/수정 CLI도 확인했다. 보호된 Test나 별도 27개 출처 holdout의 추론을 새로 실행하지 않았다.

## 남은 범위

이 수정은 기존 파서가 지원하는 문서 형식과 관측한 적용 범위 정보를 사용한다. 임의 계약·복잡한 표에서의 일반적인 근거 추출을 해결한 것이 아니다. 직접 관측한 충돌은 별도로 보존하지만, 숫자 재선택은 기존 신경망의 상태·유형·추출 방식 판단에 여전히 제한된다. 지원하지 않는 식과 읽지 않은 근거도 복구하지 못한다. 혼입 조건의 초기 모수·근거 정확도는 여전히 90% 미만이고, 판매의 불필요한 질문도 189~190건 남는다. 수요 GRU의 calibration과 경제 가치 학습의 추가 이점도 이 비교로 입증하지 않는다. 생성한 계약·정책 문서와 매니저 응답에서의 개선을 실제 조직 업무의 효과로 해석하지 않는다.
