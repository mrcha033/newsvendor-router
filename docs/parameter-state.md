# 매니저 응답 후 모수 상태의 Train 진단

금액·근거를 올바르게 구성해도, 질문에 답이 오지 않았다는 사실을 상태에 반영하지 못하는 오류가 확인됐다. 실제 Train rollout 상태를 다시 학습할 수 있도록 주 실행기에 `constructionReplay`를 연결했다. 상태 head만 추가 학습한 L40S 후보는 일부 분류 오류를 줄였지만, 학습 정책의 Dev 총손실을 개선하지 못하고 중간 상태 오류도 하나 늘려 **현재 모델은 교체하지 않았다**.

## 확인한 오류와 학습 자료

기존 replay-v1의 실제 Train rollout 두 회차에서 모델이 관측한 입력을 중복 제거했다. 생성 사례와 판매 이력 결합 사례를 합쳐 85개 출처·1,153개 상태, `c/p/v/b` 상태 판정 4,612개다. 금액·유형·근거 오류는 없었고, 상태 오류는 198개였다.

| 상태 오류 | 필드 수 |
| --- | ---: |
| 질문에 응답이 없었는데 미확인으로 남김 | 159 |
| 일부 자료만 받은 상태를 미확인 또는 응답 불가로 분류 | 25 |
| 아직 질문하지 않은 다른 필드까지 응답 불가로 분류 | 14 |

기존 언어 학습의 응답 예시는 정해진 질문 순서를 따른다. 판매 경로에서는 무응답·부분 응답 예시가 없었다. 생성 경로에는 응답 불가 112개, 부분 응답 34개 필드 주석이 있었지만, 같은 연구 사례의 확인된 필드 주석은 2,298개였다. 실제 정책이 만든 질문 순서와 중간 상태까지 모두 포함하지는 않았다.

198개 오류 중 **116개는 원래 언어 학습에 없던 관측 상태**, **82개는 이미 학습에 있던 관측 상태**에서 나왔다. 따라서 자료 누락만으로 전부 설명할 수는 없다. 숨겨진 응답 확률·정답·최종 rollout 손실은 오류 사례 선택이나 encoder 입력에 사용하지 않았다.

## 같은 encoder에서 상태 head만 학습한 비교

[사전 설정](../configs/l40s-parameter-state-v1.json)에 부모 checkpoint·원시 rollout·코드 hash, seed 42, 최대 80 epochs를 기록했다. 이미 학습한 encoder·수요 GRU·나머지 head를 고정하고 기존 `256 → 128 → 5` 상태 head만 학습했다. 다른 구조를 추가하지 않았다.

Train 출처를 68개 적합/17개 보류로 나누고, 보류 출처의 상태 정답 수와 동률 시 cross entropy로 74 epochs를 선택했다. 그 횟수만큼 전체 Train으로 부모 head부터 다시 학습했다. encoder는 이전에 이 Train 자료를 학습했으므로 이 내부 보류를 새로운 모델의 독립 검증으로 해석하지 않는다.

| 범위 | 기존 오류 | 추가 학습 오류 |
| --- | ---: | ---: |
| head 선택용 보류 Train: 266개 상태·1,064개 필드 | 47 | 24 |
| 전체 Train 재적합: 1,153개 상태·4,612개 필드 | 198 | 108 |

캐시한 표현으로 계산한 초기 head 예측이 실제 모델의 초기 예측과 모든 필드에서 일치하는지 검사했다. 표현 추출·head 학습·기록을 포함한 L40S 시간은 **38.83초**였다. 이 결과는 기존 표현으로 일부 개선이 가능함을 보여주며, 더 큰 encoder가 필요하거나 현재 표현만으로 충분하다는 결론까지 입증하지는 않는다.

## 원래 Dev에서 실제 순차 실행

[Dev 비교 설정](../configs/research-parameter-state-dev-v1.json)을 별도로 고정하고 부모/후보를 같은 생성 60사례·판매 결합 336사례에서 실행했다. 상태 head 외의 모든 가중치 hash가 같아야 한다. 기존 Test와 새 27개 출처 holdout은 사용하지 않았다.

| 측정 | 부모 | 후보 |
| --- | ---: | ---: |
| 생성 Dev 학습 정책 평균 총손실 | 147.6813 | 147.6813 |
| 생성 Dev 고정 질문 정책 평균 총손실 | 181.6758 | 181.6758 |
| 판매 Dev 학습/고정 정책 평균 총손실 | 24.3925 | 24.3925 |
| 생성 Dev 고정 질문 정책의 응답 후 상태 오류 | 11/232 | 8/232 |
| 판매 Dev 학습 정책의 응답 후 상태 오류 | 0/1,152 | 1/1,152 |

판매 총손실은 완전 관측 **고유 기간 5개 × 생성 조건 7개**에 한정한다. 표의 상태 오류는 각 정책 경로 안에서 중복을 제거한 관측 상태의 필드 수다. 최종 채택 모수·근거는 두 모델 모두 100%, 잘못된 발주 진행은 0건이었다. 판매 경로의 필요한 질문·회복은 각각 336건, 불필요한 질문은 0건이었다. 공개 문서 Dev 예측도 두 모델에서 완전히 같았다. 전체 Dev 비교 시간은 **141.98초**였다.

고정 질문 경로의 일부 상태 개선은 있었지만, 주 학습 정책의 발주·질문 성능 개선은 없었다. 판매 경로 중간 상태에서 새 오류도 생겨 후보는 채택하지 않았다. 위 수치에는 신뢰구간을 이용한 일반화 우위 주장이나 실제 조직 업무의 효과성 주장이 없다.

## 반영한 학습 경로 수정과 보존 자료

`run_research.py --stage train`이 `constructionReplay`에 등록된 실제 Train 상태를 `research_cases`에 전달한다. 주석은 현재 관측 문서와 받은 응답에서 다시 만들며, rollout의 예측 상태나 최종 손실을 모수 상태 정답으로 쓰지 않는다. 등록된 Train 사건·출처가 다른 행과 Dev/Test 행은 거부한다. 원래 언어 사례와 중복되는 관측 입력도 다시 더하지 않는다. 옵션을 지정하지 않은 기존 경로는 동일하다.

위 비교는 같은 encoder를 사용한 상태 head 진단이다. 이후 실제 rollout 상태를 연결하여 encoder까지 추가 학습한 두 조건과, 모수 학습·추론 입력 불일치 수정은 [별도 비교](constructor-training.md)에 기록했다. 두 추가 학습 후보도 부모를 넘지 못해 선택되지 않았다.

[검증·측정 요약](evidence/research-parameter-state-results.json)과 [원시 측정·표현·head·실행 코드 묶음](evidence/artifacts/research-parameter-state.tar.xz)에 유리한 결과와 불리한 결과를 함께 보존한다. 등록 당시 소스와 현재 학습 연결 수정의 소스 hash를 구분한다. 전체 ModernBERT 부모 가중치는 이 묶음에 포함하지 않아, 이 자료만으로 전체 언어 모델 추론을 외부에서 재실행할 수 있는 것은 아니다.
