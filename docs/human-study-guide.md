# 발주 의사결정 참여자 실험 운영 안내

2026-10-10. **모집한 참여자에게 개인 링크를 전달하면 진행할 수 있는 한국어 실험을 준비했다.** AI 없이 판단하는 집단과 AI 정보를 보며 판단하는 집단에 자동 무작위 배정한다. 양쪽 모두 사람이 최종 발주량을 정한다. 매니저 질문은 프로그램이 정해진 정보를 돌려주는 기능이므로 별도 매니저를 모집할 필요가 없다.

현재 실제 참여자는 0명이다. 자동 브라우저 리허설의 4명·40개 제출은 소프트웨어 검사이며 연구 데이터가 아니다. [준비·검증 기록](evidence/human-experiment-readiness.json), [연구계획](research.md), [고정 명세](../experiments/participant/protocol.json)를 함께 보관한다. 이 안내의 [Word 파일](human-study-guide.docx)도 제공한다.

## 1. 준비된 구성

| 항목 | 준비 내용 |
| --- | --- |
| 참여자 화면 | 참여 설명·동의 → 이해 확인 → 연습 2개 → 본 과제 8개 → 완료 코드 |
| 과제 | 문서와 최근 35일 판매·품절 정보로 7일 발주량 결정 |
| 대조군 | 문서·판매 그림·계산 보조·매니저 질문을 사용 |
| AI군 | 같은 정보에 고정 모델의 모수·근거·수요 추정·제안 발주량 추가 |
| 공통 조건 | 발주량 0~70, 질문 최대 2회·회당 4점, 보류 400점, 동일한 매니저 기준 b |
| 배정 | 동의·이해 확인 후 4명 단위로 2명씩 배정; 본 과제 순서는 개인별 무작위 |
| 저장 | 자동 임시 저장·재접속, 제출 중복 방지, 질문·시간·근거·발주량 기록 |
| 진행자 화면 | 전체 진행 현황, 개인 링크 CSV, 마감, 결과 ZIP 다운로드 |
| 분석 | 참여자 평균 손실·모수·근거·질문·시간·보류·실현 손실, 회귀와 누락 범위, JSON·Markdown 보고서 |

컴퓨터·같은 장소 또는 같은 LAN/VPN 사용을 기본으로 준비했다. 참여자 PC에는 설치가 필요 없다. 운영 PC에서만 Python 3.12와 uv를 사용한다. 모델 제안 100개 상태는 L40S에서 미리 계산해 고정했으므로 실제 진행에는 GPU·모델 가중치·외부 AI API가 필요 없다. 처음 의존성을 설치할 때는 인터넷이 필요하다.

## 2. 시작하기

실행 패키지를 풀거나 이 저장소에서 다음 명령을 실행한다. 패키지에는 소스·의존성 잠금·고정된 과제와 AI 제안이 포함돼 있다.

```sh
bash experiments/participant/start.sh
```

처음 실행할 때 참여자에게 표시할 **연구 문의 연락처**를 입력한다. 이름·이메일 등 연락 문구를 연구자가 정한다. 기본 보상은 ‘보상 없음’이며 실제 조건이 다르면 시작할 때 함께 지정한다.

```sh
bash experiments/participant/start.sh \
  --contact '연구팀 문의: 실제 연락처' \
  --compensation '실제로 제공할 보상 조건'
```

이 문구의 예시를 실제 연락처·보상으로 바꾼다. 이미 운영 폴더를 만든 뒤에는 조건을 조용히 바꾸지 못하도록 고정돼 있다. 모집 전에 설정이 맞는지 진행자 화면과 동의 화면을 확인한다. 모집 목표는 기본 **무작위 배정 128명**, 초대 링크는 160개다. 미동의·이해 확인 전 이탈에 대비한 여분이며 128명을 배정하면 추가 배정이 차단된다.

기본 128명은 ‘참여자 평균 점수에서 0.5 표준편차의 차이, 양측 5%, 약 80% 검정력’이라는 계획 가정의 정규 근사다. 실제 사람의 분산이나 경제적으로 중요한 최소 차이를 측정한 결과가 아니다. 적은 인원부터 진행하려면 **모집 전에** 새 폴더·목표를 지정해 탐색 파일럿으로 명시한다. 예를 들어 32명은 다음과 같다.

```sh
bash experiments/participant/start.sh \
  --directory results/human-pilot-32 --target 32 --invitations 40
```

배정 목표는 4의 배수다. 파일럿과 후속 확증은 별도 폴더·분석으로 보존한다. 결과가 좋거나 나쁜 사람을 빼고 새 사람으로 채우지 않는다. 이 로컬 계획을 외부 사전등록 또는 기관 승인 완료로 표시하지 않는다. 소속 기관의 사람 대상 연구 절차가 적용되면 모집 전에 그 절차에 맞춘다.

## 3. 모집문과 초대 링크 배포

서버 시작 시 터미널에 진행자 주소가 나온다. `http://127.0.0.1:8795/admin#key=...` 형태이며 키를 포함하므로 **진행자만 보관**한다. 참여자는 이 주소를 사용하지 않는다.

1. `results/human-study-live/recruitment.txt`에 실제 문의·보상·모집 수가 들어간 모집문이 자동 생성된다. 예상 시간은 20~30분이며 실제 사람에게 측정한 시간은 아니다.
2. 진행자 화면의 ‘참여자가 접속할 주소’를 확인한다. 같은 네트워크에서 접속 가능한 운영 PC 주소와 8795 포트를 사용한다. 참여자에게 `127.0.0.1` 주소를 전달하면 참여자 자신의 PC를 가리키므로 접속할 수 없다.
3. ‘개인 초대 링크 CSV 다운로드’를 누른다. `participant`와 `url` 두 열의 완성된 링크가 나온다. 참여자 한 명에게 링크 한 개만 전달한다. 전체 CSV나 관리자 키를 배포하지 않는다.
4. 운영 전에 다른 PC에서 리허설 링크로 접속을 확인한다. 아래 별도 리허설 폴더를 사용하면 실제 모집 자료에 시험 답변이 섞이지 않는다.

```sh
bash experiments/participant/start.sh \
  --directory results/human-rehearsal --target 4 --invitations 8 \
  --contact '리허설 담당자' --demo
```

리허설과 실제 서버를 동시에 켜면 하나는 `--port 8796`처럼 다른 비어 있는 포트를 지정한다. 배포된 기본은 같은 네트워크용 서버다. 인터넷의 불특정 장소에서 접속하는 공개 HTTPS 사이트는 아직 배포하지 않았다. 원격 진행은 기관 VPN·적절한 HTTPS 호스팅 등 접속 환경을 갖춘 뒤 주소를 변경한다.

## 4. 진행자가 할 일

실험을 시작하면 참여자가 동의·이해 확인과 두 연습을 스스로 진행한다. 본 과제에는 정답·점수를 보여 주지 않는다. 사람마다 AI 지원 유무가 달라질 수 있고, 이는 자동 배정 결과다. 진행자는 모수·발주량·질문 선택에 대한 힌트를 주지 않고 접속·조작만 안내한다. 외부 AI·검색·참여자 간 답 공유를 하지 않도록 화면에서 공통 안내한다.

참여자가 창을 닫아도 같은 개인 링크로 다시 접속하면 이어서 진행한다. 두 기기에서 같은 링크를 열면 마지막 접속 세션이 유효하다. 완료 코드로 보상 지급 여부를 관리할 수 있지만 사람 이름과 코드의 대응표는 진행자가 시스템 밖에서 별도 관리한다. 실험 앱은 이름·연락처·IP 주소를 저장하지 않는다. 외부 호스팅을 사용할 경우 호스팅 계층의 로그는 따로 확인해야 한다.

‘참여 중단·응답 삭제’를 누르면 과제 응답·이전 이벤트를 삭제하고 익명 배정·중단 상태를 남긴다. 완료 후에도 개인 링크에서 삭제를 요청할 수 있다. 이미 내려받은 내보내기·백업에는 삭제 전 기록이 남을 수 있으므로 진행자는 해당 참가자 코드를 반영해 이전 사본과 분석을 갱신한다. 성과 확인 뒤 임의로 삭제하는 연구자 제외와 참여자의 철회를 구분한다.

운영 중에는 조건별 성과를 보이지 않는다. 목표 인원을 채우고 진행 중인 참여자가 모두 마칠 때까지 기다린다. 일찍 마감하면 사유를 기록해야 한다. 마감 후 새로운 제출은 받지 않는다.

## 5. 저장·재시작·분석

운영 폴더의 SQLite 데이터베이스가 원본이다. 서버를 중지했다가 **같은 명령·같은 폴더**로 켜면 이어서 운영한다. 진행 중 코드·과제·계획을 편집하면 재시작 검증이 실패한다. 연구 버전을 바꾸려면 새 폴더에서 별도 연구를 시작한다.

진행 중 백업은 다음 명령을 사용한다. 복사본에도 비공개 키·링크가 들어 있으므로 참여자에게 공유하지 않는다.

```sh
uv run --extra experiment python experiments/participant/run.py backup \
  --directory results/human-study-live --output results/human-backup-01
```

진행자 화면에서 ‘실험 마감’ 후 ‘결과 ZIP 다운로드’를 누른다. 또는 마감 후 명령으로 저장한다.

```sh
uv run --extra experiment python experiments/participant/run.py export \
  --directory results/human-study-live --output results/human-results.zip
uv run --extra experiment python experiments/participant/analyze.py \
  --export results/human-results.zip --output results/human-analysis.json
```

같은 이름의 결과를 덮어쓰지 않는다. `human-analysis.json`과 `human-analysis.md`가 생성된다. ZIP에는 익명 배정, 원시 답변 JSON·CSV, 이벤트, 고정 명세, 자료·코드 hash가 들어 있다. 개인 초대 토큰·세션 키·관리자 키는 내보내지 않는다. 분석기는 이벤트 연쇄 hash와 제출 답변의 일치도 검사한다.

주 결과는 8개 본 과제의 ‘기대 발주 regret 또는 보류 비용+질문 비용’을 보류 비용 400으로 나눈 **참여자 평균**이다. AI−대조군 값이 음수이면 손실 감소다. 128명이 8개씩 풀어도 독립 배정 단위는 1,024행이 아니라 128명이다. 연습은 주 분석에서 제외한다. 실제 실현 수요의 손실, 질문 수·비용, 모수·근거 정답률, 보류, 경과 시간·확신도는 별도 기술 통계로 보고한다. 시간에는 화면에서 떠난 시간도 포함된다.

배정된 모든 참여자가 완료하고 블록이 완성됐을 때 참여자 평균의 블록 조정 OLS·HC2 표준오차·블록 내 10,000회 무작위화 검정을 계산한다. 중단·누락이 있으면 남은 점수의 가능한 범위를 이용한 배정 효과 범위와 완료자 차이를 보고하고, 누락을 무시하는 p값을 생략한다. 이 가능한 범위는 신뢰구간이 아니다. AI 제안과의 거리는 제안과 발주가 모두 있는 답변에 한정한 기술 통계다.

## 6. 결과를 해석할 때

과제는 공개 기업 업무 자료를 옮긴 것이 아닌 생성된 실험 자료다. 고정된 8개 본 과제에서 모집한 사람에게 제공한 AI 지원의 효과를 본다. 실무 매니저를 모집하지 않았다면 ‘매니저 행동’ 결과로 쓰지 않는다. 새로운 업무·기업의 실제 이익으로 일반화하지 않는다. 사람의 AI 사용을 무작위 배정하는 접근은 Noy와 Zhang의 글쓰기 실험 [1]과 방법상 관련이 있지만, 과제·모델·평가 지표가 다르므로 그 논문의 효과 크기를 가져오지 않는다.

AI 제안은 공개 가중치로 실제 추론했다. 생성한 새 판매 이력에서는 수요를 크게 추정해 과다 발주하는 사례가 있다. 예를 들어 한 본 과제의 초기 제안은 약 66.39, 평가용 완전정보 최적량은 37이다. 정답으로 제안을 수정하거나 AI가 잘한 사례만 고르지 않았다. 이 실험은 **현재 품질의 AI 지원을 사람이 활용·수정하는 효과**를 측정한다. AI가 반드시 사람에게 도움을 준다는 가정을 두지 않는다.

영어 관측 문서를 모델에 넣고 같은 내용을 한국어 문장으로 표시한다. 두 참여자 집단이 읽는 원자료는 같다. 이를 한국어 ModernBERT 학습 성능의 검증으로 표현하지 않는다. 연습의 피드백과 정해진 매니저 답변 역시 실험 설계의 일부다.
