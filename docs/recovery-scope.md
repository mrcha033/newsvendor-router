# 관측한 응답 실패에 한정한 행동 보정

**사전에 고정한 v2/42를 보정 모델로 채택했다.** 부모보다 무응답 뒤의 질문 비용이 줄고 정상 판단은 보존됐다. 다만 단순 중단 규칙과 결과가 같아 새 학습의 고유한 이점은 확인되지 않았다.

이 비교는 매니저가 실제로 답하지 않은 뒤의 추가 질문을 줄이면서, 평상시 필요한 질문을 보존할 수 있는지 확인한다. 공개 숫자 추출이나 수요분포를 새로 학습한 실험은 아니다. Test와 별도 27개 출처 holdout은 사용하지 않았다.

## 변경한 판단 경로

[이전 전역 보정](recovery-stability.md)은 무응답 뒤의 요청 비용을 줄였지만, 질문하기 전부터 부족 비용 `b`를 확인하지 않고 발주하는 퇴행을 만들었다. 이번에는 **최신 관측 응답이 무응답·부분 응답이고, 해당 모수가 아직 미확정인 경우에만** 작은 보정 head를 적용한다. 추가 문서 조회의 실패나 이미 확인된 값은 이 조건에 넣지 않는다. 앞으로 매니저가 응답할지 여부나 평가 정답은 입력하지 않는다.

예를 들어 `b`를 물었지만 응답을 받지 못했고, 다시 질문하거나 문서를 조회할 수 없어 발주를 완성할 수 없다면 다른 항목을 추가로 묻는 비용을 줄이는 것이 목적이다. `b`를 아직 묻지 않은 초기 상태에는 보정값을 더하지 않는다.

기존 ModernBERT·모수 구성기·수요 GRU·행동 head를 고정하고 `94 → 128 → 2` 보정 head의 12,418개 파라미터만 학습했다. 기존 head와 보정 출력을 더하되, 적용 조건 밖에서는 기존 FP32 점수를 그대로 선택한다. 점수 보존은 같은 입력 표현과 FP32 계산을 기준으로 한다. native BF16 부모와의 실제 행동 보존은 별도 순차 실행으로 확인한다. 이는 행동 보정의 효과를 분리하기 위한 비교다. 전체 연구 모델의 encoder 학습 경로를 제거한 것은 아니다. [구현](../src/newsvendor/structured_recovery.py)

학습 입력은 실제 방문한 Train 상태 1,204개와 기존 정책의 후속 경로 11,044개에서 계산한 손실 표적이다. 이 중 294개 상태가 보정 적용 조건이며 나머지 910개에서는 점수가 정확히 보존됐다. 출처별 68개 family·928개 상태로 적합하고, 17개 family·276개 상태로 학습 시점을 선택했다. 부모 encoder는 이 Train 출처를 이미 보았으므로 독립 일반화 검증은 아니다.

## 첫 선택 실패와 선택 기준 수정

첫 실행은 내부 검증에서 선택한 행동의 손실이 처음으로 가장 낮아진 epoch를 사용했다. 세 seed의 선택 시점은 8·7·8이었다. 이 표적 점수는 개선됐지만, 새로운 응답으로 실제 Train 순차 실행을 하면 세 후보 모두 부모와 총손실이 같았다. **v1은 실제 개선 기준에 실패했으며 Dev로 넘기지 않았다.**

Train 원시 기록을 확인하니, 저장된 학습 상태와 정확히 같은 `b` 무응답 상태에서도 이후 `v` 질문을 선택했다. 마지막 40 epoch 가중치는 같은 여섯 판매 실패 상태를 모두 보류했지만, 내부 검증의 선택 행동 점수는 이전과 같았다. 행동 선택만 채점하면 점수가 일찍 평평해져, 아직 남은 가치 추정 오차를 구분하지 못한 경우다.

이를 확인한 뒤 별도로 v2를 등록했다. **선택 행동 손실이 같을 때에만, 같은 내부 검증 출처의 연속적인 가치 추정 손실을 비교**하도록 했다. 적합용 출처의 손실이나 이후 순차 실행 결과로 epoch를 고르지 않았다. 자료·batch 순서·optimizer·학습량은 그대로이며, 여섯 실행의 마지막 가중치가 v1과 정확히 일치했다. 바뀐 것은 선택 시점 40·33·39와 그 시점의 후보뿐이다.

## 실제 Train 비교

원래 Train 514사례·85개 family에서 네 번의 새로운 공통 응답 표본을 사용하고, 판매의 무누락 조건을 추가했다. 같은 모수 채널에는 질문 순서와 무관하게 같은 응답을 제공했다. 각 실행은 부모·두 규칙 기준선·세 seed의 13,260개 경로다.

| v2 정책 | 생성 총손실 | 판매 총손실, 누락 0% | 판매 총손실, 누락 10% |
| --- | ---: | ---: | ---: |
| 부모 | 133.1106 | 45.7155 | 115.8712 |
| 응답 실패를 반영한 고정 질문 | 156.4942 | 45.7155 | 115.6966 |
| 부모 + 단순 중단 규칙 | 133.1106 | 45.7155 | 115.4661 |
| 보정 head, seed 42·43·44 | 132.9167 | 45.7155 | 115.4661 |

단순 중단 규칙은 실제 실패한 필수 모수의 채널을 다시 요청할 수 없고, 조회·발주도 불가능한 기대손실 과제에서 보류한다. 그 외에는 같은 부모 판단을 사용한다. 고정 질문 기준선에는 같은 중단 규칙을 붙였다. 규칙으로도 얻을 수 있는 개선을 학습 고유의 성과로 세지 않기 위한 비교다.

세 후보 모두 실제 총손실·모수·상태·근거·발주 안전성 기준을 통과했다. 감소분은 생성에서 평균 0.1939, 판매 누락 조건에서 0.4051의 **질문 비용**이며 종료 손실은 같았다. v1과 v2는 서로 다른 새 응답 표본을 사용했으므로 각자의 부모 대비 차이로 비교한다. 앞선 v1 실패를 v2 결과로 덮지 않는다.

이후 대표 후보를 v2 전체 재학습 seed 42로 고정하고 세 seed 모두를 원래 Dev에서 평가했다. Dev에서 더 좋아 보이는 seed·epoch나 규칙 기준선으로 대체하지 않았다.

## Dev 결과와 해석

원래 생성 Dev 60사례·12개 family, 판매 Dev 336조건을 사용했다. 판매에서는 네 모수 채널의 응답 유무 16개 조합을 모두 실행해, 질문 순서에 따른 응답 난수 차이를 제거했다. 공개 문서 258사례도 같은 가중치로 확인했다.

| 정책 | 생성 총손실 | 판매 누락 0% | 판매 누락 10% | 판매 누락 20% |
| --- | ---: | ---: | ---: | ---: |
| 부모 `forecast-v1` | 147.6813 | 24.3925 | 71.9563 | 118.1415 |
| 응답 실패를 반영한 고정 질문 | 181.6758 | 24.3925 | 71.7439 | 117.7167 |
| 부모 + 단순 중단 규칙 | 147.6813 | 24.3925 | 71.8147 | 117.8583 |
| 보정 head, seed 42·43·44 | 147.6813 | 24.3925 | 71.8147 | 117.8583 |

**세 seed 모두 사전 등록한 부모 대비 기준을 통과했다.** 생성 손실과 정상 판매 조건은 그대로이며, 응답 누락 10%·20%의 판매 총손실이 0.1416·0.2832 줄었다. 같은 완전 관측 조건의 종료 손실은 그대로이고 질문 비용만 줄었다. 정확한 판매 손실의 분모는 **5개 기간·4개 출처의 35조건**이다. 전체 336조건에서 계산한 평균 요청 비용을 이 손실에서 빼는 방식으로 분모를 혼합하지 않았다.

모수·유형·상태·근거와 무누락 조건의 필요한 질문·응답 후 회복을 보존했다. 잘못된 발주 진행이나 이미 해결된 모수의 재질문도 늘지 않았다. 공개 문서 지표는 부모와 같으며, TAT-QA 엄격 정답은 여전히 16/48이다. 문서 추출과 수요 예측 자체의 개선은 아니다.

**단순 중단 규칙과 모든 행동·발주 결과가 같았으므로, 새 가치 학습의 추가 이점을 입증하지 못했다.** 고정 질문 기준선은 판매 누락 조건에서 더 낮은 비용을 보였지만 생성 과제에서는 질문 부담이 더 컸다. 이 결과를 학습 정책의 일괄 우위로 해석하지 않는다. Dev는 여러 개발 비교에 사용한 기존 자료이며 새로운 blind 평가가 아니다.

## 공개 파일로 재현

[기준 bundle 다운로드와 보정 모델 조립](model-bundle.md)을 먼저 실행한다. 조립된 모델의 전체 tensor hash는 `e01f07f8ab6325411975733303a277c95d5c914170fd833d18c452ab4bd105dd`이며 전체 크기는 151,884,856 파라미터다. 이전 tensor와 0으로 늘린 행동 입력 열을 보존하므로 전체 증가량 36,482개와 새로 학습한 12,418개를 구분한다. 기존 `forecast-v1` bundle은 그대로 보존한다.

```bash
tar -xJf docs/evidence/artifacts/recovery-scope-rollouts-v1.tar.xz \
  --wildcards 'results/l40s-recovery-scoped-dev-v1/*'

CUDA_VISIBLE_DEVICES=GPU-674d64b8-4bdf-7006-1791-5dc7f7245409 \
CUBLAS_WORKSPACE_CONFIG=:4096:8 HF_HUB_OFFLINE=1 PYTHONPATH=src \
.venv-l40s/bin/python docs/evidence/scripts/reproduce-recovery-scope.py \
  --bundle results/released-model/forecast-v1 \
  --refit results/l40s-recovery-scoped-v2 \
  --dev results/l40s-recovery-scoped-dev-v1 \
  --composed-bundle results/released-model/recovery-v1 \
  --output results/reproduced-recovery-scope.json
```

GPU UUID는 실제 L40S에 맞춘다. 공개 파일 61개를 빈 폴더에 복원하고, 원래 작업용 데이터·checkpoint·네트워크를 차단해 모델 조립부터 확인했다. 고정 간격의 생성 8사례와 판매 7사례의 16개 응답 조건을 여섯 정책으로 다시 실행한 **720개 경로**의 행동·발주량·손실이 정확히 같았다. 실제 L40S 재현 시간은 51.92초이며, 독립적으로 조립한 bundle의 전체 tensor와 추론도 대조했다. [복원·접근 차단·조립·실제 추론 기록](evidence/artifacts/recovery-scope-reproduction-v1.tar.xz)

새 전체 checkpoint는 기존 학습 loader로도 검증했고, 공개 자료 조립본과 전체 tensor가 같았다. 이 재현은 기존 결과 확인이며 새 학습·모델 선택·효과 평가가 아니다. 과거 Test 243.6274를 새 보정 모델의 Test 점수로 옮겨 적지 않는다. 연구 전체의 성능 목표는 아직 완료하지 않았다.
