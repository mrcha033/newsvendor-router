# 기존 출처 안에서 판매 학습 이력 확대

이번 비교는 작은 수요 GRU에 실제 판매 관측을 더 제공하는 실험이다. ModernBERT, 모수·근거 구성기, 매니저 질문 정책은 바꾸지 않는다. 새 관측으로 학습한 GRU가 기존 Dev 기준을 통과해야 질문·발주 경로의 교체 후보가 된다.

## 확대 전에 확인한 것

기존 Train 내부의 학습 출처 430개와 제외 출처 107개를 사용해 수요 모형을 점검했다. 이미 이 제외 출처로 선택한 epoch 7 checkpoint를 진단했으므로 독립 평가가 아니다. Dev, Test, 별도 27개 출처 평가는 사용하지 않았다.

- 제외 출처의 완전 관측 주간에서 로그정규는 절단정규보다 관측 NLL이 낮았지만, 부족:잉여 비용 9:1의 평균 발주 손실은 **4.5475 대 4.2357**로 높았다. 잉여 비용 부분이 **4.0986 대 3.5150**으로 커진 것이 차이의 원인이었다. 다만 품절 구간을 포함한 90% 분위수 적중률의 식별 범위가 넓어, 이 결과만으로 전체 잠재 수요를 과대 추정한다고 단정하거나 분포의 꼬리를 줄이지 않았다.
- 고정한 모수 예측에서 날짜별 배분 농도 1~8을 비교하면 학습 출처는 3, 제외 출처는 기존 값 4의 손실이 가장 낮았다. 농도를 다른 상수로 바꿀 근거로 삼지 않았다.
- 학습 출처에서 고정 추출한 2,048개 예측 시점·16개 미니배치의 공통 GRU 기울기를 비교했다. 세 분포 사이 음의 코사인 유사도는 각 조합에서 **0/16**이었다. 이 국소 진단은 학습 전체의 간섭 부재를 증명하지 않지만, 분포별 encoder 분리나 기울기 보정 모듈을 추가할 근거도 제공하지 않았다.

## 자료 선택과 분리

FreshRetailNet-50K의 기존 고정 revision `08c1fab7f9257bc73679d415d65d644165d351d4`에 있는 실제 Train 판매 이력을 사용한다. 관측값을 읽기 전에 매장·상품 식별자로 선택을 등록했다. 기존 Train 그룹에만 연결하고, 서로 다른 그룹을 합치는 매장·상품 조합은 제외한다. 기존 Dev·Test와 별도 고정 평가의 매장·상품도 제외한다. 기존 그룹당 최대 세 이력이며 선택 seed는 53이다.

| 항목 | 기존 | 확대 후 |
| --- | ---: | ---: |
| Train 판매 이력 | 542 | 1,045 |
| Train 출처 그룹 | 537 | 537 |
| 1일·7일 Train 예측 시점 합계 | 35,772 | 68,970 |
| Dev 판매 이력 / 출처 그룹 | 8 / 8 | 8 / 8 |
| Dev 예측 시점 합계 | 528 | 528 |

추가된 503개 이력은 기존 257개 그룹에 속한다. 독립 출처 503개가 늘어난 것이 아니다. 그룹별 관측 수와 학습 비중은 달라진다. 각 이력의 첫 60일·다음 7일 구분, 관측 필드와 rolling 예측 방식은 기존과 같다. 품절 판매는 잠재 수요의 정답으로 표시하지 않는다.

기존 입력·분리된 정답 파일은 새 파일의 바이트 단위 동일한 앞부분으로 유지했다. 모든 원래 그룹 식별자와 Train/Dev/Test 배정도 유지했다. 새 식별자가 붙은 그룹의 id는 원래 그룹을 가리키는 고정 id이며 구성원이 추가됐다고 다시 계산하지 않는다. 모든 매장·상품이 정확히 한 그룹·분할에 속하고 보호된 출처가 추가되지 않았음을 별도로 검사했다.

## 동일한 모델의 비교 규칙

[설정](../configs/l40s-demand-linked-v1.json)의 seed 42·43·44를 모두 실행한다. 같은 seed의 기존 학습 결과와 초기화, GRU, 세 분포 head, 손실, 출처 분할, optimizer, batch 크기와 최대 epoch는 같다. 모수 epoch는 Train 내부 출처 분할에서 선택하며, 분포 선택 head는 기존 Huber 목적함수를 유지한다. 관측 증가로 갱신 횟수와 실행 시간이 달라지므로 같은 계산량의 비교라고 주장하지 않는다.

새 Dev 결과를 보기 전에 다음 조건을 고정했다. 사전 후보 seed는 42이며 유리한 seed로 바꾸지 않는다.

1. 현재 선택한 GRU보다 완전 관측 7일 CRPS와 비용비 1·3·9의 발주 손실이 모두 낮아야 한다.
2. 1일 CRPS 악화는 10% 이내여야 하며, 완전 관측 7일 80% 구간 적중률은 감소하지 않아야 한다. 1일 관측 NLL과 주간 날짜별 관측 NLL도 악화되지 않아야 한다.
3. 세 seed 중 둘 이상이 주간 CRPS·평균 발주 손실·날짜별 NLL을 개선해야 한다. 등록된 기계 판정은 같은 seed의 대조군과 현재 선택된 seed 42 모두에 대해 이 조건을 요구한다.
4. 이 조건을 통과해야 문서·행동 가중치를 고정한 실제 질문·발주 rollout을 실행한다. 총손실 개선과 함께 모수·근거, 필요한 질문과 응답 후 회복을 유지하고 잘못된 진행·불필요한 요청이 늘지 않아야 교체한다.

완전 관측 주간 Dev는 겹치는 30개 기간·출처 6개다. 전체 rolling Dev는 출처 8개이며 품절 때문에 잠재 수요 전체의 calibration을 식별하지 못한다. 기존 생성 Test나 별도 고정 27개 출처 결과로 새 모델을 조정하지 않는다.

## 완료한 L40S 결과

세 seed의 학습·평가를 완료했다. 아래 각 셀은 **같은 seed의 기존 542개 이력 학습 → 1,045개 이력 학습**이다. 현재 선택된 모델은 기존 seed 42이며, 사전 후보도 새 seed 42로 유지했다.

| Dev 지표 | seed 42 | seed 43 | seed 44 |
| --- | ---: | ---: | ---: |
| 1일 관측 NLL | 0.4719 → 0.5005 | 0.5020 → 0.4681 | 0.5126 → 0.4841 |
| 완전 관측 1일 CRPS | 0.2083 → 0.1894 | 0.2104 → 0.1921 | 0.2126 → 0.1812 |
| 날짜별 주간 관측 NLL | 3.9276 → 3.8463 | 3.8772 → 3.9000 | 3.9084 → 3.8394 |
| 완전 관측 7일 CRPS | 1.2871 → 1.0774 | 1.2297 → 1.1929 | 1.1802 → 0.8838 |
| 완전 관측 7일 발주 손실, 비용비 9:1 | 3.8986 → 3.8278 | 3.9284 → 4.3095 | 4.1068 → 3.4157 |
| 완전 관측 7일 80% 구간 적중률 | 46.67% → 60.00% | 56.67% → 66.67% | 56.67% → 73.33% |

seed 42는 주간 CRPS·세 비용비의 발주 손실·날짜별 주간 NLL·완전 관측 구간 적중률을 개선했다. 그러나 **1일 관측 NLL이 악화돼 채택하지 않는다.** 1일 비품절 177개 시점의 NLL은 0.3738 → 0.3424로 개선됐지만, 품절 87개 시점에서는 0.6716 → 0.8222로 악화됐다. 더 좋은 결과를 낸 seed 44로 사전 후보를 바꾸지 않았다. 등록된 다섯 판정 중 네 개는 통과했고, 일별·주별 관측 NLL 비악화 조건 하나를 실패했다.

반복 결과에서도 같은 seed와 비교한 주간 CRPS는 3/3, 날짜별 주간 NLL과 평균 발주 손실은 2/3에서 개선됐다. 평균 주간 CRPS 차이는 −0.1810, 출처 재표집 95% 구간은 [−0.2775, −0.0355]였다. 비용비 9:1 발주 손실 차이의 구간은 [−0.3102, +0.1064]로 0을 포함했다. 작은 Dev를 사용한 서술적 비교이며 독립적인 확증 결과가 아니다. seed 42의 품절까지 포함한 주간 80% 적중률은 **6.82~95.08%**만 식별할 수 있어 전체 잠재 수요의 calibration도 해결하지 못했다.

모수 학습은 최종적으로 6·7·4회를, 종류 head는 최대 20회 중 8·3·15회를 선택했다. 세 seed 모두 기존 비교군과 초기값, 바깥·안쪽 출처 분할, 모든 기존 Train 예측 시점·관측값이 일치했다. 같은 seed의 대조군과 현재 선택 모델의 `F`·종류/모수·발주량도 원래 기록과 정확히 재현됐다.

| 계산량 | seed 42 | seed 43 | seed 44 |
| --- | ---: | ---: | ---: |
| 기존 전체 optimizer 갱신 수 | 13,007 | 12,675 | 12,701 |
| 확대 후 전체 optimizer 갱신 수 | 22,618 | 23,620 | 23,126 |
| 확대 후 학습 시간, 초 | 505.09 | 537.02 | 518.52 |

특성 구성 이후 세 학습·평가 전체는 **1,622.94초(27.05분)**, 작은 수요 경로의 최대 GPU 할당은 약 **0.302 GiB**였다. 전체 ModernBERT 모델의 메모리나 운영 지연 측정이 아니다. 갱신 수는 내부 검증·재학습과 최대 20회의 종류 학습을 모두 포함한다. 원시 내부 손실은 학습과 같은 float32·단일 CPU thread로 재집계해 12개 출처 분할의 모든 epoch에서 기록값과 정확히 일치했다. 최초 감사의 float64 집계는 최대 0.0000395 차이로 임의 절대오차 검사를 실패했으며, 그 시도도 원래 로그와 함께 보존했다.

채택 관문에 미달해 이 후보의 통합 매니저 질문·발주 rollout은 실행하지 않았다. 기존 선택 모델의 파일 해시가 그대로임을 확인했다. 테스트 298개, Ruff, 다섯 자료 버전의 출처·입력 중복 0건, 수치 smoke 30개를 통과했다. 이번 수요 비교로 공개 문서 추출이나 기존 생성 Test의 목표 달성을 주장하지 않는다. [전체 결과·판정·출처 분할·원시 손실·파일 해시](evidence/research-retail-linked-results.json)

## 자료와 진단 복원

[고정 자료](evidence/artifacts/retail-linked-data-v1.tar.xz)에는 확대 전후 입력·분리된 주석·manifest와 선택 등록을 담았다. FreshRetail 관측의 출처와 CC-BY-4.0 표시는 manifest에, 함께 보존된 다른 공개 과제의 출처·라이선스도 각 항목에 남아 있다. 이 비교에서 다른 공개 과제를 추가 학습하지 않았다. [Train 진단 원시 기록](evidence/artifacts/demand-linked-diagnostics-v1.tar.xz)에는 예측·분포별 손실·기울기 측정과 감사 코드가 있다. 모든 압축 구성원의 원본 해시를 검증했다. 별도의 빈 디렉터리에도 공개 자료를 복원해 원래 입력·주석·출처 배정 보존과 중복 0건을 다시 확인했다. [자료 감사·진단 요약·파일별 해시](evidence/research-retail-linked-checks.json)

빈 결과 디렉터리의 새 checkout에서 다음과 같이 이번 자료와 기존 비교군을 복원할 수 있다. 과거 실행 archive에 들어 있는 소스가 현재 학습 코드를 덮어쓰지 않도록 자료·결과 경로만 추출한다.

```bash
tar -xJf docs/evidence/artifacts/retail-linked-data-v1.tar.xz \
  --wildcards 'data/*' 'results/*'
for part in 42 43 44 records; do
  tar -xJf "docs/evidence/artifacts/demand-selection-results-${part}.tar.xz" \
    --wildcards 'results/*'
done
```

새 이력을 원본 parquet에서 구성하려면 [자료 선택 스크립트](../scripts/expand_retail_train.py)를 사용한다. 먼저 `--identities-only`로 선택을 고정하고, 같은 등록으로 관측을 구성한다. 기존 출력 디렉터리나 변경된 선택 등록을 덮어쓰지 않는다. 원본 parquet의 고정 revision·다운로드 주소·SHA-256은 자료 manifest의 `trainExpansion.source`에 있다. 등록은 원래 작성한 선택 스크립트의 해시도 검사한다.

L40S 한 장을 지정해 새 출력 경로에서 학습한다. config의 `output`은 실제 실행 당시 임시 경로이므로 재현 시 사용 가능한 빈 디렉터리로 변경할 수 있다. 기존 학습 결과를 덮어쓰지 않으며, 장치 UUID도 재현 장치에 맞게 config와 환경변수 양쪽에 동일하게 지정한다.

```bash
CUDA_VISIBLE_DEVICES=GPU-674d64b8-4bdf-7006-1791-5dc7f7245409 \
CUBLAS_WORKSPACE_CONFIG=:4096:8 PYTHONPATH=src \
.venv-l40s/bin/python scripts/study_demand.py \
  --config configs/l40s-demand-linked-v1.json
```

모든 seed의 학습이 끝난 결과 디렉터리에 `scripts/compare_observations.py --study 경로 --output 비교.json`을 적용하면 등록된 채택 조건을 다시 계산한다. 분포 종류는 참분포의 확률이 아닌 예측 손실 점수의 최솟값으로 선택한다.

완료한 이번 실행의 [seed 42](evidence/artifacts/demand-linked-v1-42.tar.xz), [seed 43](evidence/artifacts/demand-linked-v1-43.tar.xz), [seed 44](evidence/artifacts/demand-linked-v1-44.tar.xz)는 GRU checkpoint, Train cross-fit 손실, 후보·대조군의 모든 Dev 분포와 발주량을 포함한다. [실행 기록](evidence/artifacts/demand-linked-v1-records.tar.xz)은 최종 보고서의 모든 내부 검증 손실, 출처, 등록, 소스, 감사와 로그를 담는다. 최종 보고서와 중복되는 중간 `partial.json`은 로컬 전체 압축본에도 보존했으며 공개 기록에서는 제외했다.

```bash
for part in 42 43 44 records; do
  tar -xJf "docs/evidence/artifacts/demand-linked-v1-${part}.tar.xz" \
    --wildcards 'results/*'
done
PYTHONPATH=src .venv/bin/python scripts/compare_observations.py \
  --study results/l40s-demand-linked-v1 \
  --output results/l40s-demand-linked-v1/recomputed-comparison.json
```
