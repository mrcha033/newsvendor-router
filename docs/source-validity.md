# 새로 추출한 근거의 버전과 충돌 검증

모델이 새로 선택한 식에도 이전 상태 복사와 같은 **최신 근거·충돌 검사**를 적용했다. 기존 코드는 SKU·기간·단위·연산·선호 역할을 검증했지만, 새 추출 경로에서는 문서 버전을 검사하지 않았다. 따라서 이미 폐기된 금액이 발주 모수로 승인될 수 있었다.

[공통 후보 검사](../src/newsvendor/structured_forecast.py)는 현재 지원하는 문서 종류의 적용 가능한 후보와 모델이 실제 선택한 식을 모아 최신 버전만 남긴다. 최신 후보끼리 금액이 다르면 충돌로 처리한다. [새 추출 경로](../src/newsvendor/structured_rollout.py)는 구버전 식을 `superseded-source`, 충돌을 `conflicting-source`로 거부한다. 선택된 식을 다른 식으로 교체하거나 정답 금액을 채우지 않는다. 원시 head 출력은 별도로 보존한다.

이 검사는 기존 상태 복사·관측한 매니저 응답 복사에도 공통으로 사용된다. 이후 실제 응답과 최신 원문이 일치하면 값·근거·상태가 함께 회복된다. 관측된 요청 채널과 횟수가 허용할 때만 해당 항목을 질문할 수 있다.

## 같은 모델 예측으로 비교한 결과

기존 원시 예측과 수요 예측을 그대로 두고 이전·수정 코드를 실행했다. 먼저 이전 코드가 보존된 상태를 정확히 재현하는지 검사했다. 이 비교는 모델 학습 효과가 아닌 **근거 승인 규칙의 차이**다.

| Train 진단 | 잘못된 금액 승인: 이전 → 수정 | 모수 금액 오류: 이전 → 수정 |
| --- | ---: | ---: |
| 최초 392개 상태 / 1,568개 필드 | 47 → 0 | 258 → 258 |
| 정상 형식 변형 1,259개 상태, 선택 모델 | 741 → 0 | 1,902 → 1,902 |
| 같은 변형, 정상 형식만 학습한 후보 | 73 → 0 | 202 → 202 |
| 같은 변형, SKU·기간을 명시한 후보 | 0 → 0 | 54 → 54 |

최초 진단의 구버전 조건만 보면 196개 필드 중 오류는 계속 90개다. 잘못 승인한 47개가 미확정으로 바뀌어 미확정은 43개에서 90개로 늘었다. **틀린 값으로 진행하는 결함을 막았으며, 모델이 올바른 문서를 더 잘 찾게 된 것은 아니다.** 질문·보류와 최종 경제 손실은 따로 평가해야 한다.

원래 Dev 순차 실행에 기록된 선택 모델 753개 상태, 정상 형식 후보 727개, SKU·기간 명시 후보 752개는 수정 전후 모두 동일했다. 이는 같은 관측 상태에 대한 재실행 결과이고 새로운 순차 rollout 점수가 아니다. 최초 392개 상태는 L40S에서 실제 encoder·GRU 추론으로도 다시 비교해 이전 출력과 수정 후 승인 결과가 각각 정확히 일치함을 확인했다. Test는 실행하지 않았다.

회귀 테스트는 새로 추출한 구버전 값, 값은 같지만 근거만 구버전인 경우, 동일 버전 충돌, 다른 SKU·기간 및 다른 모수의 더 높은 버전을 다룬다. 실제 응답 뒤의 회복과 원시 출력 보존도 검사한다. 테스트 283개, Ruff, 출처·입력 분리 검사 4종, 수치 smoke 30개가 통과했다. [전체 결과·원시 기록](evidence/research-source-validity-results.json)

## 범위와 한계

이 검사는 현재 지원하는 금융 문서 종류와 식·단위·역할을 인식할 수 있는 범위에 한정된다. 선택된 문서의 제목이 임의 문자열이어도 검증하지만, 경쟁 문서 탐색에는 기존 문서 종류 규칙을 사용한다. 임의 형식의 모든 계약에서 버전 계보와 적용 조건을 이해한다는 증거가 아니다.

선택 모델의 가중치와 수요분포는 변경하지 않았다. 기존 발표 수치를 새 모델 성능으로 덮어쓰지 않으며, 입력 자료·모델·소스 hash와 수정 전후 원시 상태를 보존한다. 생성한 변형 문서 결과를 실제 조직 업무의 효과로 해석하지 않는다.
