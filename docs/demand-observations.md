# 날짜별 품절 관측을 사용하는 수요 학습

이 실험은 작은 수요 GRU의 관측 손실을 점검한다. ModernBERT, 문서 모수 구성기, 정보 요청 행동과 optimizer는 바꾸지 않는다. 수요 모델도 2층 GRU(hidden 128), 1일·7일 예측, 절단정규·로그정규·Weibull 총수요 head를 유지한다. 새 학습 옵션은 `demand.observation="daily_allocation"`이며 기존 기본값은 `aggregate`다.

## 수정하는 가정

월요일 판매량 10은 품절 없이 정확히 관측했고 화요일 판매량 3은 품절로 하한만 안다고 하자. 관측은 `월요일 수요=10, 화요일 수요≥3`이다. 이를 `이틀 총수요≥13`이라는 하나의 사건으로 대체하면 월요일에 관측한 정보를 잃는다. 하한은 유효하지만 그 survival 점수가 원래 관측의 likelihood와 같지는 않다. 독립 지수 수요와 재고 제한을 사용한 [수치 반례](evidence/research-aggregate-censoring-check.json)를 먼저 확인했다.

새 손실은 날짜별 정확한 판매와 품절 하한을 구분한다. 실제 재고 정책을 모두 아는 것은 아니므로 다음 가정을 명시한 후보 모형이다.

1. 기간 총수요는 기존의 0수요 질량과 세 가지 양의 분포 중 하나를 따른다.
2. 총수요가 양수일 때 수요가 있는 날짜 집합을 선택한다. 기존 1일 head의 0수요 logit을 재사용하고, 적어도 하루는 활성이라는 조건을 둔다. 새 head나 파라미터는 추가하지 않는다.
3. 양의 총수요를 활성 날짜들에 균등 simplex 분포(Dirichlet의 각 계수 1)로 배분한다.
4. 품절일의 관측은 해당 날짜 수요의 우측 검열로 취급한다. 검열 과정이 수요 모수에 관한 추가 정보를 주지 않는다는 가정이다.

두 번째 항목에서 재사용한 1일 확률이 주간 모형의 정확한 주변확률과 같다고 보장하지 않는다. 날짜 사이의 실제 패턴, 시간대별 재고 소진과 재입고 과정까지 식별한 모형도 아니다. 따라서 수학적으로 정의된 관측 likelihood와 실제 데이터에서의 적합성을 별도로 검증한다.

## 계산

양의 판매를 정확히 아는 날짜 수를 `k`, 활성 상태인 품절 날짜 수를 `m`, 관측 판매 합계를 `s`라고 한다. 양의 총수요 밀도 `f(D)`에 대해, `m>0`일 때 관측 밀도는 다음 적분에 비례한다.

```text
Gamma(k+m) / Gamma(m)
  × integral from s to infinity of
      f(D) × (D-s)^(m-1) / D^(k+m-1) dD
```

완전 관측일은 밀도에, 정확한 0수요일은 확률 질량에 기여한다. 판매 하한이 0인 품절일은 활성·비활성 양쪽 가능성을 합산한다. 모든 날짜가 0 하한으로 검열되었다면 정보가 없으므로 손실과 기울기는 0이다. 미래의 판매·품절 배열은 손실에만 들어가며 GRU 입력, 정규화 규모, 과거 관측 hash에는 들어가지 않는다.

적분은 조건부 생존확률의 quantile에서 Gauss–Legendre 구적법으로 계산한다. 경계와 먼 꼬리를 모두 처리하는 변수 변환과 float64 계산을 사용하고 기울기를 기존 float32 GRU로 전달한다. 64개 점은 Dev 점수가 아닌 Train 수치 검사로 선택했다. 출력 `F`와 optimizer는 기존 65개 지지점 표현을 유지한다. 적분용 점과 발주용 `F`의 점은 서로 다른 용도다.

검증에는 1일 기존 likelihood·기울기 일치, 0수요와 검열의 조합, 극단 정규 꼬리의 역함수, 자동미분 검사, 미래 표적 변경에 대한 입력 불변성, 출처별 cross-fitting이 포함된다. 7개의 독립 지수분포를 합한 Gamma 총수요에서는 위 적분이 날짜별 정확한 likelihood를 복원하는지도 확인했다. 이 검사는 실제 판매 예측의 성능 근거가 아니다.

## 공개 코드와 실제 관측의 의미

[FreshRetail 공식 코드](https://github.com/Dingdong-Inc/frn-50k-baseline/tree/8af694a09a5a427d1d50648d348c022565a781f2)는 수요 복원에서 시간대 6:22를 사용하고 `hours_stock_status == 1`을 품절로 처리한다. 실제 품절과 인위적으로 가린 관측을 사용한 복원 학습이므로 미관측 수요의 정답을 제공하는 것은 아니다. 이 코드의 대치 방법을 이번 likelihood로 구현했다고 주장하지 않는다. 확인한 파일의 revision·hash는 [원본 코드 기록](evidence/research-freshretail-code.json)에 보존한다.

Train 542개 이력의 32,520일을 대조하면 시간별 판매 합계가 일 판매와 모두 일치하고, 6:22 품절 표시 합계가 `stockoutHours`와 모두 일치했다. 품절 표시가 있으면서 양의 판매가 기록된 시간과 영업 구간 밖의 판매도 존재한다. 일별 품절 여부만으로 시간대별 관측 과정을 완전히 복원할 수 없다는 제한을 남긴다. [관측 검사](evidence/research-hourly-observations.json)

## 비교와 채택 조건

[고정 설정](../configs/l40s-demand-observations-v1.json)과 [실행 코드](../scripts/study_demand.py)는 seed 42·43·44, 동일 초기값·자료·학습 횟수·학습률·batch 크기를 사용한다. 기존 확장 자료의 aggregate 대조군 가중치를 재평가하고 입력·표적·예측의 동일성을 검사한다. 대조군을 이번에 다시 학습한 것으로 표시하지 않는다. Train은 537개 출처 그룹, 35,772개 예측이고 Dev는 기존 8개 그룹, 1일·7일 각각 264개다. 겹치는 기간과 반복 seed를 독립 표본으로 세지 않는다.

후보는 사전에 정한 seed 42다. 기존 사용 중인 GRU보다 7일 CRPS와 비용 비율 1·3·9의 정확한 발주 손실이 모두 낮아야 한다. 세 seed 중 둘 이상에서 CRPS와 평균 발주 손실이 동일 seed 대조군 및 기존 GRU보다 낮아야 한다. 1일 CRPS 악화는 10% 이내, 7일 관측 구간의 적중률은 감소하지 않아야 한다. 이를 통과한 경우에만 같은 문서 구성기로 실제 질문·발주 rollout을 실행해 교체 여부를 판단한다.

기존 합계 하한 NLL과 새 날짜별 관측 NLL은 서로 다른 측정값이다. 새 NLL만 낮아졌다는 이유로 교체하지 않는다. 완전 관측 기간의 손실과 적중률도 미관측 잠재 수요 전체의 calibration을 입증하지 않는다. 원래 보호 Test는 이 실험에서 사용하지 않는다.

## 결과: 기존 GRU 유지

세 seed 학습은 각각 188.44·187.18·190.80초에 끝났다. 동일 seed의 확장 자료 대조군은 저장된 가중치로 재평가했고 모든 예측이 일치했다. 기존 사용 GRU의 과거 측정은 CPU였으므로 마지막 대조도 CPU에서 수행해 정확히 재현했다. 최초 실행의 GPU 대조 검사 실패와 별도 완료 기록을 보존했으며 학습은 반복하지 않았다. 실행기에도 이 장치 조건을 명시했다.

| 비품절 Dev CRPS, 낮을수록 좋음 | 1일 | 7일 |
| --- | ---: | ---: |
| 기존 사용 GRU | 0.2111 | 2.7732 |
| 새 관측 모형, seed 42 | 0.3286 | 5.0301 |
| 새 관측 모형, seed 43 | 0.2596 | 2.6632 |
| 새 관측 모형, seed 44 | 0.2224 | 4.0508 |

평가 분모는 1일 177개, 7일 30개 비품절 구간이다. 세 seed 평균 7일 CRPS는 기존 GRU보다 1.1415 높았다. 부족:잉여 비용 9:1의 손실은 세 seed 모두 낮았지만 1:1은 두 seed에서 높아졌다. 새 날짜별 NLL도 기존 GRU보다 세 seed 모두 높았다. 사전 후보 seed 42는 네 채택 조건을 모두 통과하지 못했다. **새 후보를 주 모델에 연결하거나 Test로 선택하지 않고 기존 GRU를 유지한다.** [전체 비교와 출처별 구간](evidence/research-observations-results.json)

이 결과는 관측 손실의 수학적 정합성만으로 실제 예측이 개선되지는 않음을 보여준다. 날짜 배분·검열 가정과 학습의 일반화 문제가 남아 있으며, 종류 선택만 고치면 해결된다고 단정하지 않는다. 구현 검증은 [209개 테스트·수치·출처 검사](evidence/research-observations-checks.json), 학습 당시 소스는 [고정 archive](evidence/artifacts/demand-observations-v1-source.tar.gz)에 보존한다. 이 archive와 JSON 기록은 checkpoint나 확장 데이터 자체의 공개 배포를 대신하지 않는다.
