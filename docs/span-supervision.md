# 공개 문서의 정답 span 경계 수정

문서 추출의 학습 정답을 연결할 때 `19`를 `2019`의 일부와 매칭하는 결함을 수정했다. **코드 수정은 반영하지만 새 가중치는 채택하지 않는다.** L40S의 같은 초기값·자료·학습 순서 비교에서 수정된 정답 연결의 추가 정확도 이점을 확인하지 못했다. 현재 선택 모델은 `recovery-v1`이며 Dev·Test를 새로 실행하지 않았다.

## 확인한 결함과 수정

기존 `occurrences`는 정답 문자열이 원문에 들어 있으면 모두 정답 후보로 등록했다. 그 문자열을 토큰 위치로 바꾸면서 `19 → 2019`, `$1 → $124`, `0 → 300` 같은 잘못된 값을 맞는 답으로 학습할 수 있었다. 숫자가 여러 토큰으로 나뉘면 `19.5`의 앞부분만 선택하는 문제도 생긴다.

[수정한 학습 어댑터](../src/newsvendor/structured_labels.py)는 단어·숫자의 경계와 실제 선택할 토큰의 원문 범위를 함께 검사한다. 토큰에 합쳐진 문장 끝 쉼표 같은 문장부호는 허용하지만, 추가 숫자·글자·부호·단위는 정답 문자열과 같다고 처리하지 않는다. 맞는 span을 연결할 수 없으면 그 추출 손실을 제외한다. 없는 값이라는 새 정답을 만들거나 입력·평가 정답을 변경하지 않는다. 이 함수는 공유 도구 인자 학습에도 사용되며, Newsvendor의 기존 추론 경로는 바뀌지 않는다.

고정한 확장 TAT-QA Train 전체 13,095개 주석·2,177개 출처를 검사했다. 그중 span 주석은 5,678개다.

| 항목 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 연결된 span 후보 | 7,887 | 7,499 |
| 추출 손실을 적용할 수 있는 사례 | 5,677 | 5,630 |

128개 사례·117개 출처에서 후보 388개가 제거됐다. 47개 사례는 새 조건에서 안전하게 연결할 span이 없어 해당 손실을 제외한다. 제거된 후보를 모두 같은 종류의 숫자 오류로 세지 않는다. 여기에는 다른 값의 일부, 더 큰 토큰에 합쳐진 답, 현재 포인터로 안전하게 표현할 수 없는 경계가 함께 있다. 원래 주석·자료 hash·출처 분할을 보존했다.

## 같은 조건의 L40S 학습 비교

[사전 등록 설정](../configs/l40s-span-supervision-v1.json)과 [실행 코드](../scripts/study_span_supervision.py)를 사용했다. `recovery-v1`의 encoder·fusion·GRU·다른 head를 고정하고, 기존 시작·끝 포인터 131,072개 파라미터만 학습했다. 두 조건은 같은 초기 가중치, 8 epochs, 배치 순서를 사용한다. 이는 정답 연결의 영향을 분리하는 실험이며 주 모델의 encoder 학습 경로를 제거한 것이 아니다.

원래 Train의 출처를 나눠 4,515개 사례로 포인터를 학습하고 1,163개로 학습 시점을 선택했다. 부모 encoder가 이미 보았을 수 있는 Train 출처이므로 독립적인 일반화 평가로 해석하지 않는다. 선택 기준은 기존 scalar 정답 수, 동률이면 수정된 span NLL이다. 아무 추가 학습을 하지 않은 부모도 epoch 0 후보에 포함했다.

| seed | 수정 전 정답 연결: 선택 epoch / 정답 수 | 수정 후: 선택 epoch / 정답 수 |
| --- | ---: | ---: |
| 42 | 3 / 872 | 2 / 871 |
| 43 | 4 / 870 | 5 / 869 |
| 44 | 7 / 871 | 8 / 870 |

모든 분모는 Train 내부의 **span 사례 1,163개**이며, 전체 TAT-QA Dev 점수가 아니다. 추가 학습 전은 850개였다. 두 조건 모두 부모보다 높지만 수정 후 조건은 같은 seed의 수정 전 조건보다 각각 1개 낮다. 고정 8번째 epoch의 수정 전/후 정답 수도 각각 867/865, 868/868, 870/870이었다. 잘못된 정답 연결을 바로잡았다는 사실만으로 정확도 향상을 주장하지 않는다.

사전에 정한 다음 단계 조건인 ‘모든 수정 후 seed가 부모보다 개선되고, 같은 seed의 수정 전 학습보다 나쁘지 않을 것’을 통과하지 못했다. 따라서 전체 Train 재학습, 실제 순차 실행·Dev 선택, 가중치 교체로 확대하지 않았다. 표현 준비와 여섯 조건의 학습·내부 평가는 L40S에서 **213.21초**였다. 선택·최종 포인터, optimizer, 배치 순서, 모든 내부 학습 곡선과 예측을 보존한다.

## 남아 있는 추출 문제

수정 전 선택 모델을 기존에 고정한 Train 표본 144개와 확장 표본 512개에서 진단했다. 허용된 추가 검색으로만 정답 span·피연산자를 찾을 수 있는 사례는 두 표본 모두 0개였다. 현재 설정에서 검색 부족을 주된 원인으로 볼 근거는 없었다.

확장 표본의 지원 가능한 계산 163개에서 연산 종류는 158개, 첫째·둘째 피연산자는 각각 141개·140개가 맞았다. 각 피연산자의 실제 상위 5개 후보에는 정답이 162개씩 포함됐다. 후보 사이의 선택은 별도 미해결 문제다. 여러 답·개수·지원하지 않는 식, 출력 단위, 반올림 차이도 남는다. 이런 사례를 전체 점수에서 빼거나 계산기 값을 반올림해 성능 향상으로 보고하지 않았다.

현재 모델의 공개 TAT-QA Dev 엄격 정답 **16/48**, 수요 calibration, 경제 가치 학습의 추가 이점과 보호된 생성 Test 목표는 여전히 해결되지 않았다. 이 수정·내부 Train 비교를 실제 조직 문서의 발주 개선으로 해석하지 않는다.

## 검증과 공개 기록

테스트 343개, Ruff, 원본·확장·고정 평가 자료의 출처 분리 검사 5개, 수치 smoke 30개를 통과했다. 숨겨진 평가 정답은 feature·추론 입력에 넣지 않았다. 학습에 사용한 것은 기존 Train 주석뿐이다.

선택 가중치를 만드는 안내도 [검증 당시 커밋을 고정해 조립](model-bundle.md)하도록 보완했다. 공개 자료만으로 다시 조립한 전체 tensor hash는 기존 `e01f07f8…105dd`와 같다. CPU 스레드 수를 4개로 맞춘 이전/현재 소스의 공개 관측 예제 8개도 전체 출력이 일치했다. 처음 과거 출력과 대조했을 때 질문 비용 점수 하나에 약 `5.3e-7` 차이가 난 기록도 보존한다. 과거 모델을 재현할 때 현재의 학습 코드 변경으로 소스 검증이 실패하지 않도록 실행 소스를 명시한다.

[진단·정답 연결 감사·여섯 학습 조건·검증 결과](evidence/research-span-supervision-results.json)와 연결된 archive에 원시 기록, 실행 소스, 후보와 optimizer를 보존한다. 큰 중간 encoder 표현 cache는 공개 archive에 넣지 않고 hash와 재구성 경로를 기록한다. 정답 후보·예측·학습 곡선의 원시 기록은 포함한다. 학습 비교를 다시 실행하려면 설정에 hash로 고정한 Train snapshot과 부모 checkpoint가 필요하다. archive만으로 전체 재학습을 제공한다는 뜻은 아니다.
