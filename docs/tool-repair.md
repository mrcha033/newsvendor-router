# 도구·상태 연결과 행동 가치 학습 수정

v3에서 확인한 퇴행을 수정한다. 이전 실패 결과는 [v3 결과](tool-upgrade-results.md)에 보존한다. 실행 설정은 [l40s-tools-v4.json](../configs/l40s-tools-v4.json)이다.

## 수정한 경로

- 절차 ID와 메모리는 전용 조회·추출 입력으로 전달한다. 제한된 질문 prefix 앞에 절차 ID를 직렬화해 최근 사용자 발화를 밀어내던 경로를 없앴다.
- 실제 선택한 도구에 속하는 필드만 대화 메모리에 기록한다. 선택하지 않은 도구와 일반 답변 query의 추측을 이후 인자로 복사하지 않는다.
- 복사 후보가 현재 필드의 span 및 예측 역할과 맞는지 검사한다. 불일치하면 현재 원문 span과 출처를 사용하고 `copyRejected`를 기록한다. 원문에 존재한다는 이유만으로 현재 필드의 의미까지 맞다고 보지 않는다. 계산된 후보는 기존 계산식·피연산자 검증을 유지한다.
- Train의 연속 prefix 쌍에서 이전 자기 예측을 다음 관측 turn에 전달하는 보조 학습을 추가했다. 다음 turn의 입력은 해당 turn의 학습에만 사용한다. 미래 발화나 정답 인자를 이전 예측 입력에 넣지 않는다.
- Dev도 대화별 자기 상태를 이어서 평가한다. `argumentsDecisionAccuracy`는 인자가 관측 가능한 호출과 비호출 전체를 평가하고, `toolDecisionAccuracy`는 모든 턴의 올바른 행동·도구를 평가한다. 불필요한 호출도 실패다. 정답 인자가 숨겨진 호출은 인자 채점에서 제외한다.
- 도구별 빈도 보정은 호출 집합 안에서만 정규화한다. 호출과 비호출의 총 학습 가중치 비율은 원래 Train 빈도를 유지한다.
- 언어 학습을 시작하기 전 체크포인트도 Dev 선택 후보에 포함한다. 수정 학습 후보가 더 나쁘면 채택하지 않는다.

기존 저장 설정에서 비호출 가중치는 0.384, 도구 호출 가중치는 1.151~4.606이었다. 가장 흔한 도구 호출도 비호출보다 사례당 약 3배 무거웠다. 수정 설정은 비호출 1.0, 도구별 호출 0.462~2.341이며 호출 전체의 평균 가중치가 정확히 1.0이 되도록 Train 빈도로 정규화한다. 이 변경은 원래 클래스 비율을 보존하면서 드문 도구의 학습을 보완한다.

## 경제적 행동 학습

언어 단계에서는 encoder까지 미세조정한다. 이후 행동 가치 단계에서는 그 표현과 구성 head를 고정하고 `heads.value`만 학습한다. 생성 Train의 자기 예측 상태에서 각 허용 행동을 실제 실행한 뒤 최종 손실과 요청 비용을 측정한다. 정확한 응답 모형을 아는 planner의 값을 표적으로 쓰지 않는다.

고정 표현을 한 번 계산해 여러 critic epoch에 재사용한다. 손실은 두 비용 항의 회귀와 비용 순서의 보조 손실이다. Dev 실제 총손실로 후보를 선택하며, 모든 평가 후보 체크포인트와 Train 표적·rollout을 저장한다. 가치 head를 제외한 가중치 hash가 학습 전후 같은지 검사하고 공개 Dev 무퇴행 조건도 다시 검사한다.

이는 가치 학습이 encoder까지 갱신하는 실험과 구분해야 한다. 원래 v3의 공동 갱신은 공개 과제와 구성 정확도를 떨어뜨려 모든 후보가 탈락했다. v4는 그 간섭을 제거하는 단계별 학습이다.

## 검증 범위

단위·통합 테스트 64개, lint, source-group 검사와 수치 smoke 30건을 통과했다. 확장 Train 92,733건의 보호 Dev/Test 중복은 0이며 snapshot은 보존됐다.

학습·평가 진행 기록은 `results/l40s-tools-v4/base/42/`에 저장한다. 언어 단계는 v3 공통 체크포인트에서 최대 16,384건 추가 학습하며 2,048건마다 Dev를 검사한다. 이는 이전 전체 학습 이후의 수정 학습 예산이다. 재평가 head는 기본 끔으로 두고 같은 가중치의 켬/끔을 비교한다.

기존 Test는 이미 오류 분석에 사용됐으므로 이후 결과는 **고정 Test 회귀 평가**다. 새 blind Test로 표현하지 않는다. 가중치·설정 선택은 Train·Dev에 제한한다. 생성 경제 시나리오는 실제 조직 업무 효과성의 근거가 아니다.

## 완료된 L40S 결과

2026-10-08, base seed 42에서 실행했다. 언어 학습은 12,288건에서 Dev 미개선으로 종료했고 8,192건 시점 가중치를 선택했다. 자기 예측 상태 718개와 609개를 두 번 수집해 각각 가치 head 40 epoch를 학습했다. 학습 시간은 25분 29초, 데이터 준비·비교까지 포함한 실행 시간은 30분 3초, 최고 GPU 할당은 38.57 GiB였다. 이는 이전 v3 전체 학습 이후의 추가 비용이다.

### 도구·인자

같은 96개 Test 대화 prefix에 자기 예측 상태를 연결한 결과다. v3는 보존된 이전 실행, 이전 base와 v4는 이번 실행에서 평가했다. 기본 설정은 재평가 끔이며 Test 결과로 설정을 다시 고르지 않았다.

| 조건 | 정답 호출의 도구 일치 | 도구+인자 일치 | 호출 precision | 호출 F1 | 전체 행동 정확도 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 이전 base + 조립 수정 | 20/26 (76.9%) | 17/23 (73.9%) | 20/29 (69.0%) | 72.7% | 87/96 |
| v3, 재평가 끔 | 24/26 (92.3%) | 14/23 (60.9%) | 24/46 (52.2%) | 66.7% | 76/96 |
| v4, 재평가 끔 | 20/26 (76.9%) | 18/23 (78.3%) | 20/25 (80.0%) | 78.4% | 85/96 |
| v4, 재평가 켬 | 21/26 (80.8%) | 18/23 (78.3%) | 21/29 (72.4%) | 76.4% | 85/96 |

인자는 정답 값이 관측 가능한 23건에서만 채점한다. v4 기본 설정은 v3보다 인자 완전 일치와 호출 precision이 개선됐지만 호출 재현율은 하락했다. 목표 수준을 달성했다고 결론 내리지 않는다. 이전 base 대비 인자 정답 증가는 1건으로 작다. 단일 seed와 작은 Test의 점추정이며, 구성 요소 각각의 독립적인 효과를 분리한 결과도 아니다.

공통 체크포인트와 가치 학습 후 체크포인트의 도구·인자 예측은 동일하다. 재평가를 켜면 도구 정답이 1건 늘지만 호출도 4건 늘고 인자 정답은 늘지 않았다. 추론 지연 중앙값은 이전 base 57.36 ms, v4 끔 90.56 ms, 켬 81.86 ms였다. 단일 실행의 시간 변동이 있으므로 이 수치로 재평가 추가가 더 빠르다고 해석하지 않는다.

### 실제 rollout 손실

가치 학습 전후 생성 Dev 평균 총손실은 **534.27→149.98**이었다. 8개 후보 중 5개가 개선으로 채택됐고, 두 수집 주기 모두 공개 Dev 무퇴행 검사를 통과했다. 가치 head 외 가중치는 학습 전후 동일하다. 이 유지 주장은 가치 학습 단계에 한정된다.

| 생성 Test 조건 | 응답 오류 0 | 응답 오류 0.1 | 응답 오류 0.2 |
| --- | ---: | ---: | ---: |
| 이전 base | 240.35 | 242.57 | 247.54 |
| v3 최종 | 632.03 | 632.02 | 632.02 |
| v4 가치 학습 전 | 610.47 | 610.47 | 610.47 |
| v4 가치 학습 후 | **257.34** | **254.86** | **257.53** |
| v4 가치 사용만 끔 | 386.68 | 386.68 | 386.68 |

120개 생성 Test에서 평균 총손실은 terminal loss와 요청 비용의 합이다. 추론 시 가치 사용만 끈 조건은 따로 재학습한 no-value 모델이 아니다. 기본 v4의 가치 학습 전후 감소는 57.8%, v3 대비 감소는 59.3%다. 그러나 이전 base의 240.35보다 아직 7.1% 높다.

응답 오류가 없는 조건에서 v4의 잘못된 handoff는 0/120이다. 초기 구성 오류는 34/120이며, 초기 정답 86건 중 9건에서 이후 오류가 생겼고 초기 오류 34건의 회복은 0건이다. v3 초기 오류 25/120보다 나빠진 부분도 있어, 구성·회복 문제가 모두 해결됐다는 주장은 하지 않는다.

언어 미세조정 전후 공개 Test에서도 변화가 섞여 있다. CUAD grounded score는 0.500→0.533, ContractNLI 상태 정확도는 0.486→0.681이지만 같은 과제의 grounded score는 0.319→0.250, OR-ShARC 결정 정확도는 0.438→0.396이다. 수요 모델과 그 평가 수치는 같다. ABCD 단일 prefix 진단과 대화 상태를 잇는 본문의 평가는 서로 다른 프로토콜이다.
