# 도구·상태·절차 실험 결과

2026-10-08, L40S 한 장에서 구현·학습·고정 Test 비교를 완료했다. **새 구성을 기존 모델의 대체품으로 채택할 근거는 확보하지 못했다.** 도구 선택의 재현율은 높아졌지만 불필요한 호출, 인자 복사 오류, 경제적 행동 선택이 악화됐다. 재평가 head의 추가 효과도 확인되지 않았다.

구현은 [변경 문서](tool-upgrade.md), 전체 비교와 원시 파일 경로는 [tool-comparison.json](evidence/tool-v3-tool-comparison.json)에 있다. Test 결과를 보고 가중치나 학습 설정을 다시 선택하지 않았다.

## 실행 범위

- 기존 base의 언어·수요 공통 체크포인트에서 encoder 전체와 새 head를 미세조정했다. 새 구성은 152,113,735개 파라미터다.
- Train pool 94,137건을 한 번 순회한 뒤 8,192건을 추가 처리했다. 총 102,329건에서 Dev 미개선 3회로 조기 종료했고, 첫 순회 81,920건 시점 가중치를 선택했다. 이전 base의 선행 학습은 별도다.
- 이후 실제 자기 예측 상태 730개와 693개를 두 차례 수집해 각각 2 epoch 행동 가치 학습을 했다. 각 허용 행동 이후 실제 rollout의 손실과 요청 비용을 표적으로 사용했다.
- 기록된 추가 학습 시간은 약 3시간 31분이며, 최고 GPU 할당 메모리는 39.05 GiB였다. 비교 평가 시간은 별도다.
- 보호된 공개 Test와 source-family 분할을 유지했다. 도구 평가는 96개 대화 prefix, 경제적 평가는 생성 Test 120개다. 이는 실제 조직 업무의 효과성 근거가 아니다.

## 도구와 인자

같은 고정 Test에서 기존 모델은 상태 복사를 사용하지 않고, 새 모델은 대화별 자기 예측 상태를 이어 쓴다. 기존 가중치에도 수정된 인자 조립·검증 코드를 적용했다.

| 조건 | 도구 선택 | 도구+인자 완전 일치 | 도구 호출 precision | 전체 행동 정확도 |
| --- | ---: | ---: | ---: | ---: |
| 기존 가중치 + decoder 수정 | 20/26 (76.9%) | 17/23 (73.9%) | 20/29 (69.0%) | 87/96 (90.6%) |
| 새 구성, 재평가 끔 | 24/26 (92.3%) | 14/23 (60.9%) | 24/46 (52.2%) | 76/96 (79.2%) |
| 새 구성, 재평가 켬 | 24/26 (92.3%) | 14/23 (60.9%) | 24/48 (50.0%) | 74/96 (77.1%) |

도구 선택의 분모는 정답 호출 26건이고, 인자까지 채점 가능한 호출은 23건이다. 호출 precision은 모델이 실제로 호출한 건수를 분모로 하므로 불필요한 호출도 실패에 포함한다. 인자까지 맞는 예측 호출의 precision은 기존 17/26, 새 구성 재평가 끔 14/43, 켬 14/45였다. 올바른 도구이지만 인자 정답이 숨겨진 호출은 이 인자 precision에서 제외했다.

재평가 켜기/끄기는 실제 가중치 hash가 같은 비교다. 도구와 인자 지표는 같고, 재평가를 켜면 불필요한 호출이 2건 증가한다. 추가 학습 전후 체크포인트도 실제 가중치가 같았다. 아래 보존 기준에서 모든 행동 가치 학습 후보가 탈락했기 때문이다. 따라서 이 두 체크포인트의 같은 결과를 행동 가치 학습의 성공으로 해석할 수 없다.

Source-family bootstrap에서 새 구성(재평가 켬)과 기존 조건의 도구 선택 차이는 +15.4%p, 95% 구간 +3.8~+26.9%p였다. 인자 완전 일치의 family 평균 차이는 -9.7%p, 구간 -27.8~+8.3%p로 넓다. 정답 도구 호출은 13개 family, 인자 관측 가능 호출은 12개 family에 속하므로 큰 모집단에 대한 정밀한 추정으로 보지 않는다.

ABCD 추론 지연의 중앙값은 기존 53.94 ms, 새 구성 재평가 끔 75.03 ms, 켬 74.87 ms였다. 원시 case별 시간은 각 조건의 `logged-conversations.jsonl`에 있다.

## 자기 상태 연결에서 드러난 문제

새 모델을 각 prefix에 독립적으로 적용한 기본 진단에서는 도구 22/26, 인자 완전 일치 19/23이었다. 이전 자기 상태를 연결하면 각각 24/26, 14/23이 된다. 이 연결에는 memory와 이전 procedure ID가 모두 포함되므로 순수한 memory 단독 ablation은 아니다.

인자 완전 일치는 기존 정답 6건이 오답으로 바뀌고 오답 1건이 정답으로 바뀌었다. 퇴행 6건은 모두 `entity` 복사 경로를 선택했다. 5건은 `pull-up-account`, 1건은 `verify-identity`였다. 실제 관측 원문의 span이라는 조건은 만족했지만 현재 필드에 맞는 값은 아니었다. 출처 일치 검증만으로 의미적 적합성을 보장할 수 없다는 결과다. [사후 오류 비교](evidence/tool-v3-memory-differences.json)에 입력 ID, 예측, 정답, 원시 파일 hash를 보존했다.

구현상 언어 학습의 자기 상태 보조 사례는 주로 같은 prefix의 추가 조회다. 서로 다른 turn 사이에서 잘못된 역할·값이 복사되는 상황을 충분히 학습하지 못했을 가능성이 있다. 이는 코드와 관측 오류에서 도출한 원인 후보이며, 별도 학습 ablation으로 확인한 결론은 아니다.

새 구성의 절차 top-1은 68/96, top-3는 95/96이었다. 진행 단계는 87/96이지만 표적은 정확한 workflow node가 아니라 관측된 선행 도구 호출 수다. 명시적으로 필드를 언급한 질문 9건에서는 올바른 질문 필드를 2건 선택했다. 이 제한된 점수를 전체 질문 필요성 정확도로 해석하지 않는다.

## 행동 가치 학습

| 생성 Dev 후보 | 평균 총손실 | 공개 Dev 보존 기준 |
| --- | ---: | --- |
| 언어·수요 공통 체크포인트 | 542.55 | 기준 |
| 첫 수집, epoch 1 | 161.14 | ABCD 행동·CUAD 정확도 하락 |
| 첫 수집, epoch 2 | 180.49 | ABCD 행동·CUAD 정확도 하락 |
| 두 번째 수집, epoch 1 | 148.40 | ABCD 행동·CUAD·OR-ShARC 정확도 하락 |
| 두 번째 수집, epoch 2 | 148.45 | ABCD 도구·인자·행동 및 CUAD 정확도 하락 |

생성 Dev 60개에서 손실 감소는 관측됐으나 네 후보 모두 사전에 설정한 공개 Dev 무퇴행 기준을 통과하지 못했다. 최종 선택은 추가 행동 가치 학습 전 체크포인트다. 탈락 후보의 Test 성능은 평가하지 않았다. 각 후보의 Dev rollout과 오류·회복 지표는 [policy-diagnostics.json](evidence/tool-v3-policy-diagnostics.json)에 있다.

| 선택된 모델의 생성 Test 조건 | 응답 오류 0 | 응답 오류 0.1 | 응답 오류 0.2 |
| --- | ---: | ---: | ---: |
| 기존 가중치 + 수정 코드 | 240.35 | 242.57 | 247.54 |
| 새 구성의 선택된 공통 가중치 | 632.03 | 632.02 | 632.02 |
| 같은 새 가중치에서 가치 사용만 끔 | 376.88 | 384.75 | 384.75 |

표는 총손실 평균이며 낮을수록 좋다. 마지막 행은 추론 시 가치 head를 쓰지 않는 진단으로, 별도로 재학습한 no-value 모델이 아니다. 유효하지 않은 handoff의 terminal loss는 최소 hold loss로 처리하고, 원래 경제 손실과 추가 penalty를 원시 기록에 따로 남겼다. 기존 가중치도 이 정의로 재평가했다.

응답 오류가 없는 Test에서 새 구성의 초기 구성 오류는 25/120으로 기존 77/120보다 적었다. 그러나 초기 정답 95건 중 19건에서 뒤에 오류가 생겼고, 초기 오류 25건은 한 건도 회복하지 못했다. 기존 조건의 회복은 6/77, 오류 누적은 0/43이었다. 새 구성의 handoff는 4/120, 기존은 74/120으로, 구성 정확도 개선이 좋은 경제적 행동으로 연결되지 않았다. 잘못된 handoff는 두 조건 모두 0건이었다.

## 검증과 재현

전체 59개 테스트, lint, source-group/보호 split 검사, 30개 수치 smoke를 통과했다. 원천 정답 인자를 그대로 넣는 Train 조립 검사에서는 기존 규칙이 거부하던 2,541건이 수정 후 0건이 됐다. 이는 모델의 추출 정확도와 구분되는 실행 가능성 검사다.

- [학습 결과](evidence/tool-v3-training.json), [비교 결과](evidence/tool-v3-tool-comparison.json), [구현 검증](evidence/tool-upgrade-checks.json)
- 학습 source hash: `95f919815e4c6e3c63de268e75edb2859d812dd286d0c5bb1c4ce0aa231a6d8b`
- 평가 source hash: `a7d70d56b3049f5150648873ade4371710a5a0dc2aae9d28c8b2a0a9b18a6eee`
- 학습 source archive와 평가 source archive를 따로 보존했다. 평가 변경은 대화별 상태 격리, 기존 모델의 입력 유지, provenance 기록에 해당하며 학습 가중치를 변경하지 않았다.

후속 수정의 우선순위는 대화 turn 간 자기 상태로 필드 선택을 학습하는 것, 불필요한 호출까지 포함하는 Dev 선택 지표, 공개 과제와 경제적 행동의 동시 유지다. 현재 결과만으로 새 전체 구성을 채택하거나 행동 가치 학습이 성공했다고 결론 내리지 않는다.
