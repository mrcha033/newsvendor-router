# 연구·분석 실행 명세

2026-10-10 갱신. 연구 질문과 수리 모형은 [research.md](research.md)가 기준이다. 과거 명세는 [원본 보존 압축](evidence/artifacts/research-documents-before-economics-v1.tar.xz)에 남긴다.

## 분석의 세 단계

| 단계 | 식별 대상 | 현재 상태 |
| --- | --- | --- |
| 기존 자료 탐색 | parent 대비 scoped 구성 수정의 조건별 결과 차이 | 공개 Dev에서 실행; [결과](decision-effects.md) |
| 통제 2×2 파일럿 | 정의한 AI 경로와 비AI 경로, 질문 허용의 주효과·상호작용 | 비AI 기준선의 구현·Train 검증 전; 미실행 |
| 새 자료 확증 | 고정한 설계에서의 효과 크기·이질성·불확실성 | 새 출처·검정력·분석계획 고정 전; 미실행 |

기존 탐색을 사전등록 실험으로 재명명하지 않는다. 연구자와 모델이 이미 본 Dev는 가설 발견용이다. Test·기존 27개 출처 holdout을 새 확증 자료로 사용하지 않는다.

## 현재 탐색 분석의 고정 명세

[설정](../configs/research-economics-v1.json)은 기존 공개 자료와 분석 대상·짝짓기·분모·회귀식을 고정한다. 이미 알려진 결과의 사후 탐색임을 명시하며 신경망 추론·학습을 실행하지 않는다.

- 비교: 같은 recovery-v1 가중치의 parent와 scoped. 두 경로 모두 AI다.
- 문서 조건: 원래 형식, 다른 상품, 다른 기간, 구버전, 환불액·수수료 서술 순서.
- 응답 조건: 원래 측정의 추가 누락 mask가 없는 경로만 사용한다. 생성 환경의 기본 응답 확률·오류는 그대로다.
- 관측 행: `(사례 ID, 출처 family, 문서 조건, 방법)`; 총 3,960행. 모든 조건의 동일 사례와 출처·관측 가용성을 검사한다.
- 생성: 조건·방법별 60사례·12 family. 판매: 336사례·8출처·48기간, 정확한 손실은 35조건·4출처·5기간.
- 모형: `scoped−parent ~ 1 + 문서 조건`, 원래 형식을 기준으로 한 CPU PyTorch float64 OLS. 포화 모형이므로 조건별 효과는 짝지은 평균 차이와 같다.
- 검증: 원시 archive/member hash, 동일 ID·family·기간·결과 가용성, 중복·누락·불균형 조건, 손실 분해, 회귀와 평균의 일치.
- 민감도: 출처 동일 가중과 한 출처씩 제외. 출처 제외 범위는 신뢰구간이 아니며 p값·신뢰구간은 산출하지 않는다.
- 사후 통제: 정확도·질문 수·실제 발주 여부를 총효과 회귀의 통제나 제외 기준으로 쓰지 않는다. 이 지표는 별도 종속변수다.
- 품절: 검열된 수요의 정확한 손실은 양쪽 방법에서 함께 제외한다. 질문·상태 지표에는 남긴다. 발주 성공 사례만 선택해 평가하지 않는다.

### 손실의 정의와 분모

| 자료 | 종료 손실 | 총손실 | 해석 |
| --- | --- | --- | --- |
| 생성 Newsvendor | 알려진 모수 아래 기대 regret 또는 보류 비용; 잘못된 진행은 기존 하한 벌점 적용 | 종료 손실 + 실제 질문·조회 비용 | 생성 환경의 정책 성과 |
| 완전 관측 판매 | 실제 출력 q와 실제 관측 수요의 과잉·부족 비용 또는 보류·잘못된 진행 비용 | 종료 손실 + 실제 질문 비용 | 생성 경제 조건을 연결한 과거 판매 평가 |
| 검열 판매 | 수요 하한에 따른 기존 진단 가능 | 정확한 손실 평균에 포함하지 않음 | 판매를 잠재 수요 정답으로 사용하지 않음 |

종료·요청 비용의 효과를 분해할 때는 같은 35조건을 사용한다. 전체 336사례의 평균 질문 비용을 35조건의 종료 손실과 더하지 않는다. 생성과 판매의 손실 숫자를 하나의 회귀에 합치지 않는다. 과거 생성 Test 기준 240.35를 판매 손실이나 혼입 문서의 새로운 기준으로 옮기지 않는다.

## 후속 2×2 설계안

아래는 실행 전 설계 요구 사항이다. 등록 완료 또는 측정된 결과로 해석하지 않는다.

| 조건 | 관측 정보의 처리 | 매니저 질문 |
| --- | --- | --- |
| A0H0 | 비AI 구성·수요 기준선 | 금지 |
| A0H1 | 같은 비AI 경로 | 공통 규칙으로 허용 |
| A1H0 | 고정 AI 구성·수요 경로 | 금지 |
| A1H1 | 같은 AI 경로 | 같은 공통 규칙으로 허용 |

비AI 기준선은 관측 문서에서 규칙으로 값을 읽고, 과거 판매에서 비신경망 수요분포를 구성해야 한다. 정확한 구성·수요 추정·결측·품절 처리·최소 이력 기준은 Train에서 검증한 뒤 고정한다. oracle/reference 구성기, 숨겨진 금액·미래 수요·미관측 응답을 주는 기준선은 허용하지 않는다. first/no_value/고정 질문처럼 일부 AI를 사용하는 경로는 전체 비AI 조건이 아니다.

전체 묶음 효과를 측정할 때는 구성·수요 추정까지 두 경로의 정의에 포함한다. 모수 구성만 교체하고 GRU를 공유하는 별도 실험은 ‘AI 모수 구성 기능의 효과’라고 명명한다. 모듈 효과를 전체 도입 효과로 바꾸어 보고하지 않는다.

optimizer·허용 행동·질문 순서 규칙·예산·비용·응답 환경은 우선 공통으로 둔다. 같은 사례·필드의 응답은 질문 순서와 무관하게 일치시키며, 설정된 누락·오류 조건은 모든 방법에 동일하게 적용한다. 신경망 가치 정책의 추가 효과는 기본 2×2와 분리한다.

주 정보효과 실험에서는 b를 이미 확정된 동일 관리자 기준으로 제공한다. b 미선택·승인이 필요한 사례는 별도 층으로 보고한다. H0가 제도상 발주할 수 없는 상황의 손실을 질문의 순수한 정보 가치와 혼동하지 않는다.

주 회귀는 사례 고정효과와 A·H·A×H, 사전에 정한 A×환경 특성이다. 주 종속변수는 종료 손실+질문 비용이며 종료 손실·질문 수·위반·보류를 별도로 보고한다. 새 출처 수는 기존 반복 행 수가 아니라 경제적으로 중요한 최소 효과와 군집 구조를 반영한 검정력으로 정한다. 이 최소 효과·표본·반복·군집·다중 비교 계획은 아직 미확정이다.

## 자료와 입력 분리

구성기·특성·모델 입력은 관측 문서·판매·달력·이미 받은 응답만 사용한다. 참모수·미래 판매·응답 결과는 환경 또는 평가에만 둔다. source family, 원래 official split, 모델 revision, 관측 입력·별도 환경·가중치·소스 hash를 보존한다. 외부 문장을 실행 지시로 취급하지 않는다.

원래 생성 자료는 600건·120 family, Train/Dev/cal/Test는 360/60/60/120이다. 상보적 공개 자료는 서로 다른 과제의 주석으로, 실제로 연결된 하나의 조직 사건으로 합성했다고 표현하지 않는다. 기존 확장·새 출처 자료의 분할과 접근 이력은 [실험 이력](experiment-history.md)과 각 manifest를 따른다.

## 실행

```sh
uv sync --frozen
uv run python scripts/analyze_decisions.py \
  --config configs/research-economics-v1.json \
  --output results/decision-effects-reproduction
```

분석에는 공개 archive만 필요하며 GPU·모델 bundle·비공개 학습 자료가 필요하지 않다. 같은 이름의 출력을 덮어쓰지 않는다. 결과와 수치 항등식 검사를 함께 기록한다.

입력·분리 검사는 다음처럼 실행한다.

```sh
uv run newsvendor restore-eval
uv run python scripts/run_research.py \
  --config configs/research-from-scratch.json \
  --stage check --output results/research-data-check
```

기존 학습을 재현할 때는 L40S UUID를 명시하고 CUDA PyTorch 환경을 사용한다. 기본 `uv sync`는 CPU용이다.

```sh
export CUDA_VISIBLE_DEVICES="$NEWSVENDOR_GPU_UUID"
export CUBLAS_WORKSPACE_CONFIG=:4096:8
uv run --no-project scripts/train_demand.py \
  --config configs/research-from-scratch.json --device cuda
uv run --no-project scripts/run_research.py \
  --config configs/research-from-scratch.json --stage train
```

위 cold-start는 공개 snapshot에서의 학습 경로다. 현재 선택한 확장 자료·checkpoint의 완전한 학습 재개와 같지 않으며, 일부 주간 검열 가정의 한계도 남는다. 현재 선택 모델 추론은 [bundle 안내](model-bundle.md), 수요 선택의 정확한 설정은 [수요 비교](demand-selection.md)를 따른다. 이 문서 정리에서는 모델을 재학습하지 않았다.
