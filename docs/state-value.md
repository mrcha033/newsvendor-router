# 구성한 발주 상태로 행동 가치를 계산하기

구조화 상태만 받는 작은 가치 head를 구현하고 L40S에서 세 seed를 비교했다. **같은 상태에서 encoder 표현 변화의 직접 영향을 제거하고 지연을 줄였지만, 경제 성능의 채택 기준은 통과하지 못했다.** 선택 모델은 `forecast-v1`을 유지한다.

이전 학습에서는 구성한 모수와 가치 head 가중치가 같아도 encoder 표현이 바뀌면서 질문이 생략되는 사례가 있었다. 이번 비교는 이 연결을 점검한다. 문서 encoder와 모수 추출기는 그대로 사용하며, 문장 생성이나 범용 업무 절차를 추가하지 않는다. [직접 대조한 이전 사례](replay-coverage.md)

## 입력과 학습 경로

| 설정 | 가치 head 입력 | 가치 head 파라미터 |
| --- | --- | ---: |
| 기존 `encoded` | encoder의 행동별 표현 256개 | 33,154 |
| 대조군 `encoded_state` | 같은 표현 256개 + 관측 상태 106개 | 46,722 |
| 실험군 `state` | 관측 상태 106개 | 13,954 |

관측 상태에는 모델이 채택한 `c/p/v/b`, 존재 여부·유형·상태, 수요 후보의 평균·표준편차 범위, 발주량, 현재 계산한 손실, 공개 비용·질문 예산이 들어간다. 기존 [수치 입력 94개](policy-state.md)에 모수별 가능한 값의 범위 12개를 더했다. 범위는 모델이 구성한 후보와 채택한 값으로 계산하며 미관측 참모수나 매니저 응답 확률을 읽지 않는다. 통화 단위를 바꿔도 정규화한 입력은 같다.

두 새 조건의 가치 점수는 FP32로 계산한다. `state`는 구성한 상태에서 행동 점수를 구할 때 encoder를 다시 실행하지 않는다. 상태를 만드는 첫 encoder 실행과 입력 준비는 여전히 필요하다. 공개 질문 비용과 허용 행동 검사는 기존 경로를 사용한다.

문서의 모수·근거 주석으로 encoder까지 학습하는 경로는 유지한다. 이번 비교의 정책 단계에서는 같은, 이미 학습한 모수 구성기와 GRU를 고정하고 가치 head만 학습한다. 상태 전용 경제 가치 손실은 encoder로 역전파되지 않는다.

## 사전에 고정한 비교와 검증

같은 `forecast-v1` 부모에서 seed 42·43·44를 사용한다. 두 조건 모두 `policy.resetValue=true`로 가치 head를 새로 초기화하고 나머지 가중치를 엄격하게 복사한다. 같은 106개 관측 입력과 head 폭 128을 쓰지만, 입력 차원이 달라 파라미터 수와 초기 난수 배치는 같지 않다.

Train 514개 episode의 자기 예측 상태에서 두 차례 실제 rollout을 수집한다. 후보 행동을 실행한 뒤의 종료 손실과 요청 비용이 표적이다. 반복당 최대 40 epochs, 10 epochs마다 Dev 평가, 연속 세 번 미개선 종료, 학습률 0.001·batch 64를 고정했다. 같은 수집 규칙을 쓰지만 정책이 달라지면 방문한 상태와 표적도 달라진다.

학습 중 선택에는 기존 생성·판매 benchmark별 정규화 손실을 사용한다. 전체 모델 채택은 실제 총손실, 모수·근거, 필요한 질문과 회복, 불필요한 질문, 잘못된 발주 진행, 공개 문서 성능을 함께 검사한다. 세 seed 모두 기준을 만족해야 한다.

Dev를 열기 전 L40S의 Train 사례 32개에서 기본 경로의 변경 전후 tensor·구조화 출력 일치, 두 새 경로의 직접·cached 계산 일치, head의 gradient와 실제 갱신을 확인했다. 표현을 바꾸면 대조군의 학습 점수는 달라졌지만 상태 전용 점수는 같았다. 상태 전용 빠른 실행은 전체 forward와 점수·행동이 같았고 추가 encoder 호출이 없었다. 모수 구성기·GRU는 부모와 같았다.

첫 진단은 고정 비용인 보류 점수에도 표현 변화에 따른 변화를 요구해 중단됐다. 제한 전 학습 점수와 비용 제한 후 점수를 구분하도록 검사 코드를 수정했고 실패 기록도 보존했다.

## 완료한 L40S 비교

기존 모델의 생성 평균 총손실은 147.6813, 판매 완전 관측 기간의 평균 총손실은 24.3925다.

| 가치 입력 | Seed | 생성 평균 총손실 | 판매 평균 총손실 | 학습·평가 초 |
| --- | ---: | ---: | ---: | ---: |
| 문서 표현 + 수치 상태 | 42 | 141.9238 | 24.3925 | 329.60 |
| 문서 표현 + 수치 상태 | 43 | 148.3549 | 24.3925 | 336.22 |
| 문서 표현 + 수치 상태 | 44 | 141.9238 | 24.3925 | 351.48 |
| 수치 상태만 | 42 | 148.3549 | 24.3925 | 212.26 |
| 수치 상태만 | 43 | 148.3549 | 24.3925 | 215.98 |
| 수치 상태만 | 44 | 148.3549 | 24.3925 | 214.25 |

여섯 실행 모두 판매 Dev에서 필요한 요청·응답 후 회복 336건, 불필요한 요청·누락 모수로 종료·잘못된 발주 진행 0건을 유지했다. 최종 모수·근거 정확도도 100%다. 이는 통제 생성한 금융 문서와 응답에서 측정한 정확도다.

대조군 seed 42·44의 총손실 감소는 **질문 비용 6.5373 감소와 발주 종료 손실 0.7798 증가**가 합쳐진 결과다. 발주 자체가 더 정확해졌다는 결과가 아니며, seed 43에서는 개선이 반복되지 않았다. 상태 전용은 encoder 표현 변화의 직접 영향을 제거했지만 이번 학습에서 더 낮은 경제 손실로 이어지지 않았다. 두 조건 모두 세 seed 공통 기준에 미달해 채택하지 않는다.

표의 시간은 실제 rollout 수집·학습·평가 전체다. 최대 GPU 할당은 대조군 1.242 GiB, 상태 전용 0.655 GiB였다. 방문한 상태와 조기 종료 횟수도 달라 순수한 head 속도 비교는 아니다. 이번 단계는 전체 encoder 미세조정이 아니다.

별도로 같은 Train 입력 16개에서 문서 구성과 행동 선택 한 단계를 세 번씩 측정했다. 대조군의 seed별 평균은 61.64–61.94 ms, 상태 전용은 35.58–35.91 ms였다. 구성기 cache를 끄고 GPU 동기화를 포함한 L40S 측정이다. 이번 입력에서 지연은 줄었지만 경제 성능 기준을 함께 통과하지는 못했다.

공개 Dev 258건의 출력도 보존됐다. TAT-QA 엄격 정답은 16/48, ContractNLI 상태 정답은 44/72다. 부모와 두 입력 경로를 직접 재평가했다. 같은 경로의 나머지 seed는 가치 head 외 모든 가중치와 추론 설정의 일치를 검사해 해당 결과를 재사용했다. 공개 과제는 가치 출력을 사용하지 않는다. 공개 문서 성능 향상으로 표시하지 않는다.

## 해석과 재현 범위

상태 전용 seed 42의 두 번째 수집에 저장된 Train 921개 상태는 FP32 수치 입력 기준 432개 집단으로 묶였다. 같은 수치 입력에도 실제 응답 결과가 달라 표적이 다른 집단은 48개였다. 따라서 개별 실현 결과의 최저손실 행동을 못 맞춘 수만으로 오류를 판단하지 않는다. 집단 안에서 표적을 평균해도 선택이 다른 집단은 18개였다. 수집 당시 정책을 계속 실행한 유한 Train 결과의 진단이며 참 최적 행동이나 일반화 성능은 아니다.

같은 선택 head와 저장 Train 표적에서 Huber 손실의 절대 오차는 모두 1 이하였다. 이 검사에서는 큰 오차를 완화하는 구간이 작동하지 않았다. 전체 학습 궤적이나 다른 seed까지 검사한 결과로 확대하지 않는다. 진단 뒤 학습 표적·후보·선택 규칙을 바꾸지 않았다.

학습 후 상태 전용 출력에 빠진 `policyMode="value"` 표기만 보완했다. 학습 소스와 보완 후 소스를 각각 보존했다. L40S Train 입력 32개에서 이 표기를 제외한 선택 행동·점수·모든 출력은 정확히 같았다.

최종 소스에서 테스트 292개, Ruff, 네 자료 버전의 출처·입력 분리 검사, 30개 수치 smoke가 통과했다. 마지막 검사 중 디스크 공간 소진으로 중단된 기록도 보존했다. 검증된 archive의 중복 복사본만 정리하고 임시 파일 위치를 옮긴 뒤 전체 검사를 다시 통과했다.

이 연구는 반복 사용한 생성 Dev 60건·12개 family와 판매 Dev 336건을 사용한다. 판매의 정확한 경제 손실은 완전 관측 기간 **5개 × 통제 조건 7개**에 한정한다. Test·새 출처 27개를 다시 평가하지 않았다. 같은 GRU이므로 calibration 개선이나 실제 조직의 효과를 주장하지 않는다.

[전체 결과·검사·파일 hash](evidence/research-state-value-results.json)와 [원시 기록·후보 head·optimizer 묶음](evidence/artifacts/research-state-value.tar.xz)에 모든 seed와 불리한 후보를 포함한다. 전체 모델·초기 head·optimizer의 로컬 archive도 파일별 hash를 검증했다. 공개 원시 묶음에는 전체 backbone 가중치가 포함되지 않는다.

실험 설정은 [문서 표현 + 상태](../configs/l40s-research-state-value-v1-encoded_state.json), [상태 전용](../configs/l40s-research-state-value-v1-state.json)에 있다. 재학습에는 설정에 기록한 원래 자료와 부모 checkpoint가 필요하다. 현재 선택 모델의 공개 추론 묶음은 [기존 release 안내](model-bundle.md)를 따른다. Test와 수요 calibration의 남은 과제를 해결한 결과는 아니다.
