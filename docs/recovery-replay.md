# 응답 후 경로를 가치 학습에 추가한 비교

저장된 Train 경로에는 실제로 방문했지만 가치 head의 학습 시작점에는 포함되지 않은 후속 상태가 있었다. 이 상태들을 추가하고, 기존 숫자 상태 입력까지 연결해 L40S에서 비교했다. **두 비교 모두 사전에 등록한 추가 개선 기준을 통과하지 못했다.** 선택 모델 `forecast-v1`의 가중치는 유지한다.

## 확인한 수집 차이

기존 수집기는 사례당 한 행동 경로에서 학습할 상태를 고른다. 각 상태에서 다른 행동을 실행해 종료 손실과 요청 비용을 측정하지만, 그 후속 경로에 나타난 상태를 다시 독립 학습 시작점으로 넣지는 않는다. `responseSamples`를 늘리는 것은 후속 손실 표본을 평균내는 기능이며 이 방문 상태의 범위를 직접 넓히지 않는다.

기록된 관측을 family와 입력으로 중복 제거하면 기존 시작점은 890개, 모든 후속 경로를 포함하면 1,153개였다. 응답 실패 뒤 다른 질문이 가능한 상태는 판매에서 1→6개, 생성 자료에서 10→48개였다. 과거 총손실이나 정답으로 상태를 고르지 않고, 모든 관측 상태를 보존했다.

실제 비교에서는 응답 환경의 사례 ID까지 유지해 **928→1,204개 상태**를 사용했다. 위 진단과 중복 제거 단위가 달라 숫자가 다르다. 원래 Train 514사례·85개 family에 속하는 기록만 허용하며, 관측 task와 ID·family가 원래 자료와 같은지 검사한다. Dev·Test와 별도 27개 출처 holdout은 사용하지 않았다.

## 같은 초기 head와 같은 학습량

현재 선택한 ModernBERT·모수 구성기·수요 GRU를 고정하고 가치 head만 학습한다. 같은 자기 예측 상태의 행동별 후속 rollout을 4회 실행해 종료 손실과 요청 비용의 평균을 표적으로 삼았다. 총 **2,761개 상태·행동 조합, 11,044개 실제 경로**다. 생성 자료는 원래 응답 환경을 유지하고 추가 오답 잡음은 0, 판매는 응답 누락률 10%다. 미래 응답 seed와 숨긴 결과를 모델 입력에 넣지 않는다.

Train 내부에서 68개 family를 적합에, 17개 family의 276개 상태를 공통 검증에 쓴다. 기존 상태만 사용하는 조건의 적합 상태는 711개, 후속 상태까지 사용하는 조건은 928개다. 두 조건 모두 seed 42·43·44, 40 epochs, epoch당 15번의 batch 64 갱신을 수행한다. 같은 초기 가치 가중치를 사용하고, 이미 구현된 FP32 행동 head 경로로 저장 표현과 실제 모델 점수의 일치를 확인했다. 언어 encoder의 BF16 연산은 유지한다.

검증 기준은 선택 행동의 표본 후속 손실을 공개 보류 비용으로 나눈 뒤 family별·benchmark별로 평균한 값이다. 후속 행동은 표적 수집 당시 부모 정책이 수행했다. **이 값은 새 head를 처음부터 끝까지 실행한 정책 손실이 아니다.** encoder는 이전 학습에서 해당 Train 출처를 보았으므로, 이 내부 분할을 독립 일반화 평가로 부르지도 않는다.

| 입력과 학습 상태 | Seed 42 | Seed 43 | Seed 44 |
| --- | ---: | ---: | ---: |
| 기존 문서 표현 · 기존 시작점 | 0.194831 | 0.194831 | 0.194831 |
| 기존 문서 표현 · 모든 후속 상태 | 0.194831 | 0.194831 | 0.194831 |
| 문서 표현 + 숫자 상태 · 기존 시작점 | 0.194831 | 0.194831 | 0.194831 |
| 문서 표현 + 숫자 상태 · 모든 후속 상태 | 0.194831 | 0.194831 | 0.194831 |

초기 부모의 같은 표적 점수는 0.202602였다. 추가 학습은 이 유한 표적에 더 잘 맞았지만, **후속 상태 확대나 숫자 입력의 추가 이점은 없었다.** 숫자 입력 조건의 새 열도 실제 갱신됐다. 선택된 가중치의 norm은 0.433–1.957이었으므로 입력 연결이나 학습 갱신이 아예 없었던 실행은 아니다.

첫 비교는 표적 수집 174.28초를 포함해 326.34초, 숫자 입력 비교는 같은 경로·표적·encoder 표현을 재사용해 143.06초였다. 숫자 입력 비교에서 encoder를 다시 실행하거나 응답을 다시 표집하지 않았다. 전체 실행 시간을 운영 지연이나 backbone 학습 속도로 해석하지 않는다.

## 남은 오판과 추가 입력 검사

선택된 열두 head는 공통 내부 검증에서 같은 행동을 골랐고, 유한 표적의 최소손실 행동과 다른 상태도 같은 7개였다.

- 판매 상태 2개: 잔존가치 `v` 질문이 실패한 뒤 부족비용 `b`를 추가로 물었다. 측정된 경로는 결국 보류했고, 즉시 보류보다 요청 비용을 더 냈다.
- 생성 상태 5개: 동일한 한 family의 변형이며, 선호 `b`를 질문하는 행동보다 바로 계산을 마치는 행동의 표본 손실이 높았다.

이 최소값은 네 번 측정한 부모 후속 경로의 비교값이다. 정확한 응답 모형을 아는 최적 planner의 정답이나 새 정책의 실제 성능으로 해석하지 않는다.

판매 실패 상태 6개에서 명시적 상태를 `unavailable`↔`unconfirmed`로 바꾸어도 기존 경로의 토큰·마스크·허용 행동·고정 비용이 모두 같았다. 긴 수요 메타데이터 때문에 상태 prefix가 잘리는 [기존 입력 문제](policy-state.md)와 연결된다. 관측 이력은 고정한 검사이므로 모든 무응답 정보가 사라졌다는 뜻은 아니다.

이를 근거로 기존 94차원 숫자 상태 경로를 별도로 비교했다. 기존 256개 입력 열을 그대로 복사하고 새 열은 0으로 시작했으며, 1,204개 상태의 초기 선택이 유지되는지 확인했다. 숫자 벡터는 상태 변경을 구분했으나 표의 학습 결과는 개선되지 않았다. 입력의 구분 가능성만으로 정책 효과를 주장하지 않는다.

두 조건 모두 등록한 기준에 미달해 추가 순차 Train 검사, 전체 Train 재적합, Dev 평가로 확대하지 않았다. 이 결과로 기존 생성 Test 243.6274가 바뀌었다고 주장하지 않으며, 공개 문서 추출과 수요분포 calibration 문제도 남는다.

## 검증과 공개 기록

11,044개 경로의 시작 관측·자기 예측 상태와 학습 표적을 전수 대조했다. 표적 평균의 차이는 0이었고, 적합·검증 family 겹침도 0이었다. 테스트 323개, Ruff, 다섯 자료 버전의 출처 분리 검사, 수치 smoke 30개를 통과했다.

[원시 후속 경로](evidence/artifacts/recovery-replay-rollouts-v1.tar.xz)와 [관측 상태·표적·표현·후보 head·optimizer·모든 epoch·실행 코드](evidence/artifacts/recovery-replay-records-v1.tar.xz)를 공개한다. 다음 명령은 저장한 표현과 선택 head에서 내부 검증 점수를 재현한다. encoder나 순차 정책을 다시 실행하는 검사는 아니다.

```bash
tar -xJf docs/evidence/artifacts/recovery-replay-records-v1.tar.xz \
  --wildcards 'results/l40s-recovery-*-v1/*'

CUDA_VISIBLE_DEVICES=GPU-674d64b8-4bdf-7006-1791-5dc7f7245409 \
CUBLAS_WORKSPACE_CONFIG=:4096:8 HF_HUB_OFFLINE=1 PYTHONPATH=src \
.venv-l40s/bin/python docs/evidence/scripts/reproduce-recovery-heads.py \
  --encoded results/l40s-recovery-replay-v1 \
  --numeric results/l40s-recovery-numeric-v1 \
  --output results/reproduced-recovery-heads.json
```

CUDA PyTorch 환경과 L40S 한 장이 필요하며 UUID는 재현 장치에 맞춘다. 파일 hash와 패키지 소스를 확인한다. 공개된 캐시 표현에서의 재현 범위이며 전체 학습 데이터나 학습한 encoder의 독립 재현을 대신하지 않는다. 문서와 응답은 통제 조건이므로 실제 조직 효과의 증거로 사용하지 않는다.

공개 기록을 빈 디렉터리에 복원하고 기존 작업용 자료·checkpoint와 네트워크 접근을 차단한 L40S 프로세스에서 확인했다. 초기 head 2개와 선택 head 12개의 276개 내부 검증 상태, 총 **3,864개 상태별 선택과 전체 점수**가 정확히 일치했다. [복원 검사·접근 제한·원시 재현 출력](evidence/artifacts/recovery-replay-reproduction-v1.tar.xz)
