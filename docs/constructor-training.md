# 모수 학습과 실제 추출 입력의 일치

모수 학습에 사용하던 행동 query를 실제 모수 추출과 같게 수정했다. 동일한 추가 학습에서 Dev 상태 오류는 수정 전 46개에서 수정 후 14개로 줄었지만, 기존 모델의 12개보다 많아 **두 학습 후보 모두 선택하지 않았다**. 이 결과를 현재 모델의 성능 향상으로 보고하지 않는다.

## 확인한 입력 불일치

`language_view`의 연구 사례는 모수 필드만 정답으로 학습하면서 행동 query 8개를 함께 넣었다. `ResearchRouter.construct`는 같은 필드를 추출할 때 `hold` query 하나만 넣는다. query를 함께 인코딩하고 fusion의 self-attention을 적용하므로, 이 차이는 필드 표현도 바꿀 수 있다.

결과를 보기 전에 선택한 Train 관측 상태 16개에서 문서·대화 source token은 같았지만 query token은 모두 달랐다. 모수 학습을 constructor와 같은 `hold` query 하나로 수정한 뒤에는 16개 모두 일치했다. 회귀 테스트도 실제 두 경로의 행동 목록·query 위치·token ID·attention mask가 같음을 검사한다. 모델 크기, 추론 행동 종류, 최종 발주 계산기는 바꾸지 않았다.

## 실제 encoder 추가 학습

[수정 전 v2](../configs/l40s-research-state-replay-v2.json)와 [입력을 맞춘 v3](../configs/l40s-research-state-replay-v3.json)는 같은 선택 모델에서 시작한다. 같은 Train 자료·seed 42·optimizer·1 epoch·선택 기준을 사용한다. 실제 rollout에서 관측했지만 기존 언어 학습에는 없던 상태 225개를 추가했다. 원래 공개 Train 주석 774개를 함께 넣고 연구/공개 비중을 80:20으로 맞춰, 한 epoch의 사례 수는 4,358개다. 원래 Dev 입력·정답과 Dev 언어 사례가 동일함을 확인했다.

encoder의 tensor 134개, projection 2개, fusion 36개, 상태 head 4개가 실제 optimizer 갱신으로 바뀐 것을 두 실행 모두 확인했다. 수요 GRU는 바뀌지 않았다. 따라서 상태 head만 학습한 [앞선 진단](parameter-state.md)과 구분한다.

| 원래 Dev의 모수 구성 792개 상태·3,168개 필드 | 기존 모델 | v2 추가 학습 | v3 추가 학습 |
| --- | ---: | ---: | ---: |
| 상태 오류 | 12 | 46 | 14 |
| 금액 오류 | 0 | 0 | 0 |
| 근거 오류 | 0 | 0 | 0 |
| 선택한 language epoch | — | 0: 부모 복원 | 0: 부모 복원 |

입력 일치는 수정 전 추가 학습보다 오류를 줄였지만, 등록한 Dev 선택 기준에서 부모를 넘지 못했다. 단일 seed·작은 기존 Dev 결과이며, 참분포 calibration이나 실제 조직 업무의 효과성 검증이 아니다. 기존 Test와 새 27개 출처 holdout은 사용하지 않았다.

## 복원 후 정책 학습과 최종 평가

언어 후보가 거부돼 두 실행 모두 부모 가중치를 복원한 뒤 정책 단계를 수행했다. 따라서 다음 총손실은 **거부된 encoder 후보의 경제 성능이 아니다**. 학습 정책 후보도 Dev에서 더 나빠져 채택하지 않았다.

| 생성 Dev 학습 정책 | 평균 총손실 |
| --- | ---: |
| 복원한 기존 정책 | 147.6813 |
| 추가 가치 학습 10 epochs | 152.3972 |
| 추가 가치 학습 20 epochs | 153.4077 |

두 실행의 최종 모델 가중치 hash는 모두 현재 선택 모델과 같다. 모수 구성 학습에 사용한 사례 파일과, 복원 후 얻은 정책 학습 표적도 두 실행에서 같음을 확인했다. 최종 판매 Dev 손실은 양쪽 모두 24.3925이며 정확한 손실은 고유 판매 기간 5개 × 생성 조건 7개에 한정한다. 최종 모수·근거 100%, 잘못된 발주 진행 0건과 기존 공개 문서 예측도 부모 복원 이후의 결과다.

전체 시간은 v2 543.00초, v3 563.73초였다. v3는 당시 디스크 여유 때문에 임시 RAM 파일시스템에 checkpoint를 썼고, 종료 후 전체 파일을 영구 저장소로 복사하여 hash를 검증했다. checkpoint 저장 주기도 다르므로 이 시간 차이를 입력 수정의 속도 효과로 해석하지 않는다. GPU precision·batch·모델 크기는 같았다.

[검증·비교 기록](evidence/research-constructor-training-results.json)과 [원시 기록·등록 설정·정확한 실행 소스](evidence/artifacts/research-constructor-training.tar.xz)에 학습 실패와 부모 복원 사실을 포함한다. 전체 checkpoint·optimizer는 로컬 실행 폴더에 보존했으며 공개 묶음에는 큰 가중치를 넣지 않았다. 재학습 성공이나 외부의 전체 재현 완료를 선언하지 않는다.
