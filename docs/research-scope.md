# Newsvendor 연구의 주 범위

2026-10-09 사용자 지시에 따라 주 모델과 평가를 아래 범위에 집중한다. 기존 ABCD의 결과·실패 기록·가중치·원시 측정은 보존한다. 이 문서는 연구 범위와 현재 구현의 차이를 기록하며 새 성능 달성을 선언하지 않는다.

연구 질문은 **작은 학습 모델이 문서와 판매 이력에서 발주에 필요한 입력을 구성하고, 근거가 부족하거나 매니저의 선택이 필요하면 적절한 정보를 요청하여, 최종 발주 손실과 질문 부담을 줄일 수 있는가**이다.

최근 Train 진단에서는 매니저 응답 후 상태 오류 198개를 확인하고, 실제 rollout 상태를 주 언어 학습에 다시 넣는 연결을 수정했다. 같은 encoder의 상태 head 추가 학습은 Train 오류를 108개로 줄였지만 주 학습 정책의 Dev 총손실을 개선하지 못하고 중간 상태 오류가 하나 늘어 채택하지 않았다. [응답 상태 진단과 L40S 비교](parameter-state.md)

이어 encoder까지 추가 학습하면서 모수 학습과 실제 추출의 query 입력 불일치를 수정했다. 같은 학습 조건에서 Dev 상태 오류가 46개에서 14개로 줄었지만 부모의 12개보다 많아 두 후보 모두 거부됐다. 복원 후 정책 학습도 개선하지 못했으며 현재 모델 가중치는 유지한다. [입력 수정과 두 L40S 실행](constructor-training.md)

문서의 SKU·기간·신구 버전을 바꾸는 진단에서 쉬운 형식 표식에 의존하던 약점을 확인해 자료 생성·checkpoint 선택을 수정했다. 이후 정상 형식 자료로 두 조건을 L40S에서 각각 2 epochs 학습했다. SKU·기간을 query 앞에 명시한 후보는 변형 학습에서 제외한 Train 출처의 금액 오류를 5,036개 중 1,902개에서 54개로 줄였다. 그러나 원래 생성 Dev 손실은 147.6813에서 148.3549로 늘고 TAT-QA는 16/48에서 10/48로 낮아져 채택하지 않았다. 명시 없이 같은 자료만 학습한 후보도 판매 질문 20건을 놓쳤다. 모든 후보·실패·원시 예측을 보존하며 현재 가중치는 유지한다. [적용 범위 수정과 두 조건의 전체 결과](parameter-contrasts.md)

현재 선택한 ModernBERT·head·GRU의 전체 추론 가중치와 토크나이저도 공개했다. 원래 학습 자료 없이 로드하며, CPU·L40S에서 기존 checkpoint와 관측 예제 8개의 출력이 장치별로 일치했다. 이는 추론 재현 검사이고 확장 Train과 optimizer를 포함한 완전한 학습 배포는 아니다. [가중치·실행 명령·검증 범위](model-bundle.md)

이후 새 추출 경로에 빠져 있던 최신 근거·충돌 검사를 이전 상태 복사와 통일했다. 고정된 원시 예측으로 비교한 최초 Train 진단에서 구버전 금액의 잘못된 승인 47개가 0개로 줄었다. 다만 해당 오류가 미확정으로 바뀌었으므로 금액 추출 정확도가 개선됐다고 보고하지 않는다. 원래 Dev에 보존된 세 모델의 상태 2,232개는 승인 결과가 같았다. [버전 검증 수정·실제 L40S 대조·한계](source-validity.md)

정상 형식 후보가 판매 질문 20건을 놓친 원인도 분리했다. 같은 관측 입력과 구성 상태에서 가치 head 가중치는 그대로였지만, 변경된 공유 표현 때문에 행동이 달라졌다. 구성기를 고정하고 새 실제 Train rollout으로 가치 head만 학습하자 판매 요청·회복은 316건에서 336건, 손실은 39.0338에서 24.3925로 회복됐다. 반면 생성 Dev 손실은 140.3161에서 148.3549로 늘었고 공개 TAT-QA도 12/48에 머물렀다. 전체 모델은 교체하지 않았다. [행동 재학습·상충 결과와 비용](action-adaptation.md)

공개 Train 출력의 보존 손실을 추가해 encoder까지 다시 학습한 후속 실험에서는 원래 모수 Dev의 원시 상태 오류가 12→5개로 줄었다. 판매의 필요한 요청·회복 336건과 손실 24.3925도 유지됐다. 그러나 TAT-QA 정답은 16/48→11/48로 하락했다. 생성 총손실은 147.6813→146.7471로 줄었지만 종료 손실은 평균 0.7798 증가하고 요청 비용만 1.7140 감소한 결과였다. 새 가치 학습 후보도 모두 탈락해 선택 모델은 그대로 유지한다. [모든 언어 후보·원시 추출·손실 분해](language-retention.md)

최신 Dev 선택에서는 문서·행동 가중치를 고정하고 수요 GRU를 교체해 통제 retail 총손실이 **44.3274 → 24.3925**로 줄었다. 모수·근거 100%, 불필요한 요청·잘못된 발주 진행 0건을 유지했으며 `no_value`·고정 질문도 같은 손실이었다. 정확한 손실은 고유 판매 기간 5개에 한정한다. [최신 학습 횟수 선택과 통합 비교](demand-selection.md)

새 GRU 선택 후에는 기존 모든 분할과 매장·상품이 겹치지 않는 27개 출처에서 모델을 고정해 평가했다. 같은 새 자료의 이전/새 GRU 총손실은 **83.1514/69.0309**였지만 차이의 출처 재표집 95% 구간은 [−31.60, +3.54]였다. 정확한 손실은 완전 관측 30개 기간·출처 16개에 한정하며 확실한 일반화 효과로 단정하지 않는다. 모수·상태·근거 100%, 필요한 요청·회복 945건, 불필요한 요청·잘못된 진행 0건이고 `no_value`·고정 질문도 같은 손실이었다. 새 평가로 모델을 바꾸지 않았다. [별도 출처 검증과 재현 자료](retail-holdout.md)

기존 replay-v1의 고정 생성 Test 평균 총손실은 **243.6274**로 기준 240.35 미만에 미달했다. 고정 질문·no_value는 263.2379였다. 기존 Retail Test의 모수·근거는 100%, 불필요한 요청·잘못된 발주 진행은 0건이었다. 기존 Test는 다시 실행하지 않았으며, 아래 **고정 Test 평가**는 이전 모델의 기록이다. 별도 새 출처 평가는 이 기존 Test와 구분한다. 수요분포 전체의 calibration과 연구 전체 목표는 아직 해결되지 않았다.

## 주 모델의 역할

1. ModernBERT와 모수 구성·상태 head가 원가 `c`, 판매가 `p`, 잔존가치 `v`, 부족 비용 `b` 및 적용 조건을 근거와 함께 구성한다. 단위·기간·SKU를 보존하고 누락·충돌·미확정 상태를 표시한다. 계약의 사실과 매니저가 정해야 하는 선호를 구분한다.
2. 작은 수요 encoder와 분포 head가 판매·품절·달력 이력과 예측 기간으로 수요분포 `F`를 추정한다. 분포를 확정된 사실로 표시하지 않는다.
3. 정보 요청 head가 추가 근거 조회, 특정 모수에 대한 매니저 질문, 공통 optimizer에 전달, 보류 가운데 선택한다. 질문은 대상 모수·이유·선택지로 표현한다. 최종 발주량은 공통 optimizer가 계산한다.
4. 응답을 받으면 근거와 모수 상태를 갱신하고 같은 경로에서 다시 판단한다. 행동 가치의 학습 표적은 자기 예측 상태에서 실제 수행한 Train rollout의 발주 손실과 요청 비용이다.

예를 들어 반품 시 회수 가능한 금액을 계약에서 찾으면 `v`의 근거로 사용한다. 찾지 못하면 그 항목을 질문한다. 부족 비용이 매니저의 정책 선택인 경우에는 문서의 임의 숫자로 대체하지 않고 선택을 요청한다. 응답 이후 수정한 입력이 실제 발주량에 반영되는지 평가한다.

기본 비교군은 '근거가 부족하면 해당 항목을 질문'하는 고정 정책이다. 학습 정책의 추가 가치는 같은 모수 구성기·자료·응답 조건에서 불필요한 질문을 줄이거나 중요한 정보를 먼저 확보하여 최종 손실을 낮추는지로 판단한다.

## 기존 수정의 위치

| 구성 | 주 연구에서의 역할 |
| --- | --- |
| 필드 역할·자료형·조립·단위 검증 | Newsvendor 모수가 올바르게 optimizer에 전달되도록 유지 |
| 공유 추출·근거·상태 복사 | 질문 응답 이후 모수와 출처를 함께 갱신하는 데 사용 |
| 문서 검색 | 발주 모수의 근거를 찾는 범위에서 사용 |
| ABCD 업무 절차·진행 단계·도구 후보 재평가·대화 이력 모듈 | 보조 도구 실험으로 보존; 주 모델의 필수 구성이나 성공 기준으로 삼지 않음 |
| 자기 예측 상태의 행동 가치·회복 | 소수의 발주 정보 요청 행동에 집중 |

ABCD 도구·전체 인자·호출 precision 각각 90%라는 이전 목표와 미달 결과는 보조 실험 기록에 남긴다. 이를 원래 연구의 달성 여부와 동일시하지 않는다.

## 주 평가

| 평가 | 측정할 내용 |
| --- | --- |
| 모수·근거 | 실제 채택한 값, 단위·기간·SKU, 원문 위치, 사실/추정/선호, 누락·충돌 상태 |
| 수요분포 | 비검열·검열 관측에 맞는 예측 손실, calibration, 구간 coverage, 선택한 종류·모수 |
| 매니저 요청 | 필요한 질문의 누락, 이미 해결된 항목의 중복·불필요한 질문, 요청 비용·횟수 |
| 응답 후 회복 | 자기 예측 상태의 오류를 응답으로 고치는지, 근거와 상태가 일관되게 갱신되는지 |
| 발주 | 모델이 실제 전달한 입력으로 계산한 발주량의 손실, 근거 없이 진행한 비율, 보류율 |
| 크기·실행 비용 | 같은 입력·자료·head를 사용하는 base/large의 지연·메모리와 성능; 가치 학습 제거 비교 |

기존 생성 Test 120건의 평균 총손실 **240.35 미만**은 원래 분할과 손실 정의에 대한 비교 기준으로 보존한다. 새로 연결한 수요분포 실험의 손실을 기존 수치와 직접 혼합하지 않는다. 새 지표의 완료 수치를 임의로 만들어 충족했다고 선언하지 않는다. 모델 선택은 Train·Dev로 수행하고, 기존 Test를 새 blind Test로 표현하지 않는다.

## 확인된 구현 차이와 다음 우선순위

2026-10-09 범위 재점검 당시:

- `ResearchRouter.construct`는 언어 head로 모수를 구성한 뒤 `construction.demand`를 호출한다. 이 생성 시나리오 경로의 `F`는 경험적 관측, 허용 후보 또는 응답으로 얻은 예측에서 온다. 학습한 수요 encoder의 출력은 이 rollout에 연결되어 있지 않다.
- `structured_train.infer(linked=True)`에는 학습한 수요분포와 추출 모수를 `economic_state`에서 결합해 optimizer를 호출하는 별도 추론 경로가 있다. 이 존재만으로 순차 질문·회복·최종 손실까지 통합 검증됐다고 할 수 없다.
- ABCD 대화 controller는 ABCD 입력 조건에서 동작한다. 이 실험의 정확도 향상을 Newsvendor의 발주 개선으로 대체해 보고하지 않는다.

우선 실제 관측 가능한 판매 이력·기간·SKU 계약을 명시하고, **학습한 `F`와 문서 모수 → 정보 요청과 갱신 → 공통 optimizer → 실제 출력 발주량의 평가**를 같은 경로로 연결한다. 이 경로를 고정 질문 정책과 비교한 뒤 모델 크기와 가치 학습의 기여를 판단한다.

이후 `structured_forecast.py`와 `structured_retail.py`를 추가하여 명시적인 `task.forecast`가 있는 입력을 기존 `ResearchRouter`의 질문·갱신 경로에 연결했다. 학습한 GRU의 `F`를 실제 optimizer에 전달하고 SKU·기간·단위·과거 관측 경계를 검사한다. 분포를 주석된 참분포와 완전 일치시키는 기존 생성 채점을 재사용하지 않고, 실제 출력 발주량을 관측 판매에 대해 별도로 채점한다. 기존 생성 입력과 결과는 유지한다.

L40S 실행 `results/l40s-research-v2/base/42`는 기존 가중치에서 ABCD 전용 모듈의 625,252개 파라미터를 제외한 동일한 core 가중치로 시작했다. 문서 encoder까지 모수·근거·상태를 미세조정하고, 모수 구성기를 고정한 뒤 자기 예측 상태의 경제 가치 head를 학습했다. 학습한 수요 GRU는 부모 checkpoint에서 가져오며, 결합 자료로 학습하지 않은 언어 context를 GRU에 임의로 더하지 않는다. 이후 v3·v4는 같은 encoder·GRU를 유지하고 상태 갱신 결함을 수정한 뒤 정책만 다시 비교했다. 세 실행은 모두 종료됐으며 Test는 사용하지 않았다.

이 통제 결합 자료는 Train 1,260/Dev 336사례이며 판매 source family는 25/8개로 분리된다. 충분한 근거, c/p/v/b 각각의 누락, v 충돌, v·b 동시 누락이라는 일곱 조건을 각 관측 기간에 적용한다. 사례 수를 독립 판매 기간 수로 해석하지 않는다. 품절 없는 7일 관측은 Train 22/Dev 5기간뿐이다. 정확한 경제 가치 학습·손실 비교는 이 관측 범위에서 수행하고, 품절 기간의 손실은 하한으로 표시한다. 전체 관측은 분포의 검열 likelihood 및 모수·질문 평가에 남긴다. 구현·수치·누출 검증은 [검증 기록](evidence/research-path-checks.json)에 보존한다.

최초 실행 `results/l40s-research/base/42`는 학습의 첫 optimizer step 전에 중단됐다. 도구 모듈이 없는 구성에서 조회 플래그가 `None`이 되는 오류를 수정했다. 초기 측정에는 `units per pack`을 금액으로 해석하여 올바른 나눗셈을 거부하고 잘못된 원가를 주석하는 결함도 있었다. 이 실행의 원시 측정은 보존하되 성능 근거에서는 제외한다. 단위 파서와 독립 수치 주석 검사를 수정했으며, c/p/v/b의 응답은 해당 문서만 갱신하도록 검증했다. 공시된 보류·질문 비용은 정확히 계산하고 나머지 행동 후 손실만 학습한다.

서로 연결되지 않은 공개 문서와 판매 SKU에 임의의 연결 표적을 만들지 않는다. 생성된 통합 사례는 통제 진단으로 표시하고 실제 조직 업무의 효과성 근거와 구분한다. 모델 revision·source hash·source/family 분할·원시 측정을 유지한다.

## 상태 갱신 수정과 확인된 결과

v3는 받은 수치 응답을 현재의 동일 SKU·기간·최신 근거와 대조한 뒤 보존하고, 이미 읽은 문서를 반복 조회하지 않도록 수정했다. v4는 다른 항목의 답을 받은 뒤 기존 값을 다시 추출하지 못하는 경우에도, 이전에 모델이 채택한 값과 원문 hash·식·적용 범위가 그대로 유효하면 보존한다. 변경된 문서, 새 버전, 충돌, 다른 SKU·기간에는 이전 값을 복사하지 않는다. 초기 추출 결과를 정답으로 채우는 규칙은 추가하지 않았다. 모델의 원시 예측과 최종 채택 상태는 별도로 기록한다.

모수·질문 지표의 분모는 Dev 336사례다. 총손실은 완전히 관측된 **5개 판매 기간 × 7개 통제 조건**에 한정한다. v4의 최종 채택 모수·근거 정확도는 100%이고, 원시 신경망 모수 예측 정확도는 99.628%다. 질문 336건은 모두 필요한 질문으로 채점됐다. v3·v4의 가치 head 재학습 후보는 초기 모델보다 Dev 손실을 낮추지 못해 채택되지 않았다. **현재 비교는 행동 가치 학습의 추가 이점을 입증하지 못했다.** 원시 기록·가중치·시간·출처는 [v3](evidence/research-v3-results.json), [v4](evidence/research-v4-results.json)에 연결되어 있다.

전체 rolling 판매 Dev를 따로 점검하면 8개 source family에서 1일/7일 각각 264개 예측 구간이 나온다. 완전 관측은 각각 177개/30개이며, 이 구간에서 80% 예측구간 적중률은 77.40%/33.33%였다. 이웃 구간이 겹치고 품절 없는 기간만의 조건부 지표이므로 독립 표본 수나 전체 수요의 calibration으로 해석하지 않는다. Train의 source-group cross-fitting으로 종류를 선택하고 검열 likelihood로 모수를 적합한 단순 기준선도 비교했다. 기준선의 관측 NLL은 GRU보다 1일 0.0861, 7일 0.0898 낮았지만, 품절 없는 7일 구간의 CRPS와 발주 손실은 GRU가 더 낮았다. 한 지표만으로 수요 경로의 우위를 선언하지 않는다. 원시 측정은 `results/research-checks/demand-dev-v3`와 `demand-baseline`에 보존했다.

품절 구간도 버리지 않고 적중률의 식별 가능한 범위를 계산했다. 관측 판매 하한이 예측구간 상단을 이미 넘었으면 반드시 미적중이고, 그렇지 않은 품절 구간은 적중 여부를 알 수 없다. 현재 GRU의 전체 관측 적중률 범위는 1일 51.89–81.06%, 7일 3.79–92.05%다. 7일의 비품절 적중률 33.33%만으로 전체 calibration을 확정할 수 없으며, 이 넓은 범위도 적절성을 입증하지 않는다. source family 단위 재표본화와 실제 optimizer에 전달된 이산 `F`의 구간 질량을 함께 기록했다. [품절 포함 식별 범위](evidence/research-calibration-bounds.json)

순차 추론은 `structured_train.infer(..., linked=True, state=previous["constructedState"])`에 이전 채택 상태를 전달한다. 내부 rollout도 동일한 근거 검증을 거쳐 상태를 전달한다. 반환한 `fields`는 실제 optimizer 입력이며, `constructedState.rawFields`는 보존 전 모델 예측이다.

## 경제 가치 학습 제거 비교

`results/l40s-research-v4/no_value/42`는 base v4와 같은 초기 checkpoint·Train/Dev·encoder·모수 구성기·수요 GRU에서 시작했다. 경제 손실 표적과 가치 점수를 사용하지 않고, 자기 예측 상태에서 관측 가능한 누락 모수를 요청하는 recovery head만 분류 학습했다. 완료 후 두 모델의 encoder·구성기·수요 가중치가 정확히 같고, no_value의 value head가 변하지 않았으며 추론 선택에서도 사용되지 않음을 검사했다. [비교 기록](evidence/research-no-value-results.json)

no_value는 첫 iteration의 10번째 epoch를 선택했고, 최종 Dev에서 base 및 고정 질문 정책과 같은 손실 **44.3274**, 최종 채택 모수·근거 100%, 필요한 질문 336건·불필요한 질문 0건·잘못된 발주 진행 0건을 기록했다. 이 비교의 학습·평가는 L40S에서 171.91초였다. 경제 가치 없이 다음 행동을 분류하는 작은 head로도 현재 통제 조건의 결과를 달성했다.

표는 동일한 5개 완전 관측 기간에 대한 평균 총손실이다. 세 정책은 모든 336사례에서 같은 질문 집합을 시도했고, 가치 정책의 질문 순서만 35사례에서 달랐다. 현재 응답 모형은 질문 위치별로 고정된 난수 표본을 사용하므로 순서가 바뀌면 실제 응답 누락 표본도 달라진다. 모든 필수 질문을 시도하고 각 응답의 누락이 독립이며 비용이 순서에 무관하다는 이 환경의 가정 아래에서는 세 정책의 기대 총손실이 같다. 실제 질문 집합과 성공 시 발주량을 대조한 계산값은 10%에서 89.9262, 20%에서 134.2033이다. 표의 차이를 가치 학습의 일반적 열세나 우위로 확정하지 않는다. 경제 가치 head가 유리해지도록 평가 조건을 추가하지 않았다.

이 시점의 후속 검증 중 동일한 초기화·자료·head·학습 예산을 적용한 base/large 비교는 아래 기록처럼 완료했다. 수요분포의 적절성과 공개 문서 과제 성능 유지는 계속 검증해야 한다. 현재 통제 조건의 높은 정확도를 전체 연구 완료로 해석하지 않는다.

## 공개 문서 학습 주석 점검

같은 공개 Dev 258건을 재평가한 결과, 기존 core는 일부 근거·상태 지표가 개선됐지만 모든 문서 능력을 유지하지는 못했다. TAT-QA의 기존 엄격 정답 점수는 이전 모델 5/48, core 4/48이었다. 이 공개 과제 전체를 Newsvendor 성공 기준으로 바꾸지 않고, 구성 능력의 손실과 학습 결함을 진단하는 데 사용한다. [공개 문서 측정](evidence/research-documents-results.json)

원천 주석 대조에서 비율의 백분율 변환 누락, 이미 지원하는 평균·증감률 연산과 주석의 연결 누락, 표의 괄호 음수를 양수로 읽는 결함을 수정했다. 정답은 학습 표적의 일관성 검사에만 사용하고 관측 입력에는 넣지 않는다. 숫자 전체가 괄호로 표시된 표 cell의 부호와 근거 위치를 함께 보존하며, 문장 속 주석 번호나 대시를 음수·0으로 임의 해석하지 않는다. 현재 표현 가능한 산술 Train 51/61건, Dev 13/18건의 표적은 원천 답과 소수 둘째 자리까지 일치한다. 여러 단계의 식, 명시되지 않은 부호 변환, 관측할 수 없는 피연산자는 학습 표적에서 제외한다. [수정·검증 기록](evidence/research-arithmetic-checks.json)

기존 엄격 점수를 그대로 유지하고 산술·개수 응답에만 반올림을 허용하는 별도 진단 점수를 추가했다. 이는 TAT-QA 공식 평가 전체의 구현이 아니며 optimizer의 실제 계산 정밀도도 바꾸지 않는다. 저장된 이전 예측을 다시 채점했을 때 정답 수는 변하지 않았다. 채점 변경을 모델 성능 향상으로 보고하지 않는다.

첫 공정 비교 실행 `results/l40s-research-paired/base/42`는 주석 결함 발견 후 중단하고 원시 기록과 가중치를 보존했다. 수정 후 비교는 `l40s-research-paired-v2-{base,large}.json`에 같은 자료·학습 횟수·손실·입력 설정을 고정한다. 두 모델은 각각 고정 revision의 사전학습 encoder, 같은 seed의 기능 head, 동일한 학습된 수요 GRU에서 시작한다. 중단된 base만 이어서 학습하지 않는다.

두 실행이 끝난 뒤 이미 채택한 근거의 보존에서 정형 문서 제목을 요구하던 결함을 수정했다. 원문 hash·식·적용 범위가 유효하면 임의 제목의 기존 근거도 유지하며, 변경·충돌 근거 검사는 남긴다. 이전 base/large Dev 기록의 모든 메모리 항목 3,837개에서 후보 집합이 변하지 않는 것을 대조했으므로 위 비교 수치를 높여 다시 보고하지 않는다. 또한 여러 답이 모두 필요한 공개 주석을 단일 span의 대체 정답으로 학습하던 결함을 고쳤다. 해당 주석에는 지원하는 scale·action 손실만 남기며, 여러 값을 출력하는 새 기능을 추가하지 않았다. 전체 183개 테스트, 세 자료 버전의 출처 분리 검사와 30개 수치 smoke가 통과했다. [수정·검증 기록](evidence/research-core-fixes.json)

새 base와 동일한 `common.pt`에서 시작한 no_value도 133.22초에 학습·평가를 마쳤다. 최종 encoder·모수 구성기·수요 GRU가 base와 동일하고, 경제 가치 가중치는 초기값 그대로이며 추론에서 사용되지 않는 것을 직접 대조했다. recovery head는 자기 예측 상태에서 학습해 첫 iteration의 10번째 epoch를 선택했다. 최종 모수·근거 100%, 필요한 질문 336건·불필요한 질문 0건·잘못된 발주 진행 0건, 같은 완전 관측 기간의 손실 44.3274였다. 현재 조건은 큰 backbone이나 경제 가치 head의 필요성을 입증하지 않는다. [동일 구성기의 no_value 비교](evidence/research-paired-no-value-results.json)

별도로 같은 작은 GRU의 일별 보조 likelihood 비중 0.3과 1.0을 같은 초기화·출처별 cross-fitting·학습 횟수로 비교했다. seed 42에서 비중 1.0은 7일 관측 NLL과 비품절 CRPS·발주 손실을 낮췄지만 1일 NLL은 높였다. 현재 사용 중인 GRU와 비교하면 7일 NLL은 0.5441에서 0.4863, 비품절 CRPS는 2.7732에서 2.3743으로 낮아졌다. 다만 CRPS·발주 손실의 출처별 재표본화 구간은 0 차이를 포함한다. 이전 모수 상태·질문 비용을 고정하고 `F`만 교체한 진단에서는 총손실이 44.3274에서 42.2658로 낮아졌으나, 이것은 새로운 순차 정책 실행 결과가 아니다. seed 43·44를 추가 확인하는 실험은 첫 seed를 본 뒤 등록한 Dev 민감도 분석이며 Test를 사용하지 않는다. [수요 비교](evidence/research-demand-weight-comparison.json)

추가 seed 43·44도 완료했다. 세 seed를 모두 포함하면 일별 비중 1.0은 0.3보다 7일 평균 NLL 0.0262, 비품절 CRPS 0.9534를 낮췄다. 그러나 seed 44에서는 부족 비용 비율 3·9의 7일 발주 손실이 증가했고, 1일 평균 NLL은 0.0556 증가했다. 현재 사용 중인 단일 GRU와 비교한 세 seed의 평균 7일 CRPS는 0.0549, 부족 비용 비율 1·3의 발주 손실은 0.2854·0.3801 높았다. 유리한 seed만 골라 교체하지 않는다. 관측 기간 수에 seed 수를 곱하지 않고 출처 그룹별 불확실성을 기록했다. [모든 반복 실험의 비교](evidence/research-demand-weight-seeds.json)

작은 표본에 의존한 추가 조정보다 실제 Train 관측의 확대를 먼저 준비했다. 고정 revision의 FreshRetail 원본 Train parquet에서 기존 모든 매장·상품과 겹치지 않는 이력 512개를 관측값을 보기 전에 선택했다. 추가 이력끼리도 매장·상품을 공유하지 않는다. 수요 Train은 기존 30개 이력·25개 출처 그룹에서 542개 이력·537개 출처 그룹으로 늘며, 기존 Dev·Test는 그대로다. 첫 60일을 입력, 다음 7일을 결과로 나누고 품절 판매를 참수요로 표시하지 않는다. 새 버전은 `data/processed/core-retail-train-v1`이며 아직 개선된 모델의 증거가 아니다. 원본 출처는 [FreshRetailNet-50K](https://huggingface.co/datasets/Dingdong-Inc/FreshRetailNet-50K/tree/08c1fab7f9257bc73679d415d65d644165d351d4), 파일 hash·선택 과정은 [자료 기록](evidence/research-retail-expansion.json)에 보존한다.

문서 경로에는 원본 TAT-QA Train의 12,951개 주석을 별도 버전 `data/processed/core-tatqa-train-v1`으로 준비했다. 기존 Dev·Test에 연결되는 원문·정규화 문맥·유사 문맥을 제외하고 기존 행과 분할을 유지했다. 확장 Train의 산술 5,492건 중 현재 계산기가 표현하는 4,526건은 원천 답과 반올림 기준이 일치하고, 나머지는 해당 연산 손실을 적용하지 않는다. 숫자·단위·근거 학습 자료의 보강이며 범용 업무 절차나 도구 기능의 추가가 아니다. 원문 문맥 분리는 원래 기업이나 보고서 전체의 분리를 보장하지 않는다. 독립 검증은 [두 확장 자료의 검사](evidence/research-expansion-audit.json)에 기록했다.

확장 수요 자료의 L40S 학습은 seed 42·43·44 모두 종료됐다. 같은 seed의 작은 자료 학습과 비교하면 1일 NLL은 평균 0.1837 낮아졌지만, 7일 NLL은 0.3152, 비품절 CRPS는 0.9474 높아졌다. 세 seed 모두 7일 NLL·CRPS가 악화했다. 부족:잉여 비용 9:1의 발주 손실은 평균 1.7545 낮아졌으나 출처별 재표본화 구간은 0 차이를 포함했다. 현재 사용 중인 GRU와 비교해도 7일 NLL은 평균 0.2505 높았다. 후보 종류 선택뿐 아니라 각 종류의 모수 예측 손실도 악화했으므로 기존 수요 checkpoint를 유지한다. 자료량 외에 batch 크기와 CPU/GPU도 달라진 비교이며, 8개 Dev 출처와 30개 비품절 주간 구간의 결과를 일반적인 자료 확대 효과로 단정하지 않는다. [모든 seed의 비교와 종류별 진단](evidence/research-demand-expanded-results.json)

후속 수요 실험은 같은 작은 GRU·자료·초기값·likelihood를 유지하고, 모수 학습의 종료 시점을 Train 내부의 별도 출처 그룹으로 선택했다. 각 outer fold에서 보류한 출처는 그 모형의 내부 종료 시점 선택에도 들어가지 않는다. 종류 head에는 그렇게 얻은 outer 예측 손실을 주며, encoder가 고정된 종류 학습 단계에서는 상태를 한 번 계산해 재사용한다. seed 42·43·44를 모두 등록하고 완료했으며 유리한 seed만 선택하지 않는다. 수치·역전파·가중치 복원과 Dev 결과를 바꿔도 모수 적합 및 cross-fit 표적이 변하지 않는 검사를 통과했다. [실험 설정](../configs/l40s-demand-selected-v1.json), [등록 당시와 동일한 학습 코드](../scripts/train_demand_selected.py)

세 seed의 실행 시간은 각각 167.17·164.15·151.09초였다. 같은 확장 자료의 고정 epoch 학습보다 7일 NLL은 평균 0.2568 낮아졌지만, 비품절 CRPS는 0.2848 높아졌고 비용 비율 1·3·9의 발주 손실도 세 seed 모두 악화했다. seed 44는 NLL이 가장 낮으면서 CRPS·발주 손실은 가장 높았다. 사전에 지정한 후보 seed 42의 7일 NLL은 0.5618, CRPS는 3.0425로 현재 사용 중인 GRU의 0.5441·2.7732보다 높았다. **이 실험으로도 수요 모델을 교체하지 않는다.** 검열된 자료의 likelihood 하나로 발주 적절성을 확정하지 않으며, 모든 반복의 원시 측정과 출처별 불확실성을 남겼다. 추가 학습·평가는 1,697.86초에 완료했고 첫 language epoch를 선택했다. TAT-QA Dev 엄격 정답은 0/48에서 11/48, 별도 반올림 진단은 1/48에서 14/48, scale 정확도는 21/48에서 46/48로 올랐다. 기존 paired base의 95회 조회는 모두 읽을 문서가 남아 있지 않은 상태에서 발생했고, 25개 최종 상태에서 판매가격이 원가로 채택됐다. 원래 생성 경로에도 모수 역할 검증과 미열람 문서 확인을 적용했다. 이 검증은 잘못 연결한 값을 거부하며 정답 값을 채워 넣지는 않는다. 해당 학습 구성에는 원래 생성 Train 사례가 포함되지 않았다. 위 Dev 수치는 수정 전 코드의 측정이며, 다음의 재학습과 구분한다. 최종 Test는 아직 사용하지 않았다.

정책 후보 저장은 고정 encoder·구성기·수요 모델을 `policy-base.pt`에 한 번 보존하고, 각 후보의 학습된 head·optimizer·RNG와 정확한 base hash를 따로 저장한다. 같은 실행을 이어갈 때도 기존 base의 신원과 고정 가중치를 검증하고 파일을 덮어쓰지 않는다. 최종 `common.pt`와 `model.pt`는 기존의 완전한 가중치 형식을 유지한다. value/recovery 복원·재학습, 원가 역할 및 반복 조회 회귀 검사를 포함해 전체 185개 테스트, 세 자료 버전의 출처 분리, 확장 자료의 보호 원문 중복 검사, 30개 수치 smoke를 통과했다. [수정·검증 기록](evidence/research-generated-core-fixes.json)

## 원래 생성 Train과 매니저 응답 상태의 재학습

원래 생성 경로와 판매 이력이 연결된 경로에 같은 모수 메모리·응답 반영·행동 허용 검사를 적용했다. Train 360건·72개 family와 Dev 60건·12개 family를 기존 분할 그대로 복구하고, 실제 환경 응답 후 상태까지 포함해 각각 740개·120개의 구성 학습 사례를 만들었다. 응답 가능성 `rho/partial`이나 숨겨진 참모수는 입력·상태 주석·행동 허용 조건에 사용하지 않는다. 환경은 선택된 질문에 실제로 응답할 때만 응답 확률을 사용한다. [누출·회귀 검사](evidence/research-replay-checks.json)

추론 코드를 먼저 고정하고 같은 부모 checkpoint를 평가하면 생성 Dev 평균 총손실은 526.9859, 보류 51건, 잘못된 발주 진행 0건이었다. 그 다음 동일 코드에서 문서 encoder·구성기를 추가 학습했다. 생성 자료와 retail의 손실 단위가 다르므로 정책 선택은 각 자료의 `총손실 / 공개 보류 비용` 평균에 동일 가중치를 주고, 원래 단위의 총손실도 따로 보존했다. [재학습 전 대조군](evidence/research-generated-replay-code-results.json)

L40S base 실행은 1,413.65초에 종료됐다. 원래 생성 Dev의 학습 정책은 평균 총손실 **147.6813**, 보류 11건, 잘못된 발주 진행 0건, 최종 모수·근거 정확도 100%였다. 관측상 누락된 모수 요청은 21건이고 이미 해결된 모수의 재질문은 0건이었다. 이는 원래 minimax 과제에서 모든 요청이 경제적으로 필수였다는 뜻은 아니다. 고정 질문 정책은 181.6758이었다. 보호된 Test의 240.35 기준을 달성했다고 해석하지 않는다. 생성 Dev의 독립 출처는 여전히 12개다. 모수 정확도는 당시 관측으로 확인할 수 있는 값과 누락 상태의 일치를 뜻하며, 미관측 참모수를 모두 알아냈다는 뜻이 아니다. [전체 결과](evidence/research-replay-results.json)

같은 실행에서 TAT-QA 엄격 정답은 16/48, 반올림 진단은 22/48, scale은 46/48이었다. ContractNLI 상태 정답은 44/72로 앞선 문서 추가 학습의 45/72보다 한 건 줄었다. Retail의 최종 모수·근거, 질문, 발주 손실은 기존 44.3274 결과를 유지했다. 두 번의 새 행동 가치 학습에서는 사전에 정한 Dev 선택 기준을 개선한 후보가 없어 상속한 value head를 유지했다. 따라서 생성 Dev 개선은 이번 구성기 재학습 이후의 결과이며, 새 가치 학습 단계의 추가 효과는 입증하지 못했다.

동일한 `common.pt`와 Train/Dev에서 시작한 `no_value`의 정책 학습·평가는 255.17초에 종료됐다. 생성 Dev 손실은 181.6758로 고정 질문 정책과 같았고, 가치 정책과의 출처별 평균 차이는 −33.9945였다. 독립 family 12개를 재표본화한 95% 구간은 [−66.0992, −5.2774]였다. Retail에서는 세 정책 모두 44.3274를 유지했다. Encoder·구성기·GRU가 동일하고 no_value의 value 가중치가 변경되거나 사용되지 않았음을 대조했다. 이 비교는 상속한 가치 head까지 포함하므로 새 가치 학습 단계의 효과와 분리해서 해석한다. [동일 구성기 비교](evidence/research-replay-no-value-results.json)

## 주간 품절 점수의 관측 모형 점검

기존 수요 모형은 하루라도 품절이면 7일 합계 판매를 수요의 하한으로 사용한다. 하한 자체는 유효하지만, 합계의 survival 점수를 날짜별로 검열된 관측의 정확한 likelihood라고 일반화할 수는 없다. 참 일평균 1인 독립 지수 수요를 매일 재고 1로 검열하는 수치 예제에서 날짜별 likelihood는 약 1을 복원했고, 7일 합계 하한 방식은 약 1.46을 추정했다. 일별 보조 손실을 더해도 약 1.28이었다. 세 seed와 1·2·7일 조건의 측정 및 [실행 코드](evidence/scripts/aggregate-censoring-smoke.py)를 보존한다. 이는 가정의 수치 점검이며 실제 FreshRetail에서의 편향 크기나 새 수요 모형의 개선을 입증하지 않는다. [수치 결과](evidence/research-aggregate-censoring-check.json)

후속으로 총수요의 세 분포 head를 유지하면서 날짜별 정확 관측·품절 하한을 함께 다루는 관측 모형을 구현했다. 기존 1일 head를 재사용하며 새 파라미터는 추가하지 않았다. 날짜별 활성 여부·균등 배분·비정보적 일별 검열을 가정한 likelihood이고 실제 재고 과정을 식별했다고 주장하지 않는다. 수치·기울기 검사는 통과했지만 세 seed의 Dev에서 일관된 예측 개선을 얻지 못했다. 사전 후보 seed 42의 7일 CRPS는 5.0301로 기존 2.7732보다 높았고 네 채택 조건을 모두 실패했다. 기존 GRU를 유지하며 이 후보에는 Test를 사용하지 않았다. [가정·구현·전체 결과](demand-observations.md)

## 고정 Test 평가

모델·코드·자료 hash와 정책을 [평가 계획](../configs/research-core-test-v1.json)에 먼저 고정한 뒤, 학습 없이 L40S에서 158.27초 동안 평가했다. 선택된 replay-v1 base와 no_value는 문서 encoder·모수 구성기·GRU의 가중치가 정확히 같다. 원래 생성 Test는 과거 도구 실험에서 이미 사용된 120건·24개 family이며 새 blind Test로 표시하지 않는다. 이번 결과로 새 가중치나 설정을 선택하지 않았다. [전체 Test 결과](evidence/research-core-test-results.json)

가치 정책의 모수 상태 정확도는 92.50%, 네 모수를 모두 올바르게 구성한 비율은 88.33%다. 모수 지표는 당시 관측으로 검증할 수 있는 값·누락 상태 기준이며 미관측 참모수를 알아냈다는 뜻이 아니다. 누락된 모수 요청 69건, 이미 해결된 항목의 재질문 0건이다. 가치 정책과 no_value의 출처별 평균 총손실 차이는 −19.6105, family 재표본화 95% 구간은 [−35.5496, −5.0222]였다. 상속한 value head를 포함한 비교이며 새 가치 학습 단계의 효과나 실제 조직의 효과로 해석하지 않는다. **생성 손실 기준에는 3.2774만큼 미달했다.**

판매 이력에 연결한 Test는 504사례·10개 출처 그룹, 고유 판매 기간 72개다. 세 정책 모두 최종 모수·근거 100%, 필요한 요청 504건·불필요한 요청 0건, 요청 후 회복 504건, 잘못된 발주 진행 0건이었다. 정확한 평균 총손실은 **9개 완전 관측 기간 × 7개 통제 조건**에서 105.9101로 같았다. Dev의 44.3274와는 서로 다른 관측 기간의 값이므로 성능 변화량으로 빼지 않는다. 이 조건에서 경제 가치 head의 추가 이점은 확인되지 않았다.

전체 rolling 판매 Test는 1일·7일 각각 396개 예측 구간이다. 완전 관측은 204개·39개이며, 이 구간에서 CRPS는 0.3773·5.6028, 80% 예측구간 적중률은 77.94%·28.21%였다. 겹치는 기간과 품절 선택이 있으므로 이 비율만으로 전체 잠재 수요의 calibration을 확정하지 않는다. 적절성을 뒷받침하는 결과도 아니다. 관측 하한을 사용한 전체 적중률의 식별 범위와 원시 `F`·발주량을 Test 기록에 보존한다.

정확한 평가 소스와 계획은 [고정 archive](evidence/artifacts/core-test-v1-source.tar.gz)에 있다. 이후 수요 비교 실행기에 CPU 대조 장치를 명시했으므로 당시 registration을 재실행하려면 해당 archive를 기준으로 한다. checkpoint·확장 자료의 공개 배포는 아래 제한 그대로다.

## 행동 head의 자기 예측 상태 전달

Train 자기 상태 928개의 입력을 감사해, 정렬한 상태 JSON이 128-token prefix에서 잘리며 일부 모수 값·유형·발주량이 사라지는 문제를 확인했다. 자기 예측 상태와 공개 비용·예산의 94개 수치 입력을 행동 head에 연결하는 선택 경로를 구현했다. 추가 파라미터는 24,064개다. 숨긴 참모수나 응답 확률을 입력하지 않는다.

같은 부모·Train/Dev·seed 42·최대 학습 예산으로 기존 입력, 수치 입력, 수치 입력의 `no_value`를 L40S에서 비교했다. 두 가치 조건은 새 후보를 채택하지 않아 생성 Dev 147.6813·Retail Dev 44.3274를 유지했고, `no_value`는 181.6758·44.3274였다. 입력 가시성의 개선으로 정책 효과를 입증했다고 해석하지 않는다. Test를 다시 평가하거나 선택에 사용하지 않았고 기존 선택 모델을 유지한다.

수치 벡터 생성 단계에서는 감사한 모든 변경을 구분했으나 BF16 변환 후에는 작은 값 변경 일부가 같은 값이 됐다. 정밀도와 GPU 추론·cached 학습의 수치 일치는 별도 검증이 필요하다. 전체 테스트 213개·Ruff·세 자료 버전의 출처 검사·30개 수치 smoke와 불리한 후보 측정을 함께 보존했다. [결함·수정·학습 결과·정밀도 한계](policy-state.md)

후속 실제 L40S 검사에서는 Train 928개 상태의 수치 입력이 모두 BF16으로 반올림됐고, 학습 후보의 한 상태에서 FP32 cached 학습과 추론이 다른 행동을 골랐다. 작은 가치·회복 head만 FP32로 계산하는 선택 경로를 추가해, 같은 928개 상태에서 입력과 두 계산 경로의 출력 일치를 확인했다. Encoder·상태 결합 표현은 정확히 같았고 전체 217개 테스트를 통과했다. 세 조건의 후속 Dev 손실은 각각 이전과 같아 정책 개선은 입증하지 못했다. Test는 다시 사용하지 않았고 기존 선택 모델을 유지한다. [정밀도 수정·실제 GPU 검증·최종 비교](action-precision.md)

후속 응답 표적 감사에서는 두 학습 반복이 같은 고정 Train 응답을 재사용하며, Train의 추가 잡음 0.1과 기본 Dev의 잡음 0이 다름을 확인했다. 추가 잡음 정렬과 행동별 8회 응답 평균 조건을 별도로 학습했다. Train에서만 응답을 재표집하고 각 응답·후속 경로·평균 표적을 기록한다. 두 조건 모두 초기 가중치를 넘지 못해 생성 Dev 147.6813, Retail 44.3274를 유지했다. 226개 테스트·출처 분리·30개 수치 smoke와 부정적인 결과를 보존했으며, Test는 다시 실행하지 않았다. [학습 표적 진단과 완료한 비교](response-supervision.md)

## 날짜별 수요 배분의 Train 추정

완전 관측 Train의 날짜별 판매 비중이 기존 균등 simplex 가정보다 집중됨을 확인하고, 각 출처 분할 안에서 대칭 Dirichlet 농도를 추정하는 선택 옵션을 구현했다. 신경망 파라미터는 추가하지 않았다. L40S의 동일 예산 세 seed에서 농도 4가 선택됐으며 완전 관측 Dev의 7일 CRPS는 1.2686·1.4107·1.5242로 기존 GRU의 2.7732보다 낮았다. 비용 비율 1·3·9의 발주 손실도 모두 줄었다. 다만 정확한 주간 지표는 겹치는 30개 기간·출처 6개에 한정한다.

1일 CRPS와 품절을 포함한 전체 관측 NLL은 세 seed 모두 악화됐다. 고정 후보 seed 42의 일별 CRPS 악화 10.3783%가 사전 한도 10%를 넘어서 기존 GRU를 유지했다. 통합 rollout이나 Test를 추가 실행하지 않았다. 테스트 246개·출처 분리·수치 smoke를 통과했으며, Train 진단 원본·세 작은 GRU 가중치·Dev 예측·대조군 재현 검사까지 공개했다. 마지막 CPU 대조에서 thread 조건 차이를 수정한 기록도 포함한다. [가정·수정·제한과 전체 결과](demand-concentration.md)

## 공개 재현 범위

로컬 `results/`의 자료 검증·수요 보고서 여섯 개를 변경 없이 `docs/evidence/`로 복사하고 링크를 수정했다. [원본과 공개 사본의 hash](evidence/research-published-records.json)를 기록한다. 보고서 내부의 checkpoint·원시 측정 경로는 로컬 경로이며 공개 다운로드를 의미하지 않는다.

공개 snapshot과 기존 연구 작업 폴더는 retail 요청 문구와 관련 manifest·입력 hash가 다르다. 50개 판매 이력, 정답, family와 분할은 모두 같고 다른 문서 과제도 같다. 기존 checkpoint의 데이터 신원 검사는 이 차이를 거부하며 이를 우회하지 않는다. [대조 기록](evidence/research-snapshot-audit.json)

새 clone용 학습 경로는 공개 snapshot에서 GRU를 새로 학습하고, 고정 revision의 ModernBERT와 새로운 기능 head에 연결한다. README에는 현재 연구 경로를 두고 native-v3·Qwen·`familyProbabilities` 설명은 [과거 실행 기록](native-history.md)으로 옮겼다. CI에는 snapshot 복원·출처 검사와 연구 입력의 `check` 단계를 추가했다. 이후 선택한 ModernBERT 전체 추론 가중치를 [별도 묶음](model-bundle.md)으로 공개했으며, 확장 Train 전체와 과거 optimizer 배포는 아직 제공하지 않는다.

별도 source export에서 공개 snapshot 복원, 연구 자료 검사, CPU GRU의 전체 cross-fitting 학습(205.78초), 해당 GRU를 사전학습 ModernBERT에 연결한 forward·backward·optimizer step을 확인했다. Encoder gradient와 실제 가중치 변경을 대조했다. 이 검증은 설치된 Python 환경과 공개 사전학습 모델 cache를 재사용했으며 과거 연구 checkpoint는 요구하지 않았다. 완전한 cold-start 문서·정책 재학습을 반복한 것은 아니다. 같은 소스의 테스트 193개, Ruff lint·format, 30개 수치 smoke가 통과했다. [재현 경로 검증](evidence/research-reproduction-checks.json)
