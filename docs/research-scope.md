# Newsvendor 연구의 주 범위

2026-10-09 사용자 지시에 따라 주 모델과 평가를 아래 범위에 집중한다. 기존 ABCD의 결과·실패 기록·가중치·원시 측정은 보존한다. 이 문서는 연구 범위와 현재 구현의 차이를 기록하며 새 성능 달성을 선언하지 않는다.

연구 질문은 **작은 학습 모델이 문서와 판매 이력에서 발주에 필요한 입력을 구성하고, 근거가 부족하거나 매니저의 선택이 필요하면 적절한 정보를 요청하여, 최종 발주 손실과 질문 부담을 줄일 수 있는가**이다.

## 주 모델의 역할

1. ModernBERT와 모수 구성·상태 head가 원가 `c`, 판매가 `p`, 잔존가치 `v`, 부족 비용 `b` 및 적용 조건을 근거와 함께 구성한다. 단위·기간·SKU를 보존하고 누락·충돌·미확정 상태를 표시한다. 계약의 사실과 매니저가 정해야 하는 선호를 구분한다.
2. 작은 수요 encoder와 분포 head가 판매·품절·달력 이력과 예측 기간으로 수요분포 `F`를 추정한다. 분포를 확정된 사실로 표시하지 않는다.
3. 정보 요청 head가 추가 근거 조회, 특정 모수에 대한 매니저 질문, 공통 optimizer에 전달, 보류 가운데 선택한다. 질문은 대상 모수·이유·선택지로 표현한다. 최종 발주량은 공통 optimizer가 계산한다.
4. 응답을 받으면 근거와 모수 상태를 갱신하고 같은 경로에서 다시 판단한다. 행동 가치의 학습 표적은 자기 예측 상태에서 실제 수행한 Train rollout의 발주 손실과 요청 비용이다.

예를 들어 반품 시 회수 가능한 금액을 계약에서 찾으면 `v`의 근거로 사용한다. 찾지 못하면 그 항목을 질문한다. 부족 비용이 매니저의 정책 선택인 경우에는 문서의 임의 숫자로 대체하지 않고 선택을 요청한다. 응답 이후 수정한 입력이 실제 발주량에 반영되는지 평가한다.

기본 비교군은 '근거가 부족하면 해당 항목을 질문'하는 고정 정책이다. 학습 정책의 추가 가치는 같은 모수 구성기·자료·응답 조건에서 불필요한 질문을 줄이거나 중요한 정보를 먼저 확보하여 최종 손실을 낮추는지로 판단한다.

## 기존 수정의 위치

| 구성 | 주 연구에서의 역할 |
| --- | --- |
| 필드 역할·자료형·조립·단위 검증 | Newsvendor 모수가 올바르게 optimizer에 전달되도록 유지 |
| 공유 추출·근거·상태 복사 | 질문 응답 이후 모수와 출처를 함께 갱신하는 데 사용 |
| 문서 검색 | 발주 모수의 근거를 찾는 범위에서 사용 |
| ABCD 업무 절차·진행 단계·도구 후보 재평가·대화 이력 모듈 | 보조 도구 실험으로 보존; 주 모델의 필수 구성이나 성공 기준으로 삼지 않음 |
| 자기 예측 상태의 행동 가치·회복 | 소수의 발주 정보 요청 행동에 집중 |

ABCD 도구·전체 인자·호출 precision 각각 90%라는 이전 목표와 미달 결과는 보조 실험 기록에 남긴다. 이를 원래 연구의 달성 여부와 동일시하지 않는다.

## 주 평가

| 평가 | 측정할 내용 |
| --- | --- |
| 모수·근거 | 실제 채택한 값, 단위·기간·SKU, 원문 위치, 사실/추정/선호, 누락·충돌 상태 |
| 수요분포 | 비검열·검열 관측에 맞는 예측 손실, calibration, 구간 coverage, 선택한 종류·모수 |
| 매니저 요청 | 필요한 질문의 누락, 이미 해결된 항목의 중복·불필요한 질문, 요청 비용·횟수 |
| 응답 후 회복 | 자기 예측 상태의 오류를 응답으로 고치는지, 근거와 상태가 일관되게 갱신되는지 |
| 발주 | 모델이 실제 전달한 입력으로 계산한 발주량의 손실, 근거 없이 진행한 비율, 보류율 |
| 크기·실행 비용 | 같은 입력·자료·head를 사용하는 base/large의 지연·메모리와 성능; 가치 학습 제거 비교 |

기존 생성 Test 120건의 평균 총손실 **240.35 미만**은 원래 분할과 손실 정의에 대한 비교 기준으로 보존한다. 새로 연결한 수요분포 실험의 손실을 기존 수치와 직접 혼합하지 않는다. 새 지표의 완료 수치를 임의로 만들어 충족했다고 선언하지 않는다. 모델 선택은 Train·Dev로 수행하고, 기존 Test를 새 blind Test로 표현하지 않는다.

## 확인된 구현 차이와 다음 우선순위

2026-10-09 범위 재점검 당시:

- `ResearchRouter.construct`는 언어 head로 모수를 구성한 뒤 `construction.demand`를 호출한다. 이 생성 시나리오 경로의 `F`는 경험적 관측, 허용 후보 또는 응답으로 얻은 예측에서 온다. 학습한 수요 encoder의 출력은 이 rollout에 연결되어 있지 않다.
- `structured_train.infer(linked=True)`에는 학습한 수요분포와 추출 모수를 `economic_state`에서 결합해 optimizer를 호출하는 별도 추론 경로가 있다. 이 존재만으로 순차 질문·회복·최종 손실까지 통합 검증됐다고 할 수 없다.
- ABCD 대화 controller는 ABCD 입력 조건에서 동작한다. 이 실험의 정확도 향상을 Newsvendor의 발주 개선으로 대체해 보고하지 않는다.

우선 실제 관측 가능한 판매 이력·기간·SKU 계약을 명시하고, **학습한 `F`와 문서 모수 → 정보 요청과 갱신 → 공통 optimizer → 실제 출력 발주량의 평가**를 같은 경로로 연결한다. 이 경로를 고정 질문 정책과 비교한 뒤 모델 크기와 가치 학습의 기여를 판단한다.

이후 `structured_forecast.py`와 `structured_retail.py`를 추가하여 명시적인 `task.forecast`가 있는 입력을 기존 `ResearchRouter`의 질문·갱신 경로에 연결했다. 학습한 GRU의 `F`를 실제 optimizer에 전달하고 SKU·기간·단위·과거 관측 경계를 검사한다. 분포를 주석된 참분포와 완전 일치시키는 기존 생성 채점을 재사용하지 않고, 실제 출력 발주량을 관측 판매에 대해 별도로 채점한다. 기존 생성 입력과 결과는 유지한다.

L40S 실행 `results/l40s-research-v2/base/42`는 기존 가중치에서 ABCD 전용 모듈의 625,252개 파라미터를 제외한 동일한 core 가중치로 시작했다. 문서 encoder까지 모수·근거·상태를 미세조정하고, 모수 구성기를 고정한 뒤 자기 예측 상태의 경제 가치 head를 학습했다. 학습한 수요 GRU는 부모 checkpoint에서 가져오며, 결합 자료로 학습하지 않은 언어 context를 GRU에 임의로 더하지 않는다. 이후 v3·v4는 같은 encoder·GRU를 유지하고 상태 갱신 결함을 수정한 뒤 정책만 다시 비교했다. 세 실행은 모두 종료됐으며 Test는 사용하지 않았다.

이 통제 결합 자료는 Train 1,260/Dev 336사례이며 판매 source family는 25/8개로 분리된다. 충분한 근거, c/p/v/b 각각의 누락, v 충돌, v·b 동시 누락이라는 일곱 조건을 각 관측 기간에 적용한다. 사례 수를 독립 판매 기간 수로 해석하지 않는다. 품절 없는 7일 관측은 Train 22/Dev 5기간뿐이다. 정확한 경제 가치 학습·손실 비교는 이 관측 범위에서 수행하고, 품절 기간의 손실은 하한으로 표시한다. 전체 관측은 분포의 검열 likelihood 및 모수·질문 평가에 남긴다. 구현·수치·누출 검증은 [검증 기록](evidence/research-path-checks.json)에 보존한다.

최초 실행 `results/l40s-research/base/42`는 학습의 첫 optimizer step 전에 중단됐다. 도구 모듈이 없는 구성에서 조회 플래그가 `None`이 되는 오류를 수정했다. 초기 측정에는 `units per pack`을 금액으로 해석하여 올바른 나눗셈을 거부하고 잘못된 원가를 주석하는 결함도 있었다. 이 실행의 원시 측정은 보존하되 성능 근거에서는 제외한다. 단위 파서와 독립 수치 주석 검사를 수정했으며, c/p/v/b의 응답은 해당 문서만 갱신하도록 검증했다. 공시된 보류·질문 비용은 정확히 계산하고 나머지 행동 후 손실만 학습한다.

서로 연결되지 않은 공개 문서와 판매 SKU에 임의의 연결 표적을 만들지 않는다. 생성된 통합 사례는 통제 진단으로 표시하고 실제 조직 업무의 효과성 근거와 구분한다. 모델 revision·source hash·source/family 분할·원시 측정을 유지한다.

## 상태 갱신 수정과 확인된 결과

v3는 받은 수치 응답을 현재의 동일 SKU·기간·최신 근거와 대조한 뒤 보존하고, 이미 읽은 문서를 반복 조회하지 않도록 수정했다. v4는 다른 항목의 답을 받은 뒤 기존 값을 다시 추출하지 못하는 경우에도, 이전에 모델이 채택한 값과 원문 hash·식·적용 범위가 그대로 유효하면 보존한다. 변경된 문서, 새 버전, 충돌, 다른 SKU·기간에는 이전 값을 복사하지 않는다. 초기 추출 결과를 정답으로 채우는 규칙은 추가하지 않았다. 모델의 원시 예측과 최종 채택 상태는 별도로 기록한다.

| 동일 Dev의 순차 실행 | 학습 정책 평균 총손실 | 고정 질문 정책 평균 총손실 | 학습 정책의 불필요한 질문 | 잘못된 발주 진행 |
| --- | ---: | ---: | ---: | ---: |
| v2 | 66.3952 | 44.8988 | 0 | 1 |
| v3 | 44.8008 | 44.8008 | 5 | 0 |
| v4 | 44.3274 | 44.3274 | 0 | 0 |

모수·질문 지표의 분모는 Dev 336사례다. 총손실은 완전히 관측된 **5개 판매 기간 × 7개 통제 조건**에 한정한다. v4의 최종 채택 모수·근거 정확도는 100%이고, 원시 신경망 모수 예측 정확도는 99.628%다. 질문 336건은 모두 필요한 질문으로 채점됐다. v3·v4의 가치 head 재학습 후보는 초기 모델보다 Dev 손실을 낮추지 못해 채택되지 않았다. **현재 비교는 행동 가치 학습의 추가 이점을 입증하지 못했다.** 원시 기록·가중치·시간·출처는 [v3](evidence/research-v3-results.json), [v4](evidence/research-v4-results.json)에 연결되어 있다.

전체 rolling 판매 Dev를 따로 점검하면 8개 source family에서 1일/7일 각각 264개 예측 구간이 나온다. 완전 관측은 각각 177개/30개이며, 이 구간에서 80% 예측구간 적중률은 77.40%/33.33%였다. 이웃 구간이 겹치고 품절 없는 기간만의 조건부 지표이므로 독립 표본 수나 전체 수요의 calibration으로 해석하지 않는다. Train의 source-group cross-fitting으로 종류를 선택하고 검열 likelihood로 모수를 적합한 단순 기준선도 비교했다. 기준선의 관측 NLL은 GRU보다 1일 0.0861, 7일 0.0898 낮았지만, 품절 없는 7일 구간의 CRPS와 발주 손실은 GRU가 더 낮았다. 한 지표만으로 수요 경로의 우위를 선언하지 않는다. 원시 측정은 `results/research-checks/demand-dev-v3`와 `demand-baseline`에 보존했다.

품절 구간도 버리지 않고 적중률의 식별 가능한 범위를 계산했다. 관측 판매 하한이 예측구간 상단을 이미 넘었으면 반드시 미적중이고, 그렇지 않은 품절 구간은 적중 여부를 알 수 없다. 현재 GRU의 전체 관측 적중률 범위는 1일 51.89–81.06%, 7일 3.79–92.05%다. 7일의 비품절 적중률 33.33%만으로 전체 calibration을 확정할 수 없으며, 이 넓은 범위도 적절성을 입증하지 않는다. source family 단위 재표본화와 실제 optimizer에 전달된 이산 `F`의 구간 질량을 함께 기록했다. [품절 포함 식별 범위](../results/research-checks/calibration-bounds/report.json)

순차 추론은 `structured_train.infer(..., linked=True, state=previous["constructedState"])`에 이전 채택 상태를 전달한다. 내부 rollout도 동일한 근거 검증을 거쳐 상태를 전달한다. 반환한 `fields`는 실제 optimizer 입력이며, `constructedState.rawFields`는 보존 전 모델 예측이다.

## 경제 가치 학습 제거 비교

`results/l40s-research-v4/no_value/42`는 base v4와 같은 초기 checkpoint·Train/Dev·encoder·모수 구성기·수요 GRU에서 시작했다. 경제 손실 표적과 가치 점수를 사용하지 않고, 자기 예측 상태에서 관측 가능한 누락 모수를 요청하는 recovery head만 분류 학습했다. 완료 후 두 모델의 encoder·구성기·수요 가중치가 정확히 같고, no_value의 value head가 변하지 않았으며 추론 선택에서도 사용되지 않음을 검사했다. [비교 기록](evidence/research-no-value-results.json)

no_value는 첫 iteration의 10번째 epoch를 선택했고, 최종 Dev에서 base 및 고정 질문 정책과 같은 손실 **44.3274**, 최종 채택 모수·근거 100%, 필요한 질문 336건·불필요한 질문 0건·잘못된 발주 진행 0건을 기록했다. 이 비교의 학습·평가는 L40S에서 171.91초였다. 경제 가치 없이 다음 행동을 분류하는 작은 head로도 현재 통제 조건의 결과를 달성했다.

| 10% | 87.9986 | 73.1450 | 73.1450 |
| 20% | 171.1302 | 145.3231 | 145.3231 |

표는 동일한 5개 완전 관측 기간에 대한 평균 총손실이다. 세 정책은 모든 336사례에서 같은 질문 집합을 시도했고, 가치 정책의 질문 순서만 35사례에서 달랐다. 현재 응답 모형은 질문 위치별로 고정된 난수 표본을 사용하므로 순서가 바뀌면 실제 응답 누락 표본도 달라진다. 모든 필수 질문을 시도하고 각 응답의 누락이 독립이며 비용이 순서에 무관하다는 이 환경의 가정 아래에서는 세 정책의 기대 총손실이 같다. 실제 질문 집합과 성공 시 발주량을 대조한 계산값은 10%에서 89.9262, 20%에서 134.2033이다. 표의 차이를 가치 학습의 일반적 열세나 우위로 확정하지 않는다. 경제 가치 head가 유리해지도록 평가 조건을 추가하지 않았다.

남은 주 검증은 수요분포의 적절성, 현재 core의 공개 문서 과제 성능 유지, 동일한 초기화·자료·head·학습 예산을 적용한 base/large 비교다. 현재 통제 조건의 높은 정확도를 전체 연구 완료로 해석하지 않는다.

## 공개 문서 학습 주석 점검

같은 공개 Dev 258건을 재평가한 결과, 기존 core는 일부 근거·상태 지표가 개선됐지만 모든 문서 능력을 유지하지는 못했다. TAT-QA의 기존 엄격 정답 점수는 이전 모델 5/48, core 4/48이었다. 이 공개 과제 전체를 Newsvendor 성공 기준으로 바꾸지 않고, 구성 능력의 손실과 학습 결함을 진단하는 데 사용한다. [공개 문서 측정](evidence/research-documents-results.json)

원천 주석 대조에서 비율의 백분율 변환 누락, 이미 지원하는 평균·증감률 연산과 주석의 연결 누락, 표의 괄호 음수를 양수로 읽는 결함을 수정했다. 정답은 학습 표적의 일관성 검사에만 사용하고 관측 입력에는 넣지 않는다. 숫자 전체가 괄호로 표시된 표 cell의 부호와 근거 위치를 함께 보존하며, 문장 속 주석 번호나 대시를 음수·0으로 임의 해석하지 않는다. 현재 표현 가능한 산술 Train 51/61건, Dev 13/18건의 표적은 원천 답과 소수 둘째 자리까지 일치한다. 여러 단계의 식, 명시되지 않은 부호 변환, 관측할 수 없는 피연산자는 학습 표적에서 제외한다. [수정·검증 기록](evidence/research-arithmetic-checks.json)

기존 엄격 점수를 그대로 유지하고 산술·개수 응답에만 반올림을 허용하는 별도 진단 점수를 추가했다. 이는 TAT-QA 공식 평가 전체의 구현이 아니며 optimizer의 실제 계산 정밀도도 바꾸지 않는다. 저장된 이전 예측을 다시 채점했을 때 정답 수는 변하지 않았다. 채점 변경을 모델 성능 향상으로 보고하지 않는다.

첫 공정 비교 실행 `results/l40s-research-paired/base/42`는 주석 결함 발견 후 중단하고 원시 기록과 가중치를 보존했다. 수정 후 비교는 `l40s-research-paired-v2-{base,large}.json`에 같은 자료·학습 횟수·손실·입력 설정을 고정한다. 두 모델은 각각 고정 revision의 사전학습 encoder, 같은 seed의 기능 head, 동일한 학습된 수요 GRU에서 시작한다. 중단된 base만 이어서 학습하지 않는다.

수정 후 base·large 실행이 모두 종료됐다. 실제 초기 기능 head·GRU hash, Train/Dev 사례 목록, 학습 횟수와 손실 설정이 같으며 두 모델 모두 3번째 language epoch를 선택했다. [공정 비교 결과](evidence/research-paired-results.json)

지연은 같은 상태 캐시 설정에서 기록한 실제 순차 실행 시간이며 모델 로딩과 인간의 대기 시간은 포함하지 않는다. 메모리는 학습을 포함한 최대 할당이다. 모수·질문은 336사례, 정확한 총손실은 5개 고유 판매 기간 × 7개 통제 조건이다. base의 불필요한 질문 3건은 완전 관측 경제 평가의 35사례 밖에서 발생하여 해당 평균 총손실에는 반영되지 않는다. large는 일부 공개 문서 근거 지표를 높였지만 TAT-QA는 두 모델 모두 엄격 0/48, 반올림 진단 1/48이었다. 크기 증가만으로 숫자·단위 추출 문제가 해결되지 않았으므로 base의 자료·구성 능력을 먼저 개선한다. 기존 v4를 자동 교체하거나 전체 연구의 성공을 선언하지 않는다.

두 실행이 끝난 뒤 이미 채택한 근거의 보존에서 정형 문서 제목을 요구하던 결함을 수정했다. 원문 hash·식·적용 범위가 유효하면 임의 제목의 기존 근거도 유지하며, 변경·충돌 근거 검사는 남긴다. 이전 base/large Dev 기록의 모든 메모리 항목 3,837개에서 후보 집합이 변하지 않는 것을 대조했으므로 위 비교 수치를 높여 다시 보고하지 않는다. 또한 여러 답이 모두 필요한 공개 주석을 단일 span의 대체 정답으로 학습하던 결함을 고쳤다. 해당 주석에는 지원하는 scale·action 손실만 남기며, 여러 값을 출력하는 새 기능을 추가하지 않았다. 전체 183개 테스트, 세 자료 버전의 출처 분리 검사와 30개 수치 smoke가 통과했다. [수정·검증 기록](evidence/research-core-fixes.json)

새 base와 동일한 `common.pt`에서 시작한 no_value도 133.22초에 학습·평가를 마쳤다. 최종 encoder·모수 구성기·수요 GRU가 base와 동일하고, 경제 가치 가중치는 초기값 그대로이며 추론에서 사용되지 않는 것을 직접 대조했다. recovery head는 자기 예측 상태에서 학습해 첫 iteration의 10번째 epoch를 선택했다. 최종 모수·근거 100%, 필요한 질문 336건·불필요한 질문 0건·잘못된 발주 진행 0건, 같은 완전 관측 기간의 손실 44.3274였다. 현재 조건은 큰 backbone이나 경제 가치 head의 필요성을 입증하지 않는다. [동일 구성기의 no_value 비교](evidence/research-paired-no-value-results.json)

별도로 같은 작은 GRU의 일별 보조 likelihood 비중 0.3과 1.0을 같은 초기화·출처별 cross-fitting·학습 횟수로 비교했다. seed 42에서 비중 1.0은 7일 관측 NLL과 비품절 CRPS·발주 손실을 낮췄지만 1일 NLL은 높였다. 현재 사용 중인 GRU와 비교하면 7일 NLL은 0.5441에서 0.4863, 비품절 CRPS는 2.7732에서 2.3743으로 낮아졌다. 다만 CRPS·발주 손실의 출처별 재표본화 구간은 0 차이를 포함한다. 이전 모수 상태·질문 비용을 고정하고 `F`만 교체한 진단에서는 총손실이 44.3274에서 42.2658로 낮아졌으나, 이것은 새로운 순차 정책 실행 결과가 아니다. seed 43·44를 추가 확인하는 실험은 첫 seed를 본 뒤 등록한 Dev 민감도 분석이며 Test를 사용하지 않는다. [수요 비교](../results/research-checks/demand-weight-study/comparison.json)

추가 seed 43·44도 완료했다. 세 seed를 모두 포함하면 일별 비중 1.0은 0.3보다 7일 평균 NLL 0.0262, 비품절 CRPS 0.9534를 낮췄다. 그러나 seed 44에서는 부족 비용 비율 3·9의 7일 발주 손실이 증가했고, 1일 평균 NLL은 0.0556 증가했다. 현재 사용 중인 단일 GRU와 비교한 세 seed의 평균 7일 CRPS는 0.0549, 부족 비용 비율 1·3의 발주 손실은 0.2854·0.3801 높았다. 유리한 seed만 골라 교체하지 않는다. 관측 기간 수에 seed 수를 곱하지 않고 출처 그룹별 불확실성을 기록했다. [모든 반복 실험의 비교](../results/research-checks/demand-weight-seeds/comparison.json)

작은 표본에 의존한 추가 조정보다 실제 Train 관측의 확대를 먼저 준비했다. 고정 revision의 FreshRetail 원본 Train parquet에서 기존 모든 매장·상품과 겹치지 않는 이력 512개를 관측값을 보기 전에 선택했다. 추가 이력끼리도 매장·상품을 공유하지 않는다. 수요 Train은 기존 30개 이력·25개 출처 그룹에서 542개 이력·537개 출처 그룹으로 늘며, 기존 Dev·Test는 그대로다. 첫 60일을 입력, 다음 7일을 결과로 나누고 품절 판매를 참수요로 표시하지 않는다. 새 버전은 `data/processed/core-retail-train-v1`이며 아직 개선된 모델의 증거가 아니다. 원본 출처는 [FreshRetailNet-50K](https://huggingface.co/datasets/Dingdong-Inc/FreshRetailNet-50K/tree/08c1fab7f9257bc73679d415d65d644165d351d4), 파일 hash·선택 과정은 [자료 기록](../results/research-checks/retail-expansion.json)에 보존한다.

문서 경로에는 원본 TAT-QA Train의 12,951개 주석을 별도 버전 `data/processed/core-tatqa-train-v1`으로 준비했다. 기존 Dev·Test에 연결되는 원문·정규화 문맥·유사 문맥을 제외하고 기존 행과 분할을 유지했다. 확장 Train의 산술 5,492건 중 현재 계산기가 표현하는 4,526건은 원천 답과 반올림 기준이 일치하고, 나머지는 해당 연산 손실을 적용하지 않는다. 숫자·단위·근거 학습 자료의 보강이며 범용 업무 절차나 도구 기능의 추가가 아니다. 원문 문맥 분리는 원래 기업이나 보고서 전체의 분리를 보장하지 않는다. 독립 검증은 [두 확장 자료의 검사](../results/research-checks/expansion-audit.json)에 기록했다.
