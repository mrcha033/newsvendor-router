# 문서 학습에서 기존 추출 능력 보존

정상 형식의 원가·가격 문서를 추가 학습한 후보는 모수 적용 범위의 오류를 줄였지만 공개 문서 추출과 필요한 매니저 질문이 악화됐다. [이전 비교](parameter-contrasts.md)와 [행동 head 재학습](action-adaptation.md)은 보존한다. 이번 실험은 같은 학습 자료와 예산에서 공개 문서 능력의 퇴행을 줄이는 방법을 검증한다.

## 학습 경로

기존 `language_backward`에는 정책 단계의 공개 자료 replay를 위한 증류 함수가 있었다. 일반 언어 학습에서는 이 함수가 연결되지 않았다. 이제 `training.distillWeight`를 지정하면 `warmStart`의 가중치를 고정한 교사 모델을 사용한다. 공개 **Train** 관측 입력에서 기존 출력 분포를 계산하고, 새 주석에 대한 손실과 함께 학습한다. 원문 포인터·관계·단위·상태 등 각 공개 주석 과제에 관련된 기존 head만 사용한다.

연구용 변형 문서는 새 주석으로 학습하며 교사 출력을 복사하지 않는다. 잘못된 SKU나 구버전 문서를 선택하던 부모 모델의 오답을 정답처럼 유지하지 않기 위해서다. 추가 조회가 필요한 공개 문서는 첫 입력과 실제 조회 후 입력의 보존 손실을 각각 절반씩 적용한다. 교사는 숨겨진 응답 결과나 Dev·Test 정답을 받지 않는다.

ModernBERT encoder와 구성 head는 계속 갱신하고 GRU는 고정한다. 교사는 학습 중에만 추가되며 추론 모델의 구조·파라미터 수는 같다. 이후 갱신된 encoder·구성기를 고정하고 실제 자기 예측 상태의 Train rollout으로 행동 가치 head를 다시 학습한다.

교사 checkpoint의 hash를 데이터 identity에 포함한다. 중단 후 재개할 때도 같은 원래 교사를 로드하며, 교사 초기화가 학생의 난수 상태나 CPU thread 수를 바꾸지 않도록 복원한다.

## 비교와 검증

[설정](../configs/l40s-research-retention-v1.json)은 기존 `scope-control`과 같은 순서의 균형화 Train 11,920건을 2회 학습한다. 한 순회는 연구 9,536건과 공개 2,384건이며, 공개 자료의 고유 사례는 774건이다. 보존 손실 가중치 4.0은 새 Dev 결과를 보기 전에 고정했다. 언어 후보 선택은 기존 연구 Dev 기준을 유지하고 모든 epoch 후보를 보존한다. 행동 가치 학습은 두 번의 새 rollout 수집과 기본 평가와 같은 응답 잡음 0을 사용한다.

기존 `scope-control`과 그 후속 행동 학습은 과거 비교군이다. 현재 코드에서 보존 손실을 끈 L40S Train 64건의 두 optimizer 갱신은 이전 코드와 손실·전체 가중치가 정확히 같았다. 켠 조건에서는 encoder가 갱신되고 교사·GRU가 고정됨을 확인했다. 이는 학습 연결 검사이고 성능 향상 결과가 아니다.

입력·환경 주석·순서 있는 학습 사례 목록 등 7개 파일은 과거 비교군과 byte 단위로 같았다. 테스트 286개, 출처·입력 분리 검사 4종, 수치 smoke 30개가 통과했다. 중단·재개 시 동일 결과, 조회 후 보존 손실의 gradient, 연구 입력 제외, Dev 입력 거부를 검사했다.

## 평가 범위

원래 공개 Dev의 과제별 추출 지표, 판매·생성 Dev의 모수·근거·질문·회복·실제 총손실을 함께 비교한다. 별도 학습 변형을 제공하지 않은 Train 출처의 진단도 기록하되, 이 출처는 부모 모델의 원래 Train에서 이미 관측됐으므로 독립적인 일반화 근거로 해석하지 않는다. 기존 Test와 별도 판매 출처 27개는 이번 학습·선택에 사용하지 않는다.

판매 Dev의 정확한 손실은 고유 완전 관측 기간 5개 × 7개 조건에 한정된다. 생성 문서와 매니저 응답으로 측정한 결과를 실제 조직 업무의 효과로 표현하지 않는다.

## 완료된 L40S 결과

두 번의 언어 학습에서 원래 모수 Dev의 원시 상태 오류는 부모 12개, 첫 후보 16개, 두 번째 후보 5개였다. 첫 후보는 퇴행으로 제외했고 두 번째 후보가 선택됐다. 분모는 학습 선택에 쓰는 관측·응답 상태 792건의 모수 필드 3,168개다. 순차 실행의 종료 후 모수·근거 정확도와는 다른 지표다.

| 원래 Dev | 기존 선택 모델 | 보존 손실 추가 후보 |
| --- | ---: | ---: |
| 모수 선택용 원시 상태 오류 / 3,168 | 12 | **5** |
| 판매 필요한 질문·응답 후 회복 / 336 | 336 | 336 |
| 판매 모수 부족 상태로 종료 | 0 | 0 |
| 판매 평균 총손실, 완전 관측 기간 | 24.3925 | 24.3925 |
| 생성 60사례 평균 총손실 | 147.6813 | **146.7471** |
| TAT-QA 엄격 정답 / 48 | **16** | 11 |
| ContractNLI 상태 정답 / 72 | 44 | 45 |

판매·생성 순차 실행의 최종 모수·근거 정확도는 100%였고 잘못된 발주 진행은 없었다. 그러나 공개 TAT-QA 정확도가 하락했으므로 전체 선택 모델은 교체하지 않는다. 생성 손실의 작은 감소나 구성 오류 감소만으로 다른 능력의 퇴행을 상쇄하지 않는다.

생성 총손실 차이는 서로 다른 출처의 두 사례에서 생겼다. 하나는 `b` 질문을 생략하고 발주해 종료 손실이 늘었고, 다른 하나는 응답을 받아도 해결되지 않던 `v` 질문을 생략하고 보류했다. 전체 60건 평균으로 요청 비용은 1.7140 감소했지만 종료 손실은 0.7798 증가했다. **총손실의 0.9342 감소는 발주 손실 개선을 의미하지 않는다.** 이 기존 생성 과제는 모수가 불확정이어도 허용된 범위에서 강건 발주를 진행할 수 있으므로, 이를 판매 Dev의 누락 모수 요청 기준과 혼동하지 않는다.

새 자기 상태 수집은 두 번 모두 919개 표적을 만들었다. 각 수집의 10·20 epochs에서 평가한 가치 head 후보는 생성 Dev 손실 148.3549로 언어 학습 직후 146.7471보다 나빠 모두 탈락했다. 최종 모델은 선택된 언어 후보의 기존 가치 head를 유지했다. 이를 새 가치 학습의 효과로 보고하지 않는다.

전체 학습·주 평가 시간은 1,380.05초(약 23분), 최대 GPU 할당은 26.58 GiB였다. 모든 언어 epoch의 가중치, 마지막 언어 optimizer, 가치 head 후보와 optimizer, 실제 rollout을 보존한다. 공개 문서와 변형 문서의 추가 대조 시간은 별도다.

전체 후보 가중치·optimizer는 hash를 검증한 로컬 압축 파일에 보존한다. 공개 artifact에는 원시 예측·rollout·설정·소스·파일 hash와 소형 가치 head 후보를 포함한다. 공개된 기존 `forecast-v1` 추론 가중치는 그대로 유지하며, 이번 미채택 후보의 완전한 학습 재현 패키지를 공개했다는 뜻은 아니다.

추가 대조는 180.04초가 걸렸다. 변형 학습을 제공하지 않은 기존 Train 출처 19개의 1,259개 상태·5,036개 필드에서 구성 금액 오류는 부모 1,902개, 첫 후보 56개, 두 번째 후보 55개였다. 원시 금액 오류도 1,997개에서 53개로 줄었다. 이는 원시 추출 자체가 달라진 결과지만, 해당 출처는 부모의 원래 Train에서 관측됐으므로 독립적인 Test 성능으로 보고하지 않는다. 선택 모델과 최종 모델의 가중치는 같았고, 공개 Dev 258건의 출력도 기존 실행 기록과 정확히 일치했다. ## 자료 범위 점검

이번에는 보존 손실의 추가 전후를 비교하기 위해 이전 실행과 같은 공개 Train 범위를 사용했다. TAT-QA는 고유 입력 144개·출처 36개다. 이미 준비된 확장 Train에는 주석 행 13,095개, 고유 입력 13,090개·출처 2,177개가 있다. 이번 실험은 그 전체 범위를 학습하지 않았다. 같은 작은 자료에 보존 손실을 추가한 결과만으로 확대된 자료의 효과까지 판단할 수 없다. 이 관측은 다음 Train 설계를 위한 정보이며, 이번 퇴행의 원인이 확정됐다는 뜻은 아니다.
