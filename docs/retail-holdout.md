# 새 판매 출처에서 고정 모델 검증

Dev에서 GRU만 교체했을 때 평균 총손실이 44.3274에서 24.3925로 줄었지만, 정확한 비교는 고유 판매 기간 5개에 한정됐다. 이 개선의 일반화를 확인하기 위해 이전 작업에서 사용하지 않은 출처에 모델을 고정해 적용한다. 기존 생성 Test와 retail Test는 다시 실행하거나 수정하지 않는다.

## 결과를 보기 전에 고정한 절차

[평가 계획](../configs/research-retail-holdout-v1.json)에 이전 GRU 모델, 선택한 새 GRU 모델, 같은 구성기의 `no_value` checkpoint hash와 코드 hash를 고정했다. 새 자료로 학습하거나 후보를 선택하지 않는다. 비교 중 문서 encoder·모수 구성기의 가중치는 같아야 하며, GRU 교체 비교의 행동 head와 정책 비교의 GRU도 각각 같아야 한다.

FreshRetailNet-50K의 고정 revision `08c1fab7f9257bc73679d415d65d644165d351d4` 원본 Train parquet에서 **매장·상품 식별자만** 먼저 읽었다. 기존 모든 Train·Dev·Test의 매장과 상품을 제외하면 허용되는 조합은 28개였다. 출처끼리도 매장·상품을 공유하지 않도록 고정 hash 순서로 선택하면 27개가 남는다. 판매량·품절 여부로 표본을 고르거나 실패한 출처를 다른 출처로 대체하지 않는다.

이 27개는 프로젝트의 별도 Test로 표시하되, 원천 제공자의 공식 분할이 Train이라는 사실도 보존한다. 기존 확장 자료의 모든 입력·주석·분할은 새 자료 파일의 앞부분에 그대로 복사하고 원본 파일은 변경하지 않는다. 새 모델의 학습 자료와 원본 자료를 검사한 뒤 새 출처의 모든 모델 결과를 보고한다.

이후 Train을 확장할 때도 이 27개 출처와 연결되는 매장·상품을 제외한다. 새 분할을 포함한 `core-retail-holdout-v1` manifest와 공개 압축 파일의 `selection.json`에 예약된 출처를 보존한다.

## 평가 단위

각 이력은 과거 60일과 후속 7일 주석으로 분리한다. 실제 순차 질문·발주 평가는 28·35·42·49·56일을 예측 시점으로 사용한다. 각 출처의 다음 7일 구간은 서로 겹치지 않는다. 전체는 **출처 27개 × 판매 기간 5개 × 통제 문서 조건 7개 = 945사례**이며, 조건을 늘린 것이 독립 판매 자료를 늘린 것은 아니다.

고정된 출처를 추출한 뒤 확인한 결과, 135개 판매 기간 중 완전 관측 기간은 **30개·출처 16개**다. 정확한 총손실은 이 기간의 210개 통제 조건에서만 계산한다. 나머지 품절 기간에는 발주 손실의 하한을 기록하며 이를 실제 손실로 대체하지 않는다. 두 모델의 차이와 불확실성은 같은 기간끼리 짝지은 뒤 출처 단위로 재표집한다.

부차적인 수요 지표는 각 이력의 33개 rolling 예측 시점에서 1일·7일을 모두 측정한다. 같은 관측 NLL끼리 비교하고, 완전 관측 CRPS·발주 손실·구간 적중률과 전체 적중률의 식별 범위를 구분한다. 일별 배분 농도 4와 수치 적분 설정도 이전 Train 적합의 값을 고정한다.

입력 파일을 저장한 뒤에만 결과 주석을 채점 경로에 전달한다. 회귀 검사는 미래 판매량과 품절 표식을 바꿔도 입력이 같고, 기존 매장·상품이 선택되지 않으며, 품절 손실이 정확한 손실 평균에 포함되지 않는지 확인한다.

## 해석 범위

이 표본은 기존 자료와 겹치지 않고 남은 매장·상품의 조합이며 전체 소매 사업의 무작위 표본은 아니다. 공통 달력·지역·상품 범주의 상관도 존재할 수 있다. 관측되지 않은 잠재 수요는 주석으로 만들지 않는다. 가격·계약 문서와 매니저 응답은 여전히 생성한 통제 조건이므로 실제 조직의 성과로 표현하지 않는다.

기존 생성 Test의 총손실 기준 240.35는 별도의 손실 정의에 대한 기준이며 이 retail 평가에 적용하지 않는다. 새 측정을 이전 Dev의 24.3925와 직접 빼서 개선량으로 보고하지 않고, 같은 새 출처에서 실행한 이전 모델과 비교한다.

## 완료한 결과

L40S에서 학습 없이 426.85초 동안 평가했다. 같은 새 출처에서 측정한 값은 다음과 같다.

| 통제 조건의 순차 실행 | 이전 GRU 가치 정책 | 새 GRU 가치 정책 | 새 GRU 고정 질문 | 새 GRU no_value |
| --- | ---: | ---: | ---: | ---: |
| 완전 관측 평균 총손실 | 83.1514 | 69.0309 | 69.0309 | 69.0309 |
| 최종 모수·상태·근거 정확도 | 100% | 100% | 100% | 100% |
| 필요한 요청 / 응답 후 회복 | 945 / 945 | 945 / 945 | 945 / 945 | 945 / 945 |
| 불필요한 요청 / 잘못된 진행 | 0 / 0 | 0 / 0 | 0 / 0 | 0 / 0 |
| 품절 기간 발주 손실 하한 평균 | 4.2141 | 5.6655 | 5.6655 | 5.6655 |

완전 관측 총손실의 평균 차이는 **−14.1205(16.98% 감소)**지만 출처 단위 재표집 95% 구간은 **[−31.5978, +3.5407]**이다. 0을 포함하므로 이 측정만으로 손실 개선이 확실하다고 단정하지 않는다. 품절 기간의 손실 하한은 오히려 높아졌으며 차이의 구간은 [−2.3620, +7.0762]였다. 하한 증가를 실제 총손실 증가량으로 해석하지도 않는다. 가치 정책과 두 비교군의 총손실 차이는 0이었다.

| 부차적인 rolling 예측 지표 | 이전 GRU | 새 GRU |
| --- | ---: | ---: |
| 1일 관측 NLL | 1.0465 | 0.6758 |
| 완전 관측 1일 CRPS | 0.2964 | 0.2966 |
| 완전 관측 1일 80% 적중률 | 67.16% | 89.87% |
| 주간 합계 관측 NLL | 1.4027 | 1.0724 |
| 날짜별 관측을 함께 쓰는 주간 NLL | 7.0968 | 5.3438 |
| 완전 관측 7일 CRPS | 3.3147 | 2.0624 |
| 완전 관측 7일 80% 적중률 | 37.62% | 60.40% |

각 예측 기간의 전체 표본은 891개·출처 27개이고, 완전 관측 표본은 1일 612개·7일 202개다. 겹치는 rolling 구간을 독립 표본으로 세지 않는다. 새 GRU의 전체 80% 적중률은 관측으로 **1일 61.73~92.37%, 7일 13.69~89.90%**까지만 식별된다. 주간 CRPS·관측 NLL 개선에도 전체 잠재 수요 calibration은 입증되지 않았다.

새 자료의 결과로 모델이나 설정을 교체하지 않았다. 테스트 251개, 자료 버전 네 개의 출처·입력 중복 0건, 수치 smoke 30개를 통과했다. [전체 결과와 검증](evidence/research-retail-holdout-results.json), [27개 입력·분리된 주석·모든 순차 경로와 예측·실행 소스](evidence/artifacts/research-retail-holdout.tar.xz)를 공개한다. 새 자료의 CC BY 4.0 출처·가공 설명·원본 hash도 포함한다.

## 공개 artifact만으로 수요 예측 재계산

다음 명령은 저장소에 공개한 작은 GRU와 위의 27개 입력·주석을 압축 파일에서 직접 읽는다. 로컬 `data/`, `models/`, `results/`의 checkpoint 접근은 검사에서 거부하며 ModernBERT를 불러오지 않는다. 원래 측정과 같은 L40S 환경에서 1,782개 예측의 선택 종류·`F`·발주량이 **정확히 일치**했다.

```sh
export CUDA_VISIBLE_DEVICES="$NEWSVENDOR_GPU_UUID"
export CUBLAS_WORKSPACE_CONFIG=:4096:8
uv run --no-project scripts/reproduce_retail_forecast.py \
  --device cuda --output results/reproduce-retail-forecast
```

고정 CUDA PyTorch 환경과 등록된 L40S를 사용한다. CPU도 실행할 수 있지만 원래 L40S 수치와의 엄격한 일치 검사는 실패했다. 종류 선택은 모두 같았으나 `F`의 최대 절대 차이는 0.0246682, 발주량은 0.0080205였다. 허용 오차를 넓혀 통과시키지 않았으며 두 장비의 원시 예측과 실패 기록을 함께 보존한다. 이 검증은 작은 수요 경로의 재현이다. 이후 전체 ModernBERT 모델도 [별도 추론 묶음](model-bundle.md)으로 공개했지만, 위 1,782개 일치 결과를 전체 순차 질문·발주 재현 결과로 바꾸어 해석하지 않는다. [재현 검사와 원시 기록](evidence/research-retail-forecast-reproduction.json)

검증에는 이미 설치된 고정 Python 환경을 재사용했다. 빈 장비에서의 CUDA 패키지 설치까지 반복한 검증은 아니다.
