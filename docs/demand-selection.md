# 수요 모수의 출처별 학습 횟수 선택

날짜별 배분 농도를 Train에서 추정한 모형은 완전 관측 주간 지표를 개선했지만 일별 오차와 전체 관측 likelihood는 악화됐다. 이를 이유로 손실 가중치를 바로 바꾸지 않고, Train 입력과 학습 과정을 먼저 점검했다. 이번 변경은 작은 GRU의 학습 횟수 선택이며 신경망 구조·추론·문서 구성기를 바꾸지 않는다.

## Train에서 확인한 근거

원본 30개와 추가 512개 판매 이력의 날짜 범위, 관측 필드·자료형, 시간별 배열 길이는 같았다. 판매·품절·할인 등의 분포에는 차이가 있지만 입력 형식이 서로 다르다는 결함은 발견하지 못했다.

동일한 Train 예측 시점 1,024개에서 1일·7일 손실의 기울기를 비교했다. 학습 후 주간 기울기가 더 컸지만 두 기울기는 대체로 같은 방향이었다. 농도 4 모형의 8개 미니배치 모두에서 합친 기울기가 일별 손실을 1차 근사상 악화시키는 방향은 아니었다. 이는 측정한 배치의 국소적 진단이며 전체 학습의 간섭이 없다는 증명은 아니다. 이 결과만으로 일별 가중치를 변경하지 않았다.

그 다음 Train 출처 537개 중 430개로 농도 4 모형을 학습하고, 107개를 제외해 epoch마다 원시 관측 손실을 기록했다. 제외한 출처의 평균 NLL은 7회 학습에서 **−0.7483**으로 가장 낮고, 20회에서는 **1.6330**이었다. 학습 출처의 손실은 계속 낮아졌지만 제외한 출처의 1일·7일 손실은 모두 악화됐다. Dev와 Test는 이 진단에 사용하지 않았다.

## 구현

`demand.parameterValidationFraction=0.2`를 선택하면 각 바깥 출처 분할의 학습 자료 안에서만 20% 출처를 제외해 학습 횟수를 선택한다. 내부 농도 추정도 내부 학습 출처만 사용한다. 선택 기준은 두 예측 기간과 세 분포의 가중 평균 관측 NLL로, 모수 학습에 사용한 목적함수와 같다.

선택 뒤 동일 초기값에서 해당 바깥 분할의 전체 학습 출처로 다시 적합한다. 이때 농도도 허용된 학습 출처에서 다시 추정한다. 바깥쪽 제외 출처는 자기 모형의 농도·학습 횟수 선택에 들어가지 않는다. 최종 모수 모형도 같은 절차를 전체 Train 안에서 수행하며, Dev는 기존과 같이 종류 선택 head의 epoch 선택에만 사용한다.

각 내부 검증의 출처·예측 시점·epoch별 모든 분포 손실과 실제 재학습 횟수를 기록한다. 기본값은 검증 비율 0으로 기존 고정 횟수 학습을 유지한다. 이전 코드와 비교한 작은 L40S 학습 검사에서 이 기본 경로의 epoch 손실과 모든 가중치가 정확히 일치했다. 출처 분리와 기록 보존을 포함한 전체 테스트는 247개를 통과했다.

## 사전 비교 규칙

[실행 설정](../configs/l40s-demand-selection-v2.json)을 고정하고 seed 42·43·44를 모두 실행한다. 기존 농도 4·고정 20회 모형을 같은 seed의 비교군으로 다시 평가한다. 최대 모수 학습 횟수는 20회이며, 내부 선택과 재학습에 필요한 추가 계산과 실제 시간을 보고한다. 총 계산량이 같은 비교라고 표시하지 않는다.

주 모델 교체 기준은 현재 사용하는 GRU다. seed 42의 완전 관측 7일 CRPS와 비용 비율 1·3·9의 발주 손실이 모두 낮아야 한다. 1일 CRPS 악화는 10% 이내이고 완전 관측 주간 적중률은 감소하지 않아야 한다. 이번에는 **1일 관측 NLL과 품절을 포함한 주간 날짜별 NLL도 악화되지 않아야 한다.** 세 seed 중 둘 이상이 각각 주간 CRPS·평균 발주 손실·날짜별 NLL을 개선해야 한다.

이전의 고정 20회 후보는 완전 관측 주간 지표만 개선하고 전체 관측 지표를 악화시켜 채택하지 않은 모형이다. 그 후보와의 모든 차이를 보고하되 각 지표에서 그 후보까지 압도해야 한다는 조건을 교체 기준으로 두지는 않는다. 이 비교 대상과 관측 NLL 조건은 새 후보의 Dev 측정 전에 명시했다. 기본 비교 스크립트의 이전 실험 조건은 그대로 재실행할 수 있다.

위 조건을 모두 통과한 경우에만 같은 문서 encoder·모수 구성기·행동 head에서 GRU를 바꿔 실제 매니저 질문·발주 rollout을 비교한다. 총손실이 낮아지고 잘못된 진행·불필요한 질문·종료 시 누락이 늘지 않아야 한다. 모수·상태·근거 정확도, 필요한 요청과 응답 후 회복도 유지해야 교체한다. Test는 이 선택에 사용하지 않는다. 완전 관측 기간과 가정한 검열 likelihood만으로 잠재 수요 전체의 calibration이나 실제 조직의 효과성을 입증하지 않는다.

[Train 진단과 구현 검증](evidence/research-selection-checks.json), [모든 학습 곡선 checkpoint·원시 손실·감사 코드](evidence/artifacts/demand-selection-checks.tar.xz), [학습 당시 고정 소스](evidence/artifacts/demand-selection-v2-source.tar.gz)를 보존했다. 최초 기울기 검사에서 cuDNN GRU의 역전파에 학습 모드가 필요해 실패한 기록도 포함한다. 이를 수정한 진단은 가중치를 갱신하지 않으며, dropout이 없는 같은 모형에서 기울기만 측정했다.

## 완료한 L40S 비교

동일한 확장 Train 이력 542개·출처 537개·1일/7일 표본 35,772개에서 세 seed를 모두 학습했다. 최종 모수 학습은 7·7·6회, 종류 선택 head는 최대 20회 중 20·7·11회를 선택했다. 모수 학습 횟수는 Train 내부 출처 분할로, 종류 head는 기존 절차대로 Dev로 선택했다. 최종 후보 seed는 사전에 정한 42를 유지했다.

| Dev 지표 | 기존 GRU | seed 42 | seed 43 | seed 44 |
| --- | ---: | ---: | ---: | ---: |
| 완전 관측 1일 CRPS | 0.2111 | 0.2083 | 0.2104 | 0.2126 |
| 1일 관측 NLL | 0.6237 | 0.4719 | 0.5020 | 0.5126 |
| 완전 관측 7일 CRPS | 2.7732 | 1.2871 | 1.2297 | 1.1802 |
| 날짜별 관측을 함께 쓰는 주간 NLL | 4.3164 | 3.9276 | 3.8772 | 3.9084 |
| 주간 합계·하한만 쓰는 기존 NLL | 0.5441 | 0.5575 | 0.5763 | 0.6133 |
| 완전 관측 주간 80% 구간 적중률 | 33.33% | 46.67% | 56.67% | 56.67% |

각 예측 기간은 264개 시점·출처 8개다. 완전 관측 1일 지표는 177개, 7일 지표는 **겹치는 30개 기간·출처 6개**에서 계산한다. 세 seed 모두 주간 CRPS·비용 비율 1/3/9의 발주 손실·날짜별 NLL이 개선됐고 사전 채택 조건을 모두 통과했다. 다만 seed 44의 일별 CRPS와 세 seed의 기존 주간 합계 NLL은 악화됐다. 서로 다른 likelihood 값을 직접 빼서 우열을 주장하지 않으며, 각각 같은 점수의 기존 GRU와 비교한다.

세 seed 평균 주간 CRPS 차이는 −1.5408, 출처 단위 재표집 95% 구간은 [−2.7151, −0.5683]이었다. 날짜별 주간 NLL 차이는 −0.4120, 같은 방식의 구간은 [−0.5700, −0.2258]이었다. Dev를 후보 선택에 사용했고 출처가 작으므로 독립적인 확증 검정으로 해석하지 않는다. seed 42의 전체 주간 80% 적중률은 품절 때문에 **5.30~93.56%**만 식별할 수 있어 잠재 수요 calibration은 여전히 미해결이다.

세 학습은 각각 298.95·296.74·307.80초, 자료 특성 준비 이후 전체 학습·평가는 936.05초였다. 내부 선택을 위한 추가 학습이 있으므로 기존 고정 20회 실행과 동일 계산량 비교는 아니다. GRU는 기존 360,716개 파라미터를 유지하고 추론 구조는 바꾸지 않았다. [전체 측정·채택 조건·세 GRU checkpoint·원시 내부 손실](evidence/research-selection-results.json)

## 실제 질문·발주 경로

기존 `replay-v1/base/42`의 ModernBERT·모수 구성기·행동 head 가중치를 고정하고 GRU만 바꿨다. 기존 GRU의 원래 Dev 총손실 44.3274를 동일 코드에서 재현한 뒤 후보를 비교했다. 각 조건에 새 상태 cache를 사용해 이전 `F`가 재사용되지 않도록 했다. 별도의 `no_value`도 같은 문서·모수·GRU 가중치인지 hash로 검증하고 실제 순차 경로를 실행했다.

| 같은 통제 retail Dev | 기존 GRU 가치 정책 | 새 GRU 가치 정책 | 새 GRU 고정 질문 | 새 GRU no_value |
| --- | ---: | ---: | ---: | ---: |
| 완전 관측 평균 총손실 | 44.3274 | 24.3925 | 24.3925 | 24.3925 |
| 최종 모수·근거 정확도 | 100% | 100% | 100% | 100% |
| 필요한 요청 / 응답 후 회복 | 336 / 336 | 336 / 336 | 336 / 336 | 336 / 336 |
| 불필요한 요청 / 잘못된 진행 | 0 / 0 | 0 / 0 | 0 / 0 | 0 / 0 |

전체 336사례는 48개 판매 기간·출처 8개에 일곱 통제 조건을 적용했다. 정확한 총손실은 **완전 관측 고유 기간 5개 × 조건 7개**이며, 같은 조건에서 19.9349(44.97%) 감소했다. 질문 비용은 변하지 않았다. 품절 기간의 발주 손실 하한 평균은 0.3144에서 0이 됐지만 실제 손실이 0이라는 뜻은 아니다. 가치 정책과 두 비교군의 차이는 없었으므로 이번 결과는 수요 모델 교체의 개선이며 행동 가치 head의 추가 효과를 입증하지 않는다.

사전 통합 채택 조건도 모두 통과해 `results/l40s-research-forecast-v1/base/42/model.pt`와 같은 구성기의 `no_value/42/model.pt`를 새 Dev 선택 checkpoint로 보존했다. 원래 모델·후보 가중치는 덮어쓰지 않았다. 네 기존/후보 순차 비교는 119.55초, 별도 no_value는 54.48초였다. 상태 cache를 사용한 평가 시간이므로 운영 환경의 독립적인 요청 지연 벤치마크로 보지 않는다. [가중치 신원·채택 조건·모든 순차 원시 경로](evidence/research-forecast-results.json)

이 Dev 선택 단계에서는 새 모델에 Test를 실행하지 않았다. 이후의 [새 출처 27개 고정 평가](retail-holdout.md)는 별도 기록이다. 기존 생성 Test 243.6274와 retail Test 105.9101은 GRU 교체 전 고정 모델의 기록이며 새 모델의 결과로 표시하지 않는다. 공개 문서 추출·행동 가중치는 그대로이고 새 개선을 주장하지 않는다. 선택한 작은 GRU 가중치와 모든 이번 원시 측정은 공개하지만 전체 ModernBERT 통합 checkpoint와 확장 Train 입력 capture는 아직 미공개다. 작은 표본·통제 문서와 응답·품절 관측의 제약 때문에 실제 조직 효과나 전체 연구 목표 달성을 선언하지 않는다.
