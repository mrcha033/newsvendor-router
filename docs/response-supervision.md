# 질문의 기대 손실을 학습하는 응답 표본

행동 head는 “지금 매니저에게 질문하면 최종 손실과 질문 비용이 얼마나 남는가”를 학습한다. 기존 설정은 같은 사례·질문에 항상 같은 응답을 반환했고, 새 정책 후보를 채택하지 않으면 다음 학습 반복에서도 같은 표적을 다시 만들었다. 실제 두 반복의 Train 표적 928개는 파일 hash까지 같았다. 또한 Train에는 추가 응답 잡음 0.1을 넣지만 기본 Dev에는 넣지 않았다.

이 사실만으로 성능 정체의 원인을 단정하지 않는다. 먼저 고정 모델의 Train 실행을 비교하고, 추가 잡음 제거와 응답 표본 확대를 별도 조건으로 학습한다. 모델은 같은 ModernBERT·수요 GRU·모수 구성기와 작은 행동 head를 사용한다.

## 학습 전 확인한 차이

같은 부모 모델·초기 행동으로 Train 514사례를 재실행했다. 원래 생성 환경의 응답 누락·부분 응답은 유지하면서 **추가 잡음만 0.1에서 0으로** 바꿨다. 이는 재학습 결과가 아니다.

| Train 관측 | 추가 잡음 0.1 | 추가 잡음 0 |
| --- | ---: | ---: |
| 생성 360사례 평균 총손실 | 159.4666 | 150.5491 |
| 생성 잘못된 발주 진행 | 7 | 0 |
| 생성 보류 | 66 | 66 |
| Retail 154사례 평균 총손실 | 108.8220 | 53.9797 |
| Retail 보류 | 16 | 0 |

두 자료에서 잡음의 뜻도 다르다. 원래 생성 자료에서는 잘못된 값을 반환하고, Retail에서는 답변이 누락된다. 생성 사례의 7건과 Retail 보류 16건은 이 추가 잡음의 영향을 받았다. 질문 비용은 같았다. 따라서 이 손실 차이를 모델 향상이나 실제 매니저의 신뢰도 추정으로 보고하지 않는다.

고정 응답 한 번으로 측정한 “다른 질문을 먼저 했다면 줄었을 손실”도 기대 가치의 정답은 아니다. 실제로 실패한 응답을 미리 아는 사후 비교이므로, 개선 가능성을 살피는 진단에만 사용한다.

## 구현

`policy.responseSeed`와 `policy.responseSamples`를 추가했다. 기본값은 기존 응답과 단일 rollout을 그대로 사용한다. 표본 확대 조건에서는 각 자기 예측 상태에서 허용 행동별로 실제 후속 rollout을 8회 실행하고, 최종 손실과 요청 비용을 각각 평균해 두 가치 출력의 표적으로 삼는다.

- 상태를 수집하는 응답 표본과 후속 가치 표본을 구분하고, 학습 반복마다 seed를 바꾼다.
- 같은 표본의 응답은 질문 항목으로 고정한다. 질문 순서를 바꿨다는 이유로 해당 항목의 응답 난수가 달라지지 않는다.
- 이미 관측한 답변과 자기 구성 상태를 고정한 채 후속 행동을 실행한다. 각 후속 rollout에서도 실제 모델이 다음 질문을 선택한다.
- seed와 응답 확률·정답 모수는 모델 입력에 넣지 않는다. 숨긴 정보는 응답 환경과 최종 채점에서만 사용한다.
- 모든 응답 seed, 실제 후속 경로와 손실을 기록한다. 재표집은 Train에서만 허용하며 기본 Dev·Test 응답 규칙은 유지한다.

이는 정확한 응답 모형을 아는 planner의 행동을 복사하는 학습이 아니다. 다만 응답 환경 자체가 생성된 통제 조건이라는 제한은 남는다. 8회 평균도 유한한 Monte Carlo 추정이며 참 기대 손실이 아니다.

## 고정 비교

같은 replay-v1 부모와 숫자 상태·FP32 행동 head에서 다음 두 조건을 비교한다. seed 42, Train/Dev 분리, 두 정책 반복, 반복당 최대 40 epochs, optimizer와 Dev 선택 기준은 같다. 언어 encoder·모수 구성기·GRU는 이번 정책 단계에서 고정한다.

- `aligned`: 추가 잡음 0, 기존 고정 응답 1회.
- `sampled`: 추가 잡음 0, 행동별 후속 응답 8회 평균과 별도 상태 수집 응답. 반복마다 새로운 응답 표본을 사용한다.

표본 확대 조건은 환경 실행량이 더 많다. 같은 gradient update 예산이며 같은 전체 계산량이라는 비교는 아니다. 평균화와 방문 상태의 재표집을 함께 바꾸므로 두 효과를 따로 식별하지도 않는다. 기존 추가 잡음 0.1의 FP32 수치 입력 결과는 역사적 비교로 보존한다.

[고정 응답 설정](../configs/l40s-research-responses-v1-aligned.json) · [표본 확대 설정](../configs/l40s-research-responses-v1-sampled.json)

전체 226개 테스트와 Ruff, 세 자료 버전의 출처·입력 겹침 0건, 수치 smoke 30건을 확인했다. 검사는 평균 표적과 실제 측정의 일치, 반복 가능한 표본, 기본 응답 보존, Train 전용 경계와 입력 불변성을 포함한다. 새 옵션을 끈 실제 L40S 수집에서는 수정 전후 Train 표적 928개가 파일 hash까지 같았다. [검증·Train 진단](evidence/research-response-supervision-checks.json), [원시 자료와 검사 코드](evidence/artifacts/response-supervision-checks.tar.xz), [고정 소스](evidence/artifacts/response-supervision-source.tar.gz)를 보존한다.

첫 표본 확대 반복은 자기 예측 상태 929개에서 후속 경로 17,280개를 측정했다. 343개 상태·행동 조합의 손실이 응답 표본에 따라 달랐으며, 평균 표적과 원시 측정의 최대 차이는 2.23e-16 미만이었다. 초기 Train 상태 514개에서는 저장한 L40S 표현과 CPU의 작은 head로 적합도를 진단했다. 생성 360사례에서 선택 행동의 평균 표적 손실과 최소 표적 손실의 차이는 부모 12.89에서 후보 5.77로 줄었다. **후속 행동을 부모 정책으로 고정한 Train 적합 진단**이며, 새 정책 전체의 실행 성능이나 Dev 개선으로 해석하지 않는다.

## 결과: 기존 모델 유지

| 설정 | 생성 Dev 평균 총손실 | Retail 평균 총손실 | 학습·평가 시간 |
| --- | ---: | ---: | ---: |
| 기존 추가 잡음 0.1, 고정 응답 | 147.6813 | 44.3274 | 355.02초 |
| 추가 잡음 0, 고정 응답 | 147.6813 | 44.3274 | 323.18초 |
| 추가 잡음 0, 8회 응답 평균 | 147.6813 | 44.3274 | 815.39초 |

첫 행은 이전 고정 비교이며 이번에 다시 학습한 결과가 아니다. 두 새 조건 모두 두 반복의 후보가 초기 부모보다 나은 Dev 점수를 얻지 못해 초기 가중치를 유지했다. 표는 이렇게 선택한 최종 모델의 점수다. 후보별 Dev 경로와 선택 이력도 보존했다. 새 옵션을 기본으로 채택하거나 추가 성능 향상으로 보고하지 않는다. [전체 결과·가중치 검사·후보 이력](evidence/research-response-supervision-results.json), [원시 Train/Dev 경로와 작은 head 가중치](evidence/artifacts/response-supervision-results.tar.xz)

생성 Dev는 60사례·12개 family, Retail Dev는 336개 통제 조건이다. Retail의 정확한 손실은 비품절인 고유 기간 5개 × 7조건, 총 35사례에서 계산한다. 두 최종 정책의 모수·근거 정확도는 유지됐고, 잘못된 발주 진행과 불필요한 Retail 질문은 0건이다. 관측 표본을 늘린다고 독립 문서나 판매 기간이 늘어나는 것은 아니다. 한 학습 seed와 반복해서 확인한 작은 Dev 결과이므로 실제 조직 효과나 일반적인 우열을 주장하지 않는다.

이번 비교에서 응답 표집과 평균 표적의 구현은 확인했지만 **성능 정체가 잡음 차이나 단일 응답 표본 때문이었다는 근거는 얻지 못했다.** Train 적합 개선을 Dev 일반화 개선으로 바꾸어 해석하지 않는다. 수요분포 calibration과 공개 문서 일반화, 전체 checkpoint의 공개 재평가는 남아 있다. 기존 고정 Test 결과 243.6274와 목표 미달 기록을 유지하며 이번에 Test를 다시 실행하지 않았다.
